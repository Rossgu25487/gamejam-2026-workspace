# 测试目录

本目录由 `qa` 维护测试计划、问题与必要证据。`game/tests/` 的既有检查脚本也归 qa，生产代码、场景和美术资源保持只读。
从仓库根进入，先读 [测试岗位工作流](../岗位工作流/06_测试_独立验收与问题回归.md)与 [接口合同](../docs/接口与交接.md)。

## 接收与执行

1. 从主程序取得准确版本、目标平台、运行包位置、启动方法、配置及已知限制。
2. 没有包时先检查本机环境、确认接收格式、整理验证计划。计划与状态写入 [qa 岗位记录](../workspace/handoffs/qa.md)，未做项目标“未执行”。
3. 有包后独立启动，依据当前需求版本核对操作与资源显示；本轮夹具为 0/+1/reset，配置变化须对应依据。
4. 规则未知时记录现象、列出待确认预期，不猜测。仅构建或无界面检查成功不能代表视觉和交互通过。
5. 缺少图形操作能力时交付最少人工步骤和所需证据，相关项保留未执行；实际人工代验注明执行者、版本和证据。
6. 发现失败时记录版本、步骤、预期与依据、实际结果、必要证据及对应岗位；实际没有问题可以通过。
7. 回归先确认新旧版本，复测原问题与直接受影响点；只有具体疑点才扩大范围。

## 文件约定

- 唯一状态与交接记录：[workspace/handoffs/qa.md](../workspace/handoffs/qa.md)。在这一份中持续更新验证和问题，避免逐轮报告。
- 必要截图、短视频或日志：`qa/evidence/`，用问题 ID 和版本辨认。
- 确需的辅助脚本：`qa/tools/`，只处理测试副本或独立数据；工程内已有检查直接维护 `game/tests/`，不另写重复检查。
- 必要证据按实际交接方式提供；只存在本机且未共享的文件须明确注明，避免接收者误以为能从仓库读取。
- 运行包由主程序在交接中给出，测试不把未经确认的任意构建当成本轮包。

状态采用通过、失败、未执行。关键项目未执行时，不能宣告整体验收通过。
游戏提审与活动投稿由队长完成，测试只交付对应版本的验收结论。

### 配色核对

协作界面使用暖灰背景 `#F1F0EB`、纸白表面 `#FAFAF7`、石墨正文 `#273330` 和蓝绿主按钮 `#2F6962`，主题只作用于插件自身。

| 文字组合 | 对比度 |
|---|---:|
| 正文 / 纸白表面 | 12.53:1 |
| 辅助文字 `#52605A` / 纸白表面 | 6.32:1 |
| 白字 / 蓝绿主按钮 | 6.33:1 |
| 选中岗位正文 / 浅绿底 | 10.66:1 |

按相对亮度计算核对，并实际查看渲染；上述常规文字组合超过 [W3C 对普通文字的 4.5:1 参考要求](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。这项结果限于列出的配色，不宣称已完成全部无障碍认证。
