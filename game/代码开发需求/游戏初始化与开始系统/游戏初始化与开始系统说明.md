# 游戏初始化与开始系统说明

配套文件：[游戏初始化与开始系统策划案.docx](游戏初始化与开始系统策划案.docx)、[游戏初始化与开始系统配置表.xlsx](游戏初始化与开始系统配置表.xlsx)。

本册仅含策划案、配置表和本说明。原型图已嵌入策划案，图源、独立图片、索引、制作脚本和音频文件均不随包提供。

人工填写后的 Excel 是本册配置依据。表中保留中文说明、程序字段和类型，程序可以采用这份结构，也可以映射到自己维护的同一内容源。

## 1. 数据页与可改值

| 数据页／字段 | 已采用制作初值 | 修改范围与用途 |
| --- | --- | --- |
| 导航总控 `id` | default | 正式总控保持唯一一行。 |
| `ui_feedback_ms` | 2000 | 毫秒，500—10000；只用于普通反馈，错误显示按策划案保留。 |
| `menu_open_ms` | 200 | 毫秒，0—2000；0表示直接显示打开完成态。 |
| `menu_close_ms` | 150 | 毫秒，0—2000；0表示直接完成关闭，下层输入仍按层级规则恢复。 |
| 导航按钮 `page` | 每个控件已有对应值 | title标题、pause暂停、subpage子页、load_confirm读取确认。 |
| 导航按钮 `action` | 每个控件已有对应值 | new_game新游戏、continue继续、load读取、settings设置、exit退出、resume恢复暂停前内容、save手动保存、return_title返回标题、back本层返回、save_then_load先存后读。 |
| `label_key` | 已填稳定使用键 | 引用界面文本绑定中的使用键；图片名和按钮排序不作为身份。 |

## 2. 导航按钮与三种继续

“导航按钮”每行登记一个绑定，`id` 保持表内唯一，`page` 表示所在页面，`action` 表示接受操作后执行的动作，`label_key` 定位“界面文本绑定”的使用键。字段名供程序接入或映射使用；图片名、按钮顺序和屏幕坐标只说明排布。

现有15条正式导航记录对应13个控件。暂停菜单的继续位置按来源选择下列一行，三行都执行 `resume`，界面一次只显示一个继续按钮，六项暂停操作的数量和顺序保持。

| 原暂停来源 | 导航记录 `id` | `page` | `action` | `label_key` |
| --- | --- | --- | --- | --- |
| 调查会话，含对白、阅读、选材与待收 | NAV_PAUSE_RESUME | pause | resume | UI_PAUSE_RESUME |
| 猫互动 | NAV_PAUSE_RESUME_CAT | pause | resume | UI_PAUSE_RESUME_CAT |
| 结局片段 | NAV_PAUSE_RESUME_ENDING | pause | resume | UI_PAUSE_RESUME_ENDING |

对应文字分别为【继续调查】【继续摸猫】【继续播放】。来源由本次菜单调用提供，不能根据按钮的位置猜测，也不同时打开三份菜单。继续只回原内容，不代替节点继续、推论收下或案件推进。

本表保留 `NAV_TITLE_CONTINUE`、`NAV_PAUSE_SAVE`、`NAV_LOAD_SAVE_FIRST` 三条实际绑定，分别对应标题继续、暂停中的保存、读取前先保存当前。调查菜单的固定动作键为 `MENU_OPEN`。这些编号和动作在换图、移位与重排时保持；新增功能或改变返回目标时，同步修改对应业务规则。

保存资格、层级输入和保存并离开选栏规则在策划案维护，不通过修改文字或动作枚举绕过。关闭后的页面、选中项、滚动及焦点仍按本册正文恢复。

## 3. 功能文字与引用

**共用固定功能文字只在本表“功能文字”页维护。** `id` 是稳定文字键，`text` 是实际中文文字；修改中文时保留原键。各册的 `text_id` 或 `textId` 引用这里的 `id`，不另存一份中文正文。初始化的“界面文本绑定”登记本册使用位置，导航的 `label_key` 引用相应使用键。

导航的文字引用按下面这条关系填写：

`导航按钮.label_key` → `界面文本绑定.id` → 该行的 `text_id` → `功能文字.id` → 该行的实际中文 `text`。

例如，`NAV_PAUSE_RESUME_CAT` 的 `label_key` 为 `UI_PAUSE_RESUME_CAT`；“界面文本绑定”的同名行使用 `text_id=UI_PAUSE_RESUME_CAT`，“功能文字”的同名行显示【继续摸猫】。三个页中的键相同是当前填写方式，程序仍须沿引用关系取字句。

已确定的按钮、标签与提示使用表内实际中文。空白正式引用表示尚未登记，不把EX示例当正式字句。程序确定正式内容系统的组织方式，旧《文案配置表》仅供参考；接入后保持各使用处共用同一来源。

页面容量只限制显示，长文字的换行、滚动和全文查看沿对应策划案。正式剧情文字和资源不在“功能文字”页补写。程序汇入同一内容源后仍保留这些使用关系。

## 4. 布局修改与返回记录

以下是游戏运行时的返回记录说明，配置表不新增这些列。它们用于理解正文7.5的恢复规则，字段结构由程序按实际接入维护。

| 运行记录／字段 | 内容与用途 |
| --- | --- |
| `navigation_snapshot` | 本次调用的页面、焦点、滚动和核心引用，供关闭子页或暂停后返回。 |
| `page_id` | 原页面身份，不用屏幕坐标识别。 |
| `focus_ref` | 原控件及其对象的稳定引用；新布局定位同一对象的对应控件，失效时沿该页默认焦点处理。 |
| `scroll_offsets` | 同一布局内的辅助偏移。跨布局先按原页面提供的对象锚点定位，再计算当前可见位置，不能只将旧像素限在新范围内。 |
| 原阅读上下文 | 透传同一对象、准确内容版本、各文字区与来源层的正文锚点，导航不从滚动像素推导对白进度。 |
| `question`、`statement`、`slots` | 引用核心维护的当前问题、说法和两槽，导航不复制第二套卡牌状态。 |

返回记录不保存按钮坐标、贴图路径或排列序号。原控件删除或禁用时，使用该页既有的默认可用控件；换图不另设调查档版本，不重新执行业务或已经播放过的一次性声音。

列表可见卡数、列数或行数调整后，同步翻页、键盘导航和位置恢复，按原对象锚点重新计算页码及可见位置。正文改字号或换行后，按原文本及文字位置重新排版；锚点与旧档处理参见《存读档系统说明》第6节“改布局后的阅读恢复”。界面重建不改变问题、两槽、已提交结果或业务处理锁，保存资格仍按菜单打开前的实际业务页面判断。

## 5. 表头、测试与备注

数据页前4行依次为 `##comment` 中文说明、`##var` 字段、`##type` 类型、`##group` 分组c；第5行起一行一条记录，正式行A列留空。数值按数字填写，必填引用不可空，ID不可重复。`#备注`、`#使用位置` 不导出，也不显示给玩家。

“导航按钮”的 `EX_NAV_DIALOG_BACK` 是子页返回的测试配置，A列标有 `##`，备注说明测试用途。可在测试配置中单独选用该行；正式导出排除测试行。以下划线开头的说明或候选页同样不导出。修改配置时保留人工填写后的实际 Excel。

## 平台与原型说明
