# 存读档系统说明

配套文件：[存读档系统策划案.docx](存读档系统策划案.docx)、[存读档系统配置表.xlsx](存读档系统配置表.xlsx)。

本册仅含策划案、配置表和本说明。原型图已嵌入策划案，图源、独立图片、索引、制作脚本和音频文件均不随包提供。

实际采用人工填写后的 Excel 值，正文保存条件与恢复规则见《存读档系统策划案》。

## 1. 总控与固定值

| 字段 | 已采用制作初值 | 单位与修改范围 |
| --- | --- | --- |
| `id` | default | 正式总控唯一一行。 |
| `manual_slot_count` | 3 | 栏位个数，可改1—10。超过保存页3条可视范围后滚动显示。 |
| `auto_slot_count` | 1 | 固定1，普通自动档数量。 |
| `pre_accusation_slot_count` | 1 | 固定1，指认前保护栏数量。 |
| `ending_resume_record_count` | 1 | 固定1，内部结局续播记录数量；不显示为手动栏。 |
| `save_schema_version` | 1 | 当前存档格式版本，固定1；改变格式及恢复规则时由程序统一登记。 |

固定为1的单元格已有锁定和类型范围。手动栏数只调整栏位数量，保存范围保持策划案已定规则。普通自动档、保护档与结局续播仍按各自时点处理。

保存并返回或退出复用同一手动保存页，由玩家选栏，有旧档时确认覆盖，成功才离开；本表不维护“默认写入哪栏”。完整流程见策划案3.3“保存并返回或退出”。

## 2. 文字与数据归属

“界面文本绑定”中的 `id` 是本册稳定使用键，`text_id` 引用《游戏初始化与开始系统配置表》“功能文字”.`id`。**固定中文文字只在初始化表修改。** 使用键与文字键可沿程序方案映射，保留唯一来源。

场景、问题、材料版本、来源快照、当前会话和处理状态由原模块提供，本配置表不复制这些运行数据。素材替换和界面重排不直接改动存档格式版本。

## 3. 测试与填写

数据页前4行为中文说明、字段、类型、客户端分组c，第5行起为记录；正式行A列留空。数字和布尔值保持实际类型，必填值不可空。`#备注` 与使用位置列不导出。

“存档总控”的 `EX_SAVE_FIVE_SLOTS` 采用5个手动栏，其他固定值仍为1，A列 `##` 和备注已注明用途。需要查看更多栏位的显示效果时，可单独采用该行制作测试配置；正式总控仍使用已采用的default，正式导出排除EX行。以下划线开头的说明／候选页不导出。人工填写后的 Excel 是当前配置依据。


## 4. 完整记录与建议字段

下列字段说明供程序映射实际数据格式，不要求采用旧文案工作簿。它们是运行记录，**不新增到本配置表的数据页**。完整保存组见策划案9.2。

| 字段／记录 | 含义与归属 |
| --- | --- |
| `schema_version`、`content_revision` | 前者识别保存容器格式，后者由主程序登记内容与恢复兼容性；固定配置`save_schema_version`提供当前格式初值。 |
| `save_id`、`slot_kind`、`slot_index` | 保存身份与目标栏位；不按图片、位置或当前选中标题识别。 |
| `save_sequence` | 本机所有栏位与调查共同的成功保存序号；失败不提交，新游戏／恢复／重试不重置，现实时间不参与继续排序。 |
| `saved_at_utc`、`elapsed_seconds` | 前者转本机时区显示；后者含调查与阅读，不含暂停、设置、文件处理和失焦。缺值不补当前时间或0。 |
| `operation_id` | 一次业务返回通知身份，同一通知合并一次；不保留跨会话的旧请求。 |
| `run_id`、`call_id`、`timing`、`group_id` | 构成结果执行身份；恢复／写盘重试／菜单返回保持原身份，新的合法调用生成新值。同组在不同入口合法使用分别执行。 |
| `state_revision` | 核心、内容、世界和导航须导出同一状态修订；已经到期的结果完整提交，尚未到期的状态保留，不写不完整结果组。 |
| `card_snapshot` | 核心的实际材料、已获／已读版、重点、首次序号、每版来源、分类与浏览状态；沿`export_card_state`／`restore_card_state`完整导出和恢复。 |
| 问题容错与尝试记录 | 核心提供已建立的各问题剩余次数、尝试身份及已消费扣次提交。随完整核心快照保存，不用结果组或高潮标记代替扣次记录。 |
| 确认成果、结果执行与关键表现记录 | 核心提供原结果身份、准确目标与冻结依据、`resolved_result_keys`、`applied_group_ids`和`handled_climax_keys`；各记录用途保持，恢复不重新确认、发卡或播放已处理高潮。 |
| `navigation_snapshot` | 本次实际页面、选中、位置与焦点；引用本档`card_snapshot`，不再存第二套两槽。 |
| `question_id`、`statement_id`、`target_selected` | 原问题、精确说法和是否已选目标；未选仍未选，历史版本不改为最高版，读档不按`previous`补发版本。实际引用格式由程序确定。 |
| 当前节点／关系／局部补充／待收／`collected` | 保存实际完整回应、依据与执行标记；恢复不自动收下、继续或重复入库，状态与动作见正文7.2。 |
| `return_stack`、`return_to` | 阅读功能的逐层对象、准确版本、各区滚动与焦点；`return_to`沿调查、出示、调用入口和结局原枚举，回问题列表由核心处理。 |
| 原模块阅读上下文：`body_anchor`、`body_offset`、`source_offset` | body_anchor为《核心玩法系统说明》第3节的接入建议，先用于同会话返回定位；实际合法快照中已有的阅读上下文由原模块提供。正文像素和来源列表位置各有用途，不能互相换算。 |
| `caller_chain`、`resume_kind` | 菜单所属功能维护原调用链；恢复类型区分`investigation`与`ending`，不与来源返回栈混用。 |
| `last_stable_snapshot`、`stable_snapshot` | 前者保留完整会话，不能使禁存页开放；导航资格仍检查菜单打开前真实页面，见正文2.1。 |
| `pending_load_ref`、`save_destination_exclusion` | 前者固定待读目标的栏位类型和编号；后者仅排除待读手动栏，自动／保护档不占手动保存位置。 |
| `cat_first_seen` | 世界对象维护，首次稳定回应实际显示时设true，随完整世界保存；不参与案件条件，返回或首见变化本身不写auto。 |
| `return_handle` | 仅当前会话返回引用，不保存内存地址、不复制牌库、不改变调查`call_id`；旧有效档恢复原调查和猫常态，不恢复动作秒数。 |
| `ending_resume` | 结局ID、指认前完整调查、当前运行状态、已播放／跳过片段、当前片段、字幕／媒体位置、剩余时间及结果执行标记；两份判定状态共同保留，不只指向可能覆盖的pre。 |
| `condition_scope` | 指认前取确认前冻结调查；执行时取此前片段结果生效后的运行状态，按播放顺序逐段检查，名单不代替条件。 |
| `parameter`及固定UI文字 | 共用组件只支持无参数和指认姓名；栏位、时间用独立控件显示。固定正文仅在初始化配置“功能文字”维护，存读绑定引用同一ID。 |

## 5. 核心新增记录与旧档边界

上述容错、尝试、完成与高潮记录由核心随`card_snapshot`导出，和其他模块保持同一`state_revision`。有这些记录的合法档按该档进度整体恢复；0次且未完成的问题重新进入仍显示失败，读档不执行重试或补次数。尚未合法进入的问题继续由核心在首次进入时创建记录。保存资格、自动档时点和栏位保持原规则，返回允许调查页后即使某题剩余0次也按原条件保存，失败页及其阅读层仍禁存。

《核心玩法系统说明》第11节已规定旧档缺少容错记录的初值。仅当核心与存读确认该档属于加入容错规则前、容器与内容版本仍受支持的旧记录时，未完成问题采用3次初值，已完成成果、结果执行与高潮标识保持，不补造旧尝试或扣次历史。不能只凭字段为空认定旧档；新版必需业务记录缺失或快照不完整时，在替换会话前拒绝读取并保留当前会话。格式或内容版本不支持仍按策划案9.1处理，本轮不增加跨版迁移。

## 6. 改布局后的阅读恢复

同会话的重排、暂停与来源返回，由原模块保留阅读上下文。列表和焦点按原对象与控件用途定位，再按当前布局计算可见位置；正文先定位同一精确文本的`body_anchor`，再按当前字号和换行计算显示位置。锚点由精确`text_id`及从0开始的Unicode字符位置组成，计数沿《核心玩法系统说明》第3节，包含标点及换行，不按字节或UTF-16代码单元计数。

合法调查档只消费原模块实际导出的完整快照，仍按策划案9.2处理。body_anchor的字段格式由程序统一确认，本说明不另定存档schema，不创建独立阅读档；配置表也不新增这些运行字段。

旧有效档没有正文锚点时，保留原对象、准确版本和来源层级。程序确认布局相同时可沿既有像素恢复；布局已变或无法确认一致时显示该正文首行，焦点沿当前有效控件或原页默认项恢复。不能从旧像素补造字符位置，也不声称跨布局精确还原。来源列表仍按自己的条目锚点与已有规则恢复。

这些处理只恢复显示位置，不修改业务进度、材料与来源、执行标记或保存资格，不触发隐藏写盘。已有合法记录包含复杂阅读状态时仍按原范围恢复，不因此开放阅读页保存；完整快照与校验继续沿策划案9.2。

## 7. 图示使用的共用显示规格

这些是原图沿用的显示初值，不生成第二份运行参数。普通保存和读取字段规格见策划案2.3；材料／来源阅读器的制作与长文规则沿《办案手册系统策划案》第4—7节。

| 共用区域 | 原图已采用的范围 |
| --- | --- |
| 覆盖／读取／保护确认 | 标题1行20字，正文4行×32字，恢复条件与独立错误区各2行×32字；对应区域独立滚动，底部操作固定，默认焦点取消。 |
| 保存离开目标与失败区 | 离开目标1行20字；失败区1行19字，超出独立滚动，完整原因保留。 |
| 来源原图标题与正文 | 标题2行×19个全角字符，正文可见6行×29个全角字符；超出只滚动对应区，完整正文保留。 |
| 来源条目 | 两列一行，左16、右17个全角字符；超出省略并通过聚焦看全，更多来源在集合内滚动。 |
| 结局占位字幕 | 原图显示2行灰条，仅说明位置与长度；正式字数由媒体／字幕组件接入时确认，本册不新增容量字段。 |

界面显示省略不改变精确内容引用、永久来源或判定正文。布局、字体或素材调整后核算对应显示范围，沿原功能保持全文阅读与操作。

## 收卡演出

收卡时长由核心玩法配置维护。本系统结合收卡演出是否结束及当前页面判断保存资格；演出结束不会单独触发自动保存。
