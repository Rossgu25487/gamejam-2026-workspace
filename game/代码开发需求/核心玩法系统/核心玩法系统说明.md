# 核心玩法系统说明

配套文件：[核心玩法系统策划案.docx](核心玩法系统策划案.docx)、[核心玩法系统配置表.xlsx](核心玩法系统配置表.xlsx)。

本册原名《玩法策划案》，旧说明中使用的该名称均指本册。本次按“核心玩法系统”统一交付文件名，仅含策划案、配置表和本说明。原型图已嵌入策划案，图源、独立图片、索引、制作脚本、制作参数文件和音频文件均不随包提供。

本说明合并配置填写与程序接口，保留原接口第1—11节编号，便于其他系统引用。字段名称与结构说明所需语义，程序确认正式内容格式及映射；正式剧情、人物、证物、对白、场次和资源按实际绑定状态接入。程序尚未构建，本次未执行游戏测试。

目录：第1节规则范围；第2节配置对象；第3节运行记录与来源；第4节调用与结算；第5节补充与结果返回；第6节跨次核查；第7节表现与业务结果；第8节待执行接入检查；第9节分段配置；第10节职责与字段映射；第11节容错与重试；附录A配置表使用；附录B界面参数与运行数据。

## 1 固定规则

完整玩法与界面见《核心玩法系统策划案》第1—7节。接入保持以下边界：同一案件共用一份材料集合，材料不消耗；底栏5张、网格6列2行、最多两个独立出示槽，单份充分可以成立。材料按身份集合匹配，左右位置和放入顺序不改变结果；同一材料的两个版本不能同时出示。

statement问题首次进入时目标未选；reasoning问题从合法入口进入后已选定当前问题，两个出示槽均为空。再次打开同问恢复草稿、target_selected与精确引用，进入不同问题按目标类型初始化。

材料取得、已获版本和来源由核心维护。共用详情、版本与来源阅读见《办案手册系统策划案》第3—7节，手册视图不覆盖选材草稿。表现等级与业务结果分别处理，新推论仍需主动收下；每题3次容错和结果生效时点见第4、5、11节。

## 2 配置对象与目标引用

对象概览说明必需的内容关系，字段与存储结构由程序确认。推荐表头及字段说明见第10节，旧工作簿不作为正式格式约束。

| 配置对象 | 字段或引用 | 使用要求 |
| --- | --- | --- |
| 材料身份 | material | 使用稳定material_id，不使用中文标题作为身份 |
| 材料内容 | id、version、previous、kind、carrier、title、summary、body、version_note | id为content_id；标题、摘要、正文与来源属于同一内容版本 |
| 说法身份与版本 | claim、id、version、previous、topic、speaker、material、text、record_content | id为statement_id；record_content必须真实包含原话，材料版本与说法版本分别保存 |
| 问题入口 | question_id、实际文本引用及新增target_kind | target_kind为statement或reasoning，缺省statement；入口条件必须已经满足 |
| 出示关联 | statement、match、a、b、a_content、b_content、a_version_rule、b_version_rule、condition、node、after、inference、next_use、a_quote、b_quote；新增question、effect_level、climax_key | 人物说法关联填写statement；推理问题关联填写question并留空statement。推理问题不填写用于目标说法更正的after |
| 来源 | owner、kind、entry、object、text、basis_content、basis_statement、relation、basis_slot、basis_relation | owner指内容版本；通用来源行和本次命中relation的来源行进入快照，其他解法不混入 |
| 节点与选项 | next、return_to、result、timing、button；选项使用condition与supplement | 使用既有结果组和执行时点，不另外建立返回枚举或结算接口 |

MaterialRef为{material_id,content_id}。StatementRef为{claim_id,statement_id}。统一TargetRef为{target_kind,question_id,statement_ref,question_text_id}，其中statement_ref与question_text_id按目标类型二选一。人物说法通过精确statement_id解析原文及record_content；推理问题记录实际question_text_id，不给问题额外创建材料身份。正式配置必须明确这个文本引用，不能把标题或原型中的灰条作为目标身份。

推理关系中的question必须指向玩家打开的问题。人物说法关系中的statement必须属于该问题的合法目标，且玩家已经听到这个版本。目标文本只用于明确本次核查对象。推理问题没有人物原话，statement_quote、目标说法after及target_after_ref留空；表现形状只使用支持、普通或涌现，不限定或碎裂问题文字。需要更正人物说法时使用对应的合法人物说法关系。

数字version仅用于显示内容版序。previous不授予玩家尚未取得的版本。玩家直接取得新版时只持有该版本；后来真实取得旧版，可以增加历史记录，当前内容仍指向已取得的最高版本。选择旧版只读取旧版正文和观察，不能借用当前新版的信息。更换同一材料的版本前，先从出示槽撤下该实体，再选择正在查看的版本。

目标的说法版本、类型或问题文本引用发生变化后，更新目标显示并使旧的局部补充失效。出示槽中的材料继续保留选用时的版本；已经确认的结果保留确认时的TargetRef及实际依据，不随新目标改写。

回看旧话读取该记录当时的精确说法版本，不替换当前问题的合法目标，也不把更正前的原句设回当前说法。恢复草稿时使用原精确引用；当前问题目标已经变化时按原目标更新规则处理，不能从手册正在阅读的条目猜选目标。

## 3 运行记录与实际来源

| 记录 | 接入字段建议 | 更新要求 |
| --- | --- | --- |
| 材料实体 | material_id、type、acquire_index、current_content_id、acquired_content_ids、viewed_content_ids、important | 首次取得、内容更新、实际阅读和重点标记时更新 |
| 内容来源 | sources_by_content[content_id]：entry_id、object_id、relation_id、source_ids、MaterialRef[]、StatementRef[]、confirmed_result_refs[] | 普通材料每次真实取得时冻结该路径条目，另一真实路径追加、同一路径重复不追加；推论来源在形成时冻结，收下时整体提交 |
| 两个材料视图 | type、sort、important_only、positions_by_type、focus_ref；网格另有initialized和expanded | 底栏与网格分别保存位置，按四种类型分别恢复 |
| 当前问题草稿 | question_id、TargetRef、target_selected、slots[MaterialRef或null,MaterialRef或null] | 玩家选用、撤下、选择目标或离开当前界面时更新 |
| 场内窗口 | card_ui_page、last_selection_view、card_caller_ref | 页面值为closed、selection、grid、pending、collected；与mode独立，避免存两套互相冲突的显示状态 |
| 临时检视返回 | inspection_return_ref、opened | 保存原页面、mode、current_node_id、result_id、正文位置、来源层级和焦点；关闭检视后释放该返回引用 |
| 正文阅读锚点（接入建议） | body_anchor：text_id string、character_index int；body_offset为同布局辅助偏移 | 每个正文阅读上下文和来源层级分别保存实际文本引用与字符位置，不改变保存资格；旧档缺少锚点时继续使用已有恢复路径 |
| 当前结果 | mode、run_id、call_id、result_id、relation_id、current_node_id、target_ref、used_sources、option_refs、inference_content_id、collected | 出示时冻结本次实际采用的来源；节点和操作状态继续更新，后来取得路径不补入本次used_sources |
| 已确认结果 | result_id、relation_id、target_ref、confirmed_scope、used_sources、confirmed、completion_index | 对应结果组完整提交后才设置confirmed=true；保留形成时的used_sources，completion_index在当前run中单调增加 |
| 表现快照 | TargetRef、statement_quote、effect_kind、effect_level、climax_key、selected_presentation、target_after_ref、first_resolution及实际来源 | 判定完成后冻结，不因检视、暂停或来源返回重新选择强度 |
| 业务执行记录 | resolved_result_keys、applied_group_ids、last_result_id | 继续使用既有结果去重；结果组按run_id、call_id、timing和group_id记录，不重复执行 |
| 关键表现记录 | handled_climax_keys | 进入关键表现时写入当前进度内存，随下一次合法调查档保存，不增加保存资格 |

body_anchor为{text_id,character_index}，用于运行上下文的接入建议，正式存档结构由程序与存读模块统一确认。text_id引用当前正在阅读的完整正文文本；character_index从0开始，0表示正文开头，按该文本实际解析字符串的Unicode字符（码点）顺序计数，包括标点和换行，不按UTF-8字节或UTF-16代码单元计数。只能用这个位置恢复同一个精确文本引用，不能拿它定位另一篇正文。

重新排版时，程序先用body_anchor找到对应文字，再按当前字体和换行计算显示位置。body_offset只记录同一布局内的辅助像素偏移，不能直接转换成字符索引。来源回查的每一级正文分别保留body_anchor；source_offset仍按既有规则记录来源列表位置，不用正文字符位置替代。旧档没有body_anchor时，保留既有文本引用及body_offset、source_offset恢复路径，不填造精确字符位置，也不宣称跨布局精确迁移已经完成。字段接入与存档消费者统一验证，仍只在原来允许的保存边界写入。旧有效档缺少正文锚点且布局已变或无法确认相同时，保留原对象、准确版本和来源层级并回正文首行，具体见《存读档系统说明》第6节。

底栏位置使用anchor_id、page和full_anchor_id；网格位置使用anchor_id、offset、full_anchor_id和full_offset。offset表示锚点距可见区上沿的位置。新增材料和内容更新保持锚点；原锚点被筛除后优先选择下一项，再选择上一项，没有项目时显示可以退出的空列表。

所有实际取得版本都未读时，卡牌显示新标记。已经阅读过任一版本而当前版本未读时，显示更新标记。当前版本已经阅读后不显示这两个标记。打开已取得版本的材料全文或来源全文才记为已读；焦点预览、选用、重点标记、调查正文及尚未入库的推论预览都不替代这次阅读。阅读旧版不清除新版的更新标记。

固定的新推论入口只统计首次入库后尚未阅读的推论实体。没有推论时入口不可用；只有一张时直接打开详情；多张时按获得顺序用同一阅读器逐项查看。打开时冻结new_inference_refs和entry_index，当前列表不会因为阅读清除了标记就缩短；关闭后再次进入，才重新计算未读集合。

### 普通材料来源与成果快照

普通材料的同一content_id经另一条真实取得路径获得时，在sources_by_content的来源集合末尾追加该次实际来源条目，原条目及其精确引用保持不变。取得路径需要按来源身份及实际入口识别，本案以来源行身份、entry_id与relation_id说明其含义，具体字段由程序映射。同一路径重复取得不追加，新的call_id不使旧路径变成新路径。各次取得按约定顺序保存，不重排早先条目，也不混入没有经历的路径。追加来源不增加卡牌、内容版本或获得序号，不改写正文、当前最高内容版本、已读标记和两个出示槽中的引用。阅读、暂停及来源返回不构成取得；观察或正文信息发生变化时，仍按内容版本规则处理。

推论及已确认成果的used_sources固定为形成当时的快照，包括实际采用的来源条目、材料版本、说法版本和前次已确认结果。实际依据的每一级下属来源都随形成时快照固定；不能只保留MaterialRef，再在下一层读取后来扩大的普通材料来源集合。推论收下时提交已经冻结的快照；后来取得的材料路径不能补入旧推论或旧成果的证明。直接阅读普通材料时，手册显示该content_id当前已经实际取得的来源集合；从推论或确认成果回查时，各层均沿该成果自己的used_sources展开。

record_content只表示说法所属的原文，不自动构成来源追溯边。材料来源、说法来源和已确认结果的引用不能形成循环。来源阅读共用《办案手册系统策划案》第6“来源回查”的阅读器，保存每一级引用、正文位置和来源列表位置。来源成立、真实取得与成果快照由玩法和文案提供，手册按提供的集合显示，不自行追加取得经历。

跨次证明使用来源kind=已确认关联依据。basis_relation填写完整出示关联记录ID，与同一来源行的basis_content、basis_statement、basis_slot互斥。relation筛选本次来源分支，basis_relation定位前一次已经确认的结果。核心按当前run_id、指定关联及精确TargetRef筛选confirmed=true的记录，并选择completion_index最大的一条。

本次结果及来源快照中的confirmed_result_refs记录所选前次结果的result_id、relation_id、target_ref、completion_index、confirmed_scope和used_sources。后续回查沿这一冻结记录展开，不重新选择最新结果，不替换当时使用的材料版本。没有找到符合要求的已确认记录时，这项来源不成立。

已知条件决定问题入口或关系是否可用。作为证明依据时，还必须声明并取得实际来源，不能只用“已经知道”条件替代证明。前一次结论不占第三个出示槽，也不会自动变成可以选用的卡牌；需要选作材料时，必须正式配置推论并由玩家主动收下。不生成卡牌的确认范围，可以在已核问题和交谈记录中回看实际依据。

程序需消费完整核对目标、前次确认、真实来源与逐层冻结、表现等级，以及调用、返回和结果时点。本案以target_kind、question、basis_relation和effect_level等字段说明需求，正式数据格式与映射待程序确认。旧工作簿与样例检查只作历史参考，不证明当前接口已接入。

交谈记录需按实际顺序提供已经合法显示的原话、署名和精确引用，已生效归纳另区显示；未播放分支、未来句和未生效结果不进入可读范围。后续追加新句或归纳时恢复未读，旧话保留当时版本。记录范围由程序生成的实际记录提供，手册不从完整配置自行猜选已听部分；查阅、暂停和重绘不补播、重记或执行结果。记录显示与阅读进度见《办案手册系统策划案》第7节，关闭后仍回原会话节点或结果。

## 4 调用、结算与连续核查

| 调用 | 输入 | 处理结果 |
| --- | --- | --- |
| acquire_material | content_id、实际entry_id和source_id、当前关系上下文 | 建立或更新材料实体；同一普通内容按第3节追加另一真实路径，重复路径不追加；返回是否首次取得及数量变化，同版追加不增加数量 |
| open_material_library | browse或presentation模式、调用界面、问题、目标和原视图 | browse使用办案手册的共用展示，只提供阅读和个人整理；presentation使用玩法的当前问题草稿和两个出示槽 |
| open_card_session | 已开放question引用、target_kind、TargetRef、当前地点、可选交谈对象和card_caller_ref | 验证合法入口与当前问题容错；0次未完成时显示失败页，否则按原目标／草稿进入，不转场、不写自动档 |
| fold_card_selection | 当前问题、稳定selection或grid页面、原调用引用 | 保存当前问题的草稿和视图，关闭可见选材层，返回原调用界面，不执行结果组 |
| open_material_inspection | 原稳定页面、mode、返回引用和已拥有集合 | 打开【办案手册】检视；不选用卡牌、不改变出示槽、不进行关系判定，结束检视后恢复原界面 |
| select_material | MaterialRef | 验证玩家已经取得该内容、材料身份未重复且还有可用槽，再放入最靠左、尚未放入卡牌的出示槽 |
| withdraw_material | slot_index或all | 只撤下指定槽中的卡牌，另一个槽的位置不变；按当前筛选和排序恢复材料列表 |
| present_materials | question_id、TargetRef、出示槽中的MaterialRef集合和条件状态 | 冻结目标与材料版本，返回result_id、relation_id、feedback、node、used_sources及表现快照 |
| supplement_source | 局部result_id、玩家点击的content_id、基准和目标版本 | 检查实际持有与条件，放入尚未放入卡牌的出示槽，再重新匹配完整关系 |
| collect_inference | result_id和等待收下的inference_content_id | 整体执行收下结果组，拥有与来源同时提交，返回已经收下的结果页面 |
| continue_result | result_id、成功或尚未完成结果、continue／reselect／defer动作 | 成功正常结束；重选恢复草稿，稍后核对保草稿回原调用。0次失败只允许回原处，不接受成功继续或重选 |
| retry_question | 当前失败question_id、实际合法入口及容错记录 | 主动恢复当前问题3次并清草稿／局部；按当前目标初始化，其他知识、成果、高潮与容错记录保持 |
| export_card_state、restore_card_state | 存档请求或已经验证的卡牌快照 | 导出或恢复核心数据，不决定外部存档栏位和页面 |

出示时先检查目标合法、尚未完成且剩余容错大于0，再按TargetRef筛选关系，依次检查双份充分、单份充分、局部成立／有效反证、明确错误和默认不足。条件分支内部全部满足，不同分支任一即可；版本和观察只读取实际取得／选用内容。同优先级不能指向不同成果或互斥错误原因，接入前修正。错误关系的最低语义见第11节。

不生成推论的结果使用节点配置的执行时点。人物改口在进入相应回应节点时执行，支持事实在玩家点击继续时确认。生成新推论时，进入推论节点只保存等待收下的对象及实际来源；确认、更正、下一问题解锁与推论拥有统一在玩家收下时执行。结果组按order整体执行，after和inference只是预期引用，不能额外执行第二遍。

文案切换节点时回传current_node_id，恢复显示该节点的完整文字。结果组已经执行过就不再触发。推论节点的next在玩家收下前不推进，自动播放不能绕过收下。表现结束只改变显示，不自动确认尚未提交的结果。

连续核查由文案显式配置下一问选项。玩家点击【继续】或配置的下一问选项后，核心先调用continue_result，完成当前结果在该时点应执行的确认与结束步骤，清除该问题的目标选择、两个出示槽中的卡牌引用及临时补充状态，再依据更新后的真实条件处理后续入口。支持事实如果在点击继续时才确认，必须先执行这次确认，不能为了预先开放下一问题而提前写入事实。

普通继续仍返回原调用界面，不自动选择另一个问题；玩家选择配置中的合法下一问选项时，再调用open_card_session打开对应问题。statement类型仍由玩家选择具体说法，reasoning类型的当前推理问题已经被选为核对目标。两个出示槽里都还没有放入卡牌。后续入口没有满足真实条件时，不能进入该问题，也不能自动改选其他入口。

产生新推论的结果必须先由玩家收下卡牌，收卡动画结束前不能进入下一问题。已经收下的成果也必须按正常结束步骤收束，不能通过下一问选项跳过当前结果。下一个问题在当前地点内通过合法入口打开；需要跨地点时，仍使用原调查转场规则，不通过连续核查暗中移动场景。

### 界面开合与随时检视

调查、普通会话、稳定选材、稳定网格、完整回应、待收、已收及失败页默认允许【办案手册】或I检视。打开时暂停当前文案自动播放及计时，保留原节点和文字位置；关闭后由玩家继续。资料阅读和个人整理不改变目标、出示槽或结果，正文尚未读完不限制检视。

进入对局时记录card_caller_ref，包含调查或会话页面、问题列表、地点视角、文案节点、焦点和滚动位置。呼出约250毫秒，收起约200毫秒，只改变界面显示，不移动地点，也不重新启动一次人物问话。返回调用界面时使用当前有效节点和已经执行的更正，不能恢复旧说法。

稳定选材和稳定网格可以直接收起。核心保留当前问题的精确目标、材料版本、last_selection_view及各自列表锚点；再次打开同一个问题时恢复这些值。收起牌库只返回五张卡牌的基础视图，收起对局只关闭选材层，不能把这两个动作当成关闭资料阅读器。

出示反馈结束后，card_ui_page为closed，无新推论且未归零失败的结果使用mode=response；归零未完成时mode=failure。没有新推论的成果显示完整回应，不显示可以操作的出示槽或五张卡牌；回看依据仍读取这次使用的版本。成功结束后清除当前问题的草稿；局部或不足结果可以重新选材，也可以选择【稍后核对】返回原调用界面，保留当前问题的草稿，不完成该问题，不开放它所要求的后续内容。

只有明确标记的连续镜头、完整关键演出、收卡动作和不可中断结果事务暂时禁止检视。inspection_policy的接入值为allow或cinematic_lock，缺省allow；锁定段必须声明结束点，进入稳定对白或回应后解除。普通和递进短表现可以先显示其稳定目标，再打开检视，不能代替玩家点击继续或收下。连续演出锁定期间拒绝I键并说明原因，不排队等待结束后突然打开。

办案手册检视中按I或点击【关闭手册】，结束整个本次检视并恢复inspection_return_ref，不重复叠加检视。Esc每次只处理最上层：先关闭筛选或版本面板，再返回来源上一级、收起材料抽屉、关闭详情，最后关闭手册并回原调用页面；回到选材后，再按Esc才收起网格或没有其他窗口覆盖的稳定选材页面。暂停菜单、设置或读取子页处于最上层时，I不穿过该层关闭手册。response、pending、collected及failure页面没有上层阅读器时，Esc打开菜单。菜单和失去焦点只暂停当前页面，不收起结果界面。共用阅读输入见《办案手册系统策划案》第8.1“逐层关闭与输入”，玩法页面的业务限制仍由本节规定。

### 场景与人物显示

current_scene_id由调查模块维护。人物说法核查根据问题对象的parent取得talk_character_id，目标说法的speaker必须属于同一交谈对象。普通问话使用入口target。文案当前节点的speaker只决定台词署名，text决定正文，不切换左侧交谈对象。

背景从current_scene_id解析场景对象asset，再读取背景资源path。人物从talk_character_id解析角色asset，再读取立绘资源path。portrait非空时读取当前角色的完整表情变体，空值读取该角色默认资源；每个节点重新求值，不沿用上一节点的表情。缺少人物资源时仍显示合法姓名和正文，不切换人物或地点。

reasoning可以不具有交谈对象。没有交谈对象时不建立talk_character_id，不加载人物立绘或身份行，显示问题说明和配置明确引用的相关已确认事项。存在合法会话上下文时可以保留该交谈对象，不能因为材料署名或台词发言者变更而切换。相关已知事项只提示范围，真正作为证明时仍须声明basis_relation。

场景名称、人物姓名、身份和节点正文通过文本引用解析，不直接显示配置ID。speaker为空时只隐藏台词署名。观察原件或肖像属于材料阅读界面，不替换交谈对象。背景虚化、阅读时人物透明度和素材保护范围读取制作参数，不决定业务地点。

进入会话时保存return_scene_id和return_view_ref。资料、来源、菜单和检视沿原上下文返回。明确的转场请求成功提交后结束旧会话，更新当前地点和调查返回基准；准备失败时保留原场景。多人物演出由文案模块按节点切换资源，结束后重新建立单人物问话或推理问题的上下文。

### 结算去重与保存资格

每次文案调用记录run_id和call_id。收下、查看来源和暂停恢复沿同一次调用处理，不创建新的call_id。结果组的去重键为(run_id,call_id,timing,group_id)。合法的新调用可以复用结果组；同一逻辑成果和推论拥有仍由resolved_result_keys与材料身份判断，不能只按调用次数发放。

本文中的保存或提交首先表示更新当前运行内存，不等同写入存档文件。手动保存只允许可操作调查主画面、问题列表，以及稳定选材界面，包括稳定网格和整理面板。对白、普通回应、资料、目标详情、交谈记录、来源、等待收下、已经收下但尚未继续的结果、判定、演出和收卡阶段，都不能写入新的手动调查档。菜单、设置和读取子页不提高资格。

进入等待收下的页面、点击收下、收卡开始或刚结束、打开关闭资料或来源，都不写入新的普通自动档。结果组完整提交、表现完成，并且玩家按正常流程返回允许调查的页面后，当前有效流程才按既有条件触发一次完整自动保存。核心不代替玩家收下或继续，不保留跨会话的补写队列，旧流程被替换后不再发出保存请求。

不可中断事务期间不接菜单请求。纯表现暂停时停止画面和声音的播放时钟，保持当前帧与原处理锁，不完成显示，也不代替业务操作。玩家选择跳过时才显示既定终态；暂停和跳过都不扩大保存资格，保存模块按实际业务状态判断。正式指认前保护、阶段前后保护和结局内部续播分别按《存读档系统策划案》第6节、5.2与第8节处理。处于禁止保存的页面时，离开确认提供直接离开和取消，保存选项不可用；读取其他档案也不增加先保存资格。直接离开会丢弃最近一次成功保存之后的变化。

## 5 主动补充与结果返回

局部补充只使用玩家实际点击的已拥有内容版本，不自动代用已有材料。两个出示槽都已放入卡牌时，先回选材界面撤下无关卡牌。基准材料撤下、目标改变或目标版本改变后，旧局部补充失效，必须重新判定。

不生成推论的结果先显示完整回应。需要生成推论的结果先读完整回应，再保存等待收下的对象及实际来源。三个表现等级都保持相同业务结果。未收下的新推论不能进入持有集合、不能参与下一次出示，也不能提前执行它所绑定的更正、确认和解锁。

| 状态或操作 | 必须保持的行为 |
| --- | --- |
| 进入推论节点 | 保存result_id、relation_id、current_node_id、inference_content_id和实际来源，不执行收下结果组 |
| 等待收下时点击【回看来源】 | 独立调用来源阅读器并读取本次used_sources；逐层保存返回位置，不建立推论实体，也不套用办案手册的整次检视调用 |
| 来源上一级或Esc | 只返回上一层；第一层返回它的调用对象 |
| 关闭来源阅读 | 结束本次来源阅读，回到最初详情或同一个等待收下的推论页面，恢复位置、焦点和出示槽引用 |
| 待收、已收或失败时打开菜单 | 暂停继续或取消离开回原页面；返回标题／退出沿共用确认，禁保存，直接离开可用，不提交未完成结果或推进next |
| 点击收下 | 验证当前待收引用，整体执行唯一收下结果组，同时提交拥有、永久来源、确认、更正和解锁 |
| 收卡动作结束 | 显示已经收下的稳定结果，允许继续及检视；新卡不会自动放入出示槽 |
| 点击继续或合法下一问选项 | 按正常结束步骤清除当前问题的草稿，再返回调用界面或初始化已经开放的下一问题 |

等待收下时允许菜单、只读全库检视、实际来源和收下操作。改变目标、修改出示槽、离开场景及进入下一问题仍不可用。通过【办案手册】或I进入的整次检视，关闭后回原待收页面；通过【回看来源】独立进入的阅读，关闭后回同一待收全文。独立来源页中按I，沿原检视许可打开完整手册，结束该次手册检视后返回原来源页及层级；I不替代【关闭来源】，也不穿过上层菜单。两种调用均保留当前结果、正文位置、焦点和两个出示槽的精确引用，不能隐式收下。共用阅读动作见《办案手册系统策划案》第6“来源回查”和8.1“逐层关闭与输入”。普通问话不使用出示槽中的材料；从核查中进入普通问话且没有转场时，返回原问题和位置。

普通材料按取得节点直接入库，没有等待收下步骤，不锁定正常操作。新操作切换页面时结束这次显示，已经取得的材料和未读状态保持。核查生成的新推论仍必须由玩家主动收下，不能通过普通材料的即时入库步骤绕过这次提交。

## 6 跨次核查与关卡配置

关卡由问题入口、目标、材料、出示关系、条件、节点和结果组组织，读取同一份内容与持有集合。具体配表由程序确定；每段仍需明确核查目标，不在本接口填写正式台词、证物、场景事件或游玩时长。

| 配置项 | 内容要求 | 核心处理 |
| --- | --- | --- |
| 开始入口 | 问题引用、target_kind、实际目标文本引用、开放条件和调用上下文 | 尚未开放的问题不能进入；两种目标分别校验合法引用 |
| 证明目标 | 确认范围、可用内容版本、充分关系、局部及未命中回应 | 保持本次选用的版本，一张材料充分时无关第二张不进入来源 |
| 中间结果 | 回应节点、结果组、执行时点、是否生成推论和实际来源 | 不生成卡牌时保存已确认记录；生成推论时等待玩家主动收下 |
| 后续入口 | 必要的已确认事实或已拥有内容，以及显式下一问选项 | 只开放合法入口，不自动选择问题或改变地点 |
| 前次依据 | 需要引用的basis_relation及其实际确认范围 | 已知条件和证明来源分别校验，冻结实际结果，不占额外出示槽 |
| 等价解法 | 相同确认范围、业务成果、结果组、是否生成推论、强度和必要高潮标识 | 共用成果去重，每条路径仅保存本次命中的实际依据 |

串联把上一段已经确认的结果作为下一段的开放或成立条件。并联允许多个已开放的问题按不同顺序完成，各自保存实际结果。汇合在同一条件分支要求必要的前段全部完成，再开放共同的后续问题。可选补证使用独立条件分支或额外可选问题，不提高已经充分的最低要求。多解法通过不同合法关系指向同一成果，不能只因为共用动画就判为同一结论。

条件为真只说明入口或关系可以使用。后续核查真正采用前次结论作证明时，必须另外配置basis_relation，读取实际已确认记录。没有生成卡牌的结论通过已核问题或交谈记录回看，不能拖入出示槽。需要选作牌时，正式配置推论并完成主动收下。

每段必须有可以到达的开始条件、可以取得的充分依据和正常返回路径。循环依赖使任何前提都无法取得、同优先级关系指向不同成果、尚未收下的推论提前解锁后续内容、未声明的材料自动补入，都需要在内容接入前解决。扩展不增加推理点数、成功概率、任意合成或强制固定问话顺序。

## 7 三级表现与业务结果

| 字段 | 填写要求 | 核心使用 |
| --- | --- | --- |
| effect_kind | 支持、收窄、击破、涌现或普通 | 选择形状，不改变feedback、结果组或执行时点 |
| effect_level | normal、progress或key，缺省normal | 选择普通反馈、递进推理或关键突破，不参与匹配 |
| statement_quote | 人物说法的限定或排除表现需要填写，必须是目标全文中的唯一连续片段 | 只定位指定原句；推理问题留空，不碎裂问题文字 |
| climax_key | key必填，normal和progress留空 | 同一个关键认识转折的合法解法共享，在当前进度中记录已经处理 |
| a_quote和b_quote | 本次实际使用内容版本中的连续原句 | 只高亮实际依据，不绑定左右出示槽 |

normal承载日常确认、限定、普通排除、局部、不足及重复成果回读。progress用于充分关系首次确认新的范围或事实，或者形成新的推论，默认表现约3200毫秒。它可以只保存确认结果，也可以生成普通推论，或通过结果组开放后续问题，不要求与人物原话发生矛盾。key用于主要调查方向改变、重要解释排除或阶段证明链闭合，提供最高规格的击破或涌现。

等级、形状与是否生成卡牌分别配置。已经成立的普通排除仍完整更正说法，普通关联仍可以生成推论；递进确认可以不生成卡牌；关键涌现也可以只揭示重大新确认。表现强度不能补造充分条件，也不能替代作者明确声明的确认范围。

关系判定完成后，在本次结果组执行前确定first_resolution，冻结selected_presentation、TargetRef和实际来源。首次依据精确目标、确认范围及既有完成结果判断，不依据调用次数或动画名称。同一成果的等价解法共用稳定业务引用，程序不通过台词相似程度猜测两个结论是否相同。

progress只用于首次充分成立的新结果。重复成果使用普通回应回读，复用result_id、resolved_result_keys和confirmed记录，不新增progress_seen队列或累计数值。局部反馈仍是当前问题尚未充分完成的结果，不因为画了进展效果就写入永久完成状态。普通话题如果明确核明同一合法成果，共用该成果记录；纯台词切换和重读不自动确认。

### 关键表现准入与终态

key需要充分关系、首次重大认识转折、明确climax_key以及当前进度尚未处理该标识。人物说法的击破还需要精确断言片段和与它互斥的实际依据。推理问题没有人物原话，不能使用断言碎裂；重大新确认可以采用关键涌现。

关键涌现有两个结果分支。需要生成新推论时，还必须确认这个推论身份尚未拥有，结束后显示完整等待收下的推论，玩家主动收下才能提交拥有、更正和解锁。不生成新推论时，必须是首次新增的重大确认结果，灵感演出揭示结论图文后返回完整普通回应，仅提供继续、回看依据和办案手册入口，不显示收下按钮，持有数量不变。

不生成新卡牌的关键涌现使用key_insight_fact表现分支，退出时mode=response、card_ui_page=closed。需要玩家收下的新推论退出时mode=pending、card_ui_page=pending。核心依据配置的inference_content_id和业务结果选择终态，不从动画形状或粒子是否出现推断。

已经拥有的推论如果只被再次说明，使用普通回读；如果这次有新的合法确认或更正，作者另外配置结果与执行时点，按该新成果判断等级。不能重新发放旧推论、覆盖首次来源或自动执行旧的收下结果组。同一成果的多条合法路径，结果组、是否生成推论和climax_key必须一致。

同一次成果同时更正说法并生成新推论时，只选择一个主表现，先说明合法更正范围，收下后才整体提交。没有新推论的关键成果继续使用其原节点执行时点，不增加专用结算接口。动画结束后读取明确配置的终态，不通过定时器推测是否应发卡或打开下一问题。

### 重复、暂停与读取进度

进入选定关键表现时，把climax_key写入当前进度内存。正常播放、跳过和减弱动态都视为这个高潮已经处理。暂停、只读检视、来源返回及同成果的另一解法都不重复播放；业务去重仍沿resolved_result_keys和结果组执行记录，两类标记互不代替。

关键标记随下一次合法调查档保存。已经完成的档案恢复完整结果，旧的待收或已收档案恢复稳定阅读页面，不续播动画。读取突破之前的旧档，再重新完成核查，可以在该档进度中播放一次。系统不记录跨档案的永久观看历史，不增加禁止保存页面的写入资格，也不保留后台补写队列。

普通、递进和关键表现结束后，完整回应或推论全文都没有阅读倒计时。暂停保持当前画面与声音时钟，不推进播放；跳过才完成当前显示，不代替继续、收下或下一问选择。静音仍能读到确认范围，减弱动态使用静态对照代替强位移。连续段的检视限制保持，收卡期间的检视锁随演出调整为900毫秒。

同一转折在当前进度只处理一次，每次出示只选一个主高潮。关卡可参考2—3次递进后安排一次关键转折，此参考不参与运行判定；不配置时间冷却、随机概率或累计成功门槛。关键资格不足时使用普通反馈，失败／重试不清高潮标识。

### 接入责任

缺省normal用于已有配置。progress没有充分新结果、key缺少climax_key、推理问题使用断言碎裂、同一高潮标识指向不同认识转折、等价解法产生不同业务结果，都属于需要在接入前修正的配置错误。表现字段不能吞掉合法结果，也不能凭显示效果产生事实。

策划确认玩法所需的问题、原话、证明范围、依赖与结果时点。文案系统设计、数据格式、配表与字段映射由程序确定；程序消费完整目标、实际已听记录及来源，冻结目标、证明与表现选择，按既有时点提交结果。存档模块在原合法边界读取联合快照。当前交付玩法需求，正式映射及运行接入仍待程序确认。

## 10 扩展边界与推荐配置格式

### 共用手册展示与玩法职责

共用展示引用《办案手册系统策划案》第3—7节，关闭、输入与返回引用该案第8节。手册读取实际已知内容、版本和来源，不从未来配置推定玩家已经知道的内容。

调查回顾单份阅读沿《办案手册系统策划案》8.4“调查回顾中的单份阅读”，只传准确对象、实际来源集合或成果各层冻结快照，以及原回顾返回引用。关闭回原条目、位置与焦点；I按该阅读层处理，不套用核心待收来源的检视调用。手册不解析原目标和结果，也不自行确认、收下、推进或发出保存请求。

玩法继续维护材料身份、实际取得和已读版本、获得序号、重点标记，以及第3节的真实来源和成果快照。选材的五张卡牌底栏、六列两行网格、两个独立出示槽、目标选择、草稿、关系判定、补充、待收、主动收下和结果执行仍由玩法维护。手册自身的页签、筛选与浏览位置按手册规则管理，不覆盖玩法底栏和网格的视图；关闭阅读后恢复原玩法调用、精确目标、槽内版本、结果和焦点。

办案手册检视中的共用阅读器不得显示选用、撤下或出示动作；从玩法选材直接打开的详情，才沿原presentation模式提供合法操作。一般详情和版本展示可以引用手册章节，所选版本不能在槽内被替换、第三张材料不能自动挤掉已有材料、待收来源必须返回原待收页面，以及阅读不得扩大保存资格等业务约束仍保留在本文件第1、4、5节。来源冻结与返回沿本说明第3—5节。

材料与成果、出示规则、结果提交和界面按以下职责接入：

| 部分 | 维护内容 | 接入要求 |
| --- | --- | --- |
| 材料与确认成果 | 身份、已获版本、实际来源、已确认结论和依据 | 独立于两个槽的开合、卡面位置及玩法界面。调查或交谈取得材料时可直接调用 acquire_material。 |
| 出示核对规则 | 当前问题、最多两份材料的核对、单份充分、判定顺序、局部补充和容错 | 读取实际已知内容，不依赖卡面坐标、动画时长或手册排版。 |
| 结果提交与执行记录 | 结果身份、实际依据、生效时点和已执行记录 | 沿确认、继续和主动收下的既定时点提交，不以按钮文字或动画重播决定。 |
| 界面与演出 | 显示业务状态，提交玩家动作和对象引用 | 不直接修改材料集合、推定目标完成或写存档；导航读取已生效的案件状态与目标。 |

完整材料集合由核心维护，显示页按筛选、排序和容量计算。改变可见数量时，分页、滚动、键盘操作和原对象定位一同调整，保留集合和草稿。未来新增机制需要自己的输入规则、界面及可保存进度适配，可复用兼容的材料与结果语义；当前不预建新机制配置，不将新操作套入两槽关系。阶段变化仍交案件模块按确认及保护流程处理。

### 功能与表现分别维护

新增问题、材料内容版本、合法关系、条件分支和等价解法，沿现有目标、结果组和来源引用配置。它们可以扩充核查内容，但不能仅靠配置文字扩大出示上限、增加新的目标种类或改变结算时点。涉及这些规则时，需要同时明确数据结构、校验与消费者的变更。

颜色、纹理、字体、立绘、缩略图和布局可以重新设计，材料身份、目标引用、确认记录和永久来源保持不变。两个出示槽可以移到不同位置，但仍各自绑定固定槽编号；撤下指定槽中的卡牌不能因为重新排版而移动另一个槽。底栏显示数量、网格列数或可见行数的改变影响导航、翻页和位置恢复，需要明确作为功能调整接入，不能当成单纯换皮肤。

正式界面必须按稳定动作键、语义区域和当前业务状态绑定输入。区域位置、大小、字体和素材适配从最终布局读取；重新排版后，命中范围随当前布局重新计算，不能沿用旧图坐标。按钮改变中文名称、颜色或形状后仍调用同一业务接口，颜色变灰或图像隐藏不代替程序拒绝输入。

| 接入对象 | 稳定绑定 | 布局改变时的要求 |
| --- | --- | --- |
| 操作控件 | 对应接口的稳定动作键与参数，例如指定槽编号 | 更新当前命中范围，重新校验业务状态，不按按钮文字或图注编号派发 |
| 两个出示槽 | 固定slot_index及各自MaterialRef | 显示位置可以改变，材料引用和槽编号不变，不按屏幕顺序重新分配 |
| 焦点与列表 | focus_ref记录对象引用和控件语义，列表使用anchor_id | 按新布局找到同一对象，重新计算可见位置，不把旧屏幕坐标当焦点 |
| 正文阅读 | 精确文本引用与稳定文字位置，像素偏移仅作布局内辅助 | 字号或换行改变后回到同一文字位置，不能仅复制旧body_offset；具体文字锚点与存档消费统一接入 |

布局刷新只更新显示排布、文字排版、素材适配与命中范围。它不重新打开一个问题，不执行关系判定或结果组，不改变TargetRef、所选材料版本、来源快照、业务mode及call_id，也不清除当前问题的草稿或重新播放已经处理的关键演出。保存资格继续根据实际业务页面和处理锁判断，不因为换皮或重建控件树而改变。

材料文字和观察图片如果承载证明信息，就必须跟对应内容版本一致。没有改变信息的素材替换可以作为美术调整；证明信息改变时，使用新的内容记录，不能用换图覆盖旧版本。图注与界面保持同一语义区域，布局变更后同步受影响标注；本次不提供图源。内边距、滚动条、字号和行高变化后，重新计算显示容量，完整正文数据继续保留。

现有接口分别定义材料身份、版本、来源与确认成果记录，通用显示读取这些记录。出示接口接收MaterialRef集合，证明关系的a/b字段与两个出示槽是双卡核对的局部约束。排序复用材料引用并改变显示顺序；新的观察操作可以沿材料更新及结果提交入口接入，手册和导航读取已生效记录。该操作的输入、临时交互与信息变化仍需具体设计并由程序实现，不能在手册只读层暗中发卡；这些接口约定不代表游戏架构已落地。

### 配套表头与程序映射

配套表与七册使用四行表头：第1行中文字段名称、第2行稳定机器键、第3行数据类型、第4行客户端分组c，第5行开始数据。每个字段独立一列，不能把多个机器字段名放在同一个表头格。前三行表达字段语义，第4行用于导入分组；中文名称可优化，实际机器键、枚举与外部引用由程序确认映射。

| 维护位置 | 策划填写与阅读 | 程序消费约定 |
| --- | --- | --- |
| 数据表头 | 中文名称、机器键、类型和c分组分别显示，每个字段独立一列 | 明确第2行机器键、第3行类型和第5行数据；调整时同步导入器与引用检查 |
| 字段字典 | 每行解释一个字段的类型、必填条件、默认值、范围、单位、引用及刷新时点 | 使用同一个机器键校验，默认值与示例值分别维护 |
| 多条来源、条件或结果动作 | 按程序确认的结构分别维护记录，不将编号名单压入未声明格式的单元格 | 按稳定引用和明确顺序解析；已经定义成员结构的JSON数组仍按原结构消费 |
| 布局与资源参数 | 区域位置、大小、字号和资源适配分别维护 | 制作逻辑像素与展示像素明确换算，游戏程序按最终布局消费，不读取图注编号作为身份 |

下面是接口字段的推荐说明，表结构、机器键及映射由程序确认，旧工作簿仅作参考。必需引用不能填示例默认ID，空值语义需明确区分。普通材料每次真实取得按约定顺序冻结，新路径依第3节追加，旧条目不因改表重排。推论及确认成果保留形成时的used_sources，不追加后来路径。

| 中文名称与机器键 | 类型及引用范围 | 填写要求、默认与校验 |
| --- | --- | --- |
| 记录编号 id | string，当前表的稳定主键 | 有效记录必填，没有默认编号，不使用标题代替；示例编号不成为正式默认值 |
| 核对目标类型 target_kind | enum，问题入口 | 省略时使用statement；允许statement或reasoning，缺省行为不改变进入条件 |
| 人物说法引用 statement | string，精确说法记录id | 人物说法关联必填；推理问题关联保持为空，不补用当前最新版 |
| 推理问题引用 question | string，问题对象id | 推理问题关联必填，并与玩家打开的问题一致；没有默认问题 |
| 表现形状 effect_kind | enum，既有主题定义 | 必须解析为合法主题，推理问题不能碎裂断言；接入字段与存储值由程序映射 |
| 表现等级 effect_level | enum，表现元数据 | 省略时使用normal；允许normal、progress或key，不进入关系成立条件 |
| 关键转折标识 climax_key | string，关键认识转折 | key必须填写，normal与progress保持为空；等价解法共享，不同成果不能按动画合并 |

制作参数的单位与范围独立说明，不混入正式文案数据表。x和y定位所属视图中的区域；width和height必须大于0。font_size与line_height按真实字体排布检查，不能仅按字符数量推算。下文制作参数中的像素以1600×900制作逻辑计算，展示到1920×1080时乘1.2；实际播放时长和制作姿态时钟分别标明单位。带pose_ms的值只用于姿态取样，按照rhythm映射到实际播放时间；粒子姿态寿命不能成为发卡、解锁、保存或检视恢复的条件，程序读取真正的表现结束事件。

字段字典中的中文说明供维护者阅读，程序校验按同一schema中的机器键与明确约束实现，不执行自然语言说明。类型为枚举时，存储值与中文显示名称分别解释；默认值采用明确类型，不能把示例编号用作默认引用。

程序确认格式后，更改机器键、字段类型、引用目标或枚举值时同步实际数据、字典、导入与消费者。中文显示名修改不改变业务语义。接入验证需覆盖缺失引用、互斥目标、重复路径、逐层冻结，以及目标类型与生成卡牌的两种终态；推荐表头不证明程序已经支持。

## 11 核查完成、容错与重试

### 结果类别与判定顺序

沿第4节原有关系，补充明确错误类别incorrect。按双份充分、单份充分、局部成立／有效反证、明确错误关系、默认不足的顺序求得唯一结果。充分和有效局部结果优先；单份充分时，无关的另一张卡牌不计入来源，也不扣容错。无匹配继续按insufficient说明欠缺，不从卡牌类型、动画等级或出现反证自动推导incorrect。

incorrect表示作者已经明确声明：本次出示在当前已知条件下错置对象、时段或证明范围。所选材料仍可用于其他问题，真实材料和正确内容保持。错误关系必须同时满足合法目标、实际所选精确材料及已知条件，不能只配置一个error标记。未取得的新版本或尚未知晓的条件不参与这次判定；同优先级错误关系若给出不同原因和结果，在接入前修正。

| 最低配置语义 | 填写要求 |
| --- | --- |
| 错误关系身份 | 稳定且唯一的incorrect_relation_id；具体表名和ID格式由程序映射 |
| 合法目标 | target_kind、question_id及精确statement_ref或question_text_id，二选一；说法须已听到，问题须已开放 |
| 所选材料 | 一份或两份MaterialRef，各自明确material_id与content_id；不写版序代替内容身份 |
| 匹配范围 | exact_set要求所选身份集合正好一致，contains要求包含配置引用；两者均按精确版本核对，左右槽无关 |
| 已知条件 | known_condition_ref必填，引用实际已经满足的条件组；始终有效时显式引用作者配置的无附加条件组 |
| 原因与回应 | reason_text_ref及response_ref，说明错置范围并展示本次扣1、剩余次数；全文可读，不使用无依据的通用失败话术 |

配套表“错误出示”有可填模板与匿名test例：TEST_Q_STATEMENT绑定已听到的目标对象，TEST_CARD_OTHER_OBJECT_V1是实际取得的另一对象记录，TEST_COND_OBJECT_MISMATCH_KNOWN表示玩家已知两者不同。没有前面的充分或局部关系命中时，只选择该材料时以exact_set命中错误关系，回应指出对象对应错误。切回未绑定错误关系的其他材料，默认不足且不扣。主笔用试跑的真实引用替换这些占位；示例不给正式剧情补造材料或正文。

错误结果只改变当前问题的容错，显示原因与实际出示依据；不生成推论、不更正目标、不确认成果、不解锁内容。人物回应正常加入实际已听记录，记录展示仍由手册消费。归零判断发生在这次扣除提交后；表现结束开放相应稳定页面，不由粒子或定时器扣次。

### 次数、退出与重试

每个问题在案件进度中分别记录初始上限3和剩余次数。首次合法进入未完成问题时创建记录；同问重入、收起对局、切换其他问题、检视、换版、更新合法目标及暂停都保持。只有命中incorrect的新主动出示扣1，最低0；充分、支持、限定、排除、关联、局部、有效反证、不足和重复均不扣。

每次有效新出示使用程序可识别的 present_attempt_id，格式由程序确定；未完成输入和不可出示不建立有效尝试。命中明确错误后，在同一次内存提交中扣1并记录本次已扣，随后显示回应，不执行成功结果组。同次连点、回调和恢复重复消费只能扣一次；玩家读完回应再主动提交属于另一次出示，可以再次扣。容错扣除使用独立提交记录，不能借climax_key或结果组执行标记代替。字段格式由程序确定，最低需能识别当前案件、问题、尝试和该次提交。

剩余大于0时显示完整错误原因，可重新选材或稍后核对，保留草稿。剩余为0且问题尚未完成时进入failure，card_ui_page=closed，出示、收下与成功继续不可用；检视、依据回看、暂停和返回原调用处可用。共用菜单可返回标题或退出，保存灰显，直接离开与取消可用；成功离开终止旧会话，不补自动档。失败状态由0次及未完成结果推导，不新增另一份完成记录。

返回原调查或会话后仍保留0次，重新打开同问仍显示失败页。点击【重试】才恢复当前问题3次，开启新的尝试身份，清该问题草稿与局部临时结果，按当前合法入口初始化：statement目标未选，reasoning问题自动选定，两个出示槽均无材料。按钮文字复用UI_COMMON_RETRY，动作保持retry_question；五卡底栏按首次选材初值显示，手册视图保持。

重试不回滚持有材料、已取得版本、同版来源、已读／重点、其他问题容错、已确认成果、冻结证明、已经执行的结果组和handled_climax_keys。已经完成的成果回看原记录，不通过重试重新发卡。读取旧档后，全部记录以该档进度为准，不维护跨档容错或永久观看历史。

### 完成与保存

本次核查成功以充分成果实际提交为准。无新推论时，按原进入回应或继续时点确认；需要新推论时，收下才整体提交。动画停止、关键未触发、局部成立、待收、明确错误和失败均不完成核查。继续或下一问结束本次结果，随后按原规则返回；阶段开放、案件胜利与正式指认失败由对应案件／指认功能判断，核心只提供确认成果与实际依据。

容错只存运行内存，随原合法调查档联合保存。稳定选材、允许的调查页或问题列表按《存读档系统策划案》2.1开放手动保存，保存不执行出示；档案导出／恢复各问题剩余次数、尝试和扣次去重记录，无新档位或时点。0次返回允许调查页后可手动保存，重入恢复失败。

失败及其原因、依据和手册阅读按禁存调查来源打开暂停。失败主屏继续回原失败页，阅读层按手册恢复原对象、层级与位置，关闭后回失败页；读取只有直接读取／取消，取消保留原状态，成功读取才替换会话。保存与先保存后读取禁用，禁存提示绑定UI_SAVE_DISABLED_CORE_FAILURE，正文读取初始化唯一文字源。玩家返回可操作且允许保存的调查画面后，即使本题剩余0次，也可按原条件保存。上层菜单不提高资格，返回标题／退出沿共用直接离开和取消规则。

错误、失败返回及重试本身不触发普通自动档，不新增问题开始保护档，不补写旧快照。重试850ms显示结束到稳定选材后，才按原资格开放手动保存。完成成果仍在完整提交、表现结束并正常返回原允许页面后按既有条件更新自动档。仅当核心与存读模块共同确认档案属于加入容错规则前、容器与内容版本仍受支持的旧记录时，未完成问题采用3次初值，已完成成果／结果／高潮标识保持，不补造旧尝试或扣次历史。新版必需记录缺失或快照不完整时，在替换会话前拒绝读取并保留当前会话；完整边界见《存读档系统说明》第5节。

### 频率与共用消费

effect_level缺省normal；progress须首次充分的新确认，key还须完整关键准入和未处理climax_key。同一转折当前进度一次，同一出示一个主高潮，无随机触发、时间冷却或连续累计门槛；2—3次递进后安排一个高潮是关卡节奏参考，不作为程序判定。关键资格不足降为同语义普通反馈，合法结果继续执行。失败和重试不清高潮记录。

功能文字读取初始化唯一文字源 basic.TbFunctionText，具体绑定见本说明附录A。内部容错记录以页边复核记号及辅助数字显示，错误划去一枚，重试另起草稿；不新增材料实体、人物属性或剧情道具。retry_text_ref保持UI_COMMON_RETRY，动作保持retry_question；原计数、结果与保存规则保持，原因正文、回应和推论内容由相应内容配置提供。

声音使用《声音播放系统策划案》第3、4、6节的事件／通道、暂停和恢复规则，只补动作切点及声音特征；目标导航读取真实完成状态，不根据动画和容错变化判为完成。手册读取同一材料与证明，失败不会新建库存或隐藏已取得材料。

配置数据页的#备注供策划阅读，不参与导出；data_scope继续决定runtime／test。测试行备注注明匿名用途。当前TEST_*例与主笔TEST_BLUEBOX的内容和活动关系分别使用；蓝盒试跑读取核心已定runtime规则与主笔有效内容，不能把两套测试关系一起加载。

### 错误出示怎样填写

一行声明一个具体错误范围。启用时问题、目标、材料一身份及精确内容版、匹配范围、真实已知条件、原因文字与回应必须完整合法。材料二可空；填写时身份与内容版成对，两个身份不同。

statement填写claim_ref和statement_ref，question_text_ref留空。reasoning填写准确question_text_ref，说法两个引用留空。问题必须已经开放，人物说法还需已听到准确版本。

exact_set要求所选集合恰好等于本行的一份或两份材料；contains要求包含本行全部材料，允许附带其他材料。左右位置与放入顺序不参与匹配，不借用当前最高版。known_condition_ref引用程序内容方案的条件组，真实满足后才允许命中。

真实材料在另一问题可以成立，在当前问题可能错置对象、时段或证明范围。本表不提供假牌。原因和回应由作者绑定，不依据动画、有效反证字样或未命中推断扣罚。同一目标、材料范围及条件不能同时指向不同错误回应，接入前必须消除冲突。

### 黄纸结果与演出表现

三类表现复用components.notebook_page及notebookWordmark。击破在深墨背景中放大指定断言摘录，裂面停顿后逐层崩解，露出当前人物反应与字标；碎片整体裁切、前后翻转，材料卡保持。涌现沿当前地点的模糊背景，由实际来源汇成纸脊，书页持续向上喷出，最后一页贴近画面中央、向右微上滑动落定。纸页与新卡保持竖向2:3，未确认图文用灰条和素材位；演出不改变地点或交谈对象。

核心演出为击破5600、涌现6800、递进3200毫秒。击破650—1050ms开裂，1050—1450ms停400ms，1520ms主崩裂、余片散至3000ms；字峰1.26倍停80ms，3700—4900ms完整宣告，5600ms回回应。涌现900—3900ms连续飞页，1900ms字标出现，2050ms放大、2150ms收束；末页4180ms接触停110ms，4290—4860ms滑动落定，5140—6100ms阅读，6800ms回完整结果。递进依据收紧停140ms，圈注压实停160ms，字与纸回弹后显示完整内容；标题1行、正文5行，超出独立滚动。时点均为可调整初值，单份充分只展示该份实际来源。

三段字标随对应物件受力缩放，停顿保留声音的自然尾音。击破650ms轻裂，1520ms连续明亮玻璃崩裂约700ms，碎尾逐渐稀疏并延续到3000ms，字标配短低音。涌现字标收束后飞页继续，2760ms配近景纸页轻缩放一次；末页接触只暂停末页，背景飞页最晚5300ms退尽。裂解仅作用于被排除摘录，原文、版本、来源和业务时点保持。
