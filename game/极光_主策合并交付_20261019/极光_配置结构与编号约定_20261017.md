# 极光｜配置结构与编号约定

版本：2026-10-18（沿用原文件入口更新）。交付对象：主程序及各系统策划。适用范围：本轮十一套策划案、配套配置表及剧情资源。

本文件统一读表格式、编号和数据归属。玩法、交互、显示、存档等具体规则分别写在所属策划案，表头只解释字段用途与填写方法。主程序按本地交付包接入；本轮不直接修改或上传游戏仓库。

## 1. 本轮采用的表格格式

所有运行数据页采用同一套四行表头，第5行起为数据。说明页、候选样例页采用`##`开头的页名，整页不导入。

| 行 | A列 | 业务列 |
|---|---|---|
| 1 | `##comment` | 中文名称，并在同一格换行填写必填/可空、单位、枚举、引用来源等必要约束 |
| 2 | `##var` | 稳定机器字段名；沿用已有效的英文键，新字段采用小写下划线 |
| 3 | `##type` | 基础类型：`string`、`int`、`float`、`bool`；已有列表字段见下文 |
| 4 | `##group` | 需要导入的业务列填`c`；不导入列留空 |
| 5起 | 通常留空 | 一行一条记录，复合记录的唯一键在表头写清 |

- A列以`#`开头的行不导入；完全空行不导入。
- 第二行字段名以`#`开头的列只供维护，不导入。第四行同时留空，避免两处标记冲突。
- 已有`data_scope`字段的表只导入`runtime`，已有`enabled`字段的表只导入`true`。不为没有阶段隔离需求的每一张表追加这两列。
- 测试记录同时采用测试标记和既有测试用途字段；正式行不得引用测试或禁用内容。缺失的必需资源不能通过测试路径冒充已完成。
- 第三行不夹带`!`、`#range`或中文单位。原有约束搬到第一行及所属策划案的字段说明，导入校验同步保留。声音导入器原先支持扩展类型；本轮统一后需要跟随新的类型约定读取。
- 同一列保留真实数字/布尔类型；ID一律为文本。禁止把`0`、`FALSE`当成空值。
- ID列表统一用英文分号`;`分隔，例如`SC02;SC06`。单元格类型使用`string`，由该字段的列表语义解析；已有故事表的`list`类型可在转换层转为相同字符串列表。空列表留空，不写“无”。正文中的标点不参与拆分。
- 现有组件参数中的`int[]`继续表达固定长度的数值数组，例如`[1600,900]`。这是数值参数的值类型，不与ID列表混用；允许保留该已使用的类型。
- 事件结果当前包含少量对象状态JSON，例如`{"scene_id":"SC04","view_id":"SC04_MAIN"}`。本轮只允许所属案列明的键；所有内部引用也参加迁移与校验。不得在JSON里塞规则、脚本或自由解释文字。
- 数据区不使用Excel公式、合并单元格或说明行；中文表头自动换行，冻结前四行和关键标识列。筛选从数据表头到末条数据，不把类型、分组行混入数据筛选。

所有数据页均须给出唯一键。例如条件表为`condition_id + branch + order`，事件结果为`event_id + order`，观察反馈为`object_id + observation_id`。多行共同表达一个条件或事件时，同一组ID重复合法。

## 2. 身份、编号与枚举

### 2.1 编号原则

业务身份采用区分大小写的字符串，同一类使用同一格式。新人物、地点、入口、对象等业务ID使用大写英文字母、数字和下划线。资源ID按共用素材清单的已采用编码精确引用，例如PAPER_V2控件前缀及固定控件名，不由消费者另改大小写。显示名称、台词内容、排列顺序变化不重编身份；删除的编号不重新分配给另一件内容。

| 对象 | 格式及实例 | 说明 |
|---|---|---|
| 人物 | `CHR01`—`CHR11` | 取代纯数字人物编号；各案共用同一人物身份 |
| 章节 | `CH01`—`CH06` | 保留现有编号 |
| 实体地点 | `SC01`—`SC11` | 物理地点；SC11为货运卡车，SC10仍为空值班室，SC01仍为站外 |
| 剧情片段 | `SEQ_CH01_ARRIVAL` | 一段可调用的连续内容；不再复用“场景ID”名称 |
| 交互入口 | `ENTRY_CH01_ARRIVAL` | 新增入口沿ENTRY前缀；现有TALK/ACTION/INV入口继续保留稳定身份，入口用途另列枚举 |
| 剧情文字 | `TXT_CH01_0001`、`TXT_OBS_SC01_FIRST` | 保留现有稳定TXT编号；新增文字续号，不按Excel行号编号 |
| 调查对象 | `OBJ_SC09_FLASK` | 独立于材料卡；未生成卡牌的物件和整个场景也有对象身份 |
| 热点 | `HS_SC09_FLASK` | 一处可点区域，引用调查对象；迁移地点不改变物品身份 |
| 观察反馈 | `OBS_SC09_FLASK` | 场景反馈的稳定引用；存在差分时由条件选用具体反馈 |
| 场景视图 | `VIEW_SC09_MAIN`、`VIEW_SC11_CABIN` | 具体镜头或局部；固定镜头与连续宽景通过调查案的camera_mode及视窗参数区分 |
| 话题 | `TOPIC_CH01_IVAN_TRANSFER` | 人物话题行，引用ENTRY入口 |
| 证物、证言、推论 | `E01`、`T01`、`P01` | 保留现有身份，分别沿所属材料类型 |
| 材料内容 | `E01_V1` | 身份及内容版本分别引用；`version`列仍为整数 |
| 人物资料版本 | `PROFILE_CHR01_V1` | 人物页公开资料，独立于可出示材料 |
| 关卡与问题 | `L01`、`L01_R01` | 保留现有组和问题编号；普通对白不硬套问题ID |
| 击破、关联 | `B01`、`I01` | 保留已配置的转折编号 |
| 条件 | `COND_CH01_ACTIVE` | 跨系统引用同一条件定义 |
| 结果事件 | `EV_CASE_INVESTIGATION_OPEN` | 跨系统引用同一结果定义；重播正文不重复提交 |
| 结果、目标、导航依据 | `RESULT_L01_R01`、`GOAL_CH01`、`NAV_BASIS_E01_V1` | 沿现有统一前缀，保持稳定 |
| 资源 | `BGM_STATION_LOOP`、`BG_SC01_MAIN`等 | 保留已存在的分类前缀；文件路径与逻辑ID分开 |

同类统一即可，各类编号无需等长。既有程序参数键和约定常量（如`default`、`logical_width`、`panel_opacity`）维持当前取值，不按人物或物件编号迁移。

页签、显示模式与排序继续使用所属表声明的整数枚举，不按业务ID改成字符串。当前办案手册为证物、人物两类入口，独立对白记录从右下另一入口打开；旧材料/原话记录/人物三页签不再作为当前界面依据。手册总控记录的`10001`是旧单例配置身份，迁移为`HANDBOOK_DEFAULT`；如程序仍硬编码旧值，接入时同步修改。

### 2.3 唯一迁移文件

[极光_ID迁移映射_20261017.json](./极光_ID迁移映射_20261017.json)沿原入口维护10月16日起的实际变更，并补入18日货车地点和调查身份修正。每条含`kind`、`old_id`、`new_id`、`name`及适用上下文；当前new_id直接指向采用身份。既有TXT、ENTRY/TALK/ACTION/INV、条件、事件、关卡、材料及目标等稳定编号继续使用，不重复填写同值映射。

迁移按“字段含义 + kind + old_id”执行。旧数据里`SC01_BUS`同时用作对象、观察和视图，三者分别迁移，禁止全文直接替换。新稿拆分或合并片段时先迁移既有身份，再为新增内容分配新号；被合并/废弃的旧入口不得继续留作悬空引用。

迁移覆盖：本表主键、其他表外键、ID列表、事件状态JSON内的引用及初始状态。正文中的年份、数量、行号、路径文件夹、资源文件名不参加身份替换。资源路径可以保留数字文件夹，无需只为编号形式批量改名。

大规模剧情与编号变更使用新的`content_revision`。旧演示存档保留原文件，通过原内容版本校验拒绝混读；本轮不要求兼容旧演示进度。

## 3. 数据由谁维护

| 所属配置表 | 唯一维护内容 | 其他系统读取方式 |
|---|---|---|
| 文案 | 人物身份、章节、片段、逐句文字、入口与跳转、案件条件、结果事件、调查文字 | 引用文字/入口/条件/事件ID，不复制正文或条件规则 |
| 办案手册 | 材料身份、精确内容版本、人物公开资料版本 | 关卡读取材料版本；文案事件授予/公开；人物页不自动变成出示牌 |
| 核心玩法 | 问题、关卡轮次、出示关系、判定结果与接续 | 调用文案入口和事件；不重复维护对白正文 |
| 调查与场景交互 | 调查对象、热点、视图、对象显示、话题列表及当前人物入口 | 从文案取得反馈，从公共状态读人物位置和对象状态 |
| 地图切换 | 实体地点、地图分组、地点节点与地图资源 | 读案件状态判断可达；跳转后进入已确定的地点视图 |
| 目标导航 | 目标、事项、显示顺序、准确依据和前往入口 | 读文案条件与真实结果，不自建第二套剧情进度 |
| 初始化与开始 | 共用功能文字、基础文字样式、输入矩阵、右下HUD入口、初始入口及基础菜单配置 | 各系统引用同一文字、样式、键位和HUD布局；剧情正文留在文案 |
| 存读档 | 存档容量、格式和读写时点的规则 | 保存统一运行状态，不在各表另配可冲突的存档进度 |
| 游戏设置 | 音量、字速与显示选项初值及偏好 | 各系统读统一设置；字速倍率作用于文案标准速度 |
| 声音播放 | 声音资源、播放事件与场景音景 | 文案/地图按场景和阶段请求播放，不写入另一份音量规则 |
| 撸猫 | 猫对象与实际回应动画的绑定、时长、声音 | 调查入口调用该互动；重复可共用同一动画 |

规则先在所属案确定，再修改对应字段和数据。共用约定不代替上述各案的业务说明。

## 4. 文案表的机器字段对应

现有中文名称保留在第一行。下表保留主要机器字段的职责对应；完整字段和列顺序以本包实际XLSX第二行为准，程序按字段名读取。新增font_color等字段不能因旧列号约定被遗漏。

| 数据页 | 主要机器字段 |
|---|---|
| 脚本文本 | `character_id, portrait_path, position, avatar_ref, speaker_name, text_id, text, text_kind, font_color, read_version, chapter_name, sequence_id, sequence_name, #scene_description, #reference_image, background_path, chapter_id, next_text_id` |
| 人物字典 | `character_id, name, default_portrait_path` |
| 章节字典 | `chapter_id, name, default_bgm_id` |
| 剧情片段字典（原剧情场景字典） | `sequence_id, name, chapter_id, entry_id, entry_kind, first_text_id, condition_id, call_kind, call_ref, completion_event_id, location_mode, clear_positions, bgm_mode, bgm_id, allowed_scene_ids` |
| 片段地点关联（原场景地点关联） | `sequence_id, scene_id, view_id, background_path, #reference_image` |
| 文本跳转 | `source_text_id, source_entry_id, trigger, operation_id, condition_id, target_kind, target_ref, event_id, timing, option_text, observation_id, location_mode, scene_id` |
| 案件条件 | `condition_id, branch, order, kind, ref, scene_id, expected` |
| 事件结果 | `event_id, #name, condition_id, order, kind, ref, value, material_id, content_id, action_condition_id` |
| 调查文字关联 | `entry_id, object_id, scene_id, observation_id, condition_id, is_default, first_text_id, repeat_text_id, completion_event_id, interaction_mode, same_object_id, location_mode, allowed_scene_ids` |

本行中的逗号只用于文档展示字段清单，Excel中每个字段独占一列。

`position`使用`left/center/right`，供人工阅读的第一行说明“左/中/右”。无人物的字幕、心声不填人物站位；心声发言身份仍可为艾琳。`text_kind`及其他枚举按文案案中列明的对应表转为程序值，不猜测自由文字。

font_color采用当前纸面主题：普通正文#34413F、时间地点#3F6B4C。读取显式行值，未指定时使用共用样式默认；旧白字默认退出。逐字速度、停顿和打字音按文案公参及声音资源配置，快显、跳过、重绘不补播积累的字符音。

单一顺序播放沿`next_text_id`；同一句的条件分支/选项由文本跳转维护。同一句同时配置两种互相冲突的后继应报配置错误。目标引用依`target_kind`解释，不能把入口、问题、文字混成同一主键空间。

## 5. 版本与结果接续的接入要求

- 材料身份及内容版本分别引用。手册正文只维护一次；出示关系绑定玩家实际持有的准确`content_id`。更新同一件证物时沿原身份增加内容版本，触发既定更新反馈。
- 包裹的所有权、翻阅情况等并行知识按照各案的条件组合选用已写好的内容，不能仅按“最后一个事件”的版号覆盖，导致已知事实消失。
- `read_version`表示本句内容修订版本；重新排版、换行、移动Excel行不自动改变已读语义。
- 条件组内全部满足、组间任一满足，沿已有且/或结构；`chapter/event/content/text/entry/npc_scene/current_scene`引用各自类型。章节归属不自动成为入口硬锁。
- 入口打开、文字显示、读完、选中选项、回应结束、主动收下为不同提交时点。文案和核心统一引用一个事件ID，并声明唯一提交方。打开入口不能提前取得尚未读到的证物或证言。
- 保存当前入口/文字/问题、返回位置、已读版本、已提交事件、材料精确版本、人物与对象状态。实际字段和写入时点由存读档案与文案案对应，避免只保存章节造成读档重发卡或错位。

以上是跨表必须表达的关系；详细业务时点由对应案规定，配置填写该案已定义的值。

## 6. 立绘、场景视图与背景人物

1600×900仅为默认显示。用户的1920×1080参考中发顶距顶约300像素，对应900高有效区约250；膝盖上方约一拳处贴有效显示区底边，完整PNG保留。UI、前景和场景采用各自明确的适配方式，不把所有对象锁在固定16:9画布内。

需要由文案所属配置提供：三个站位的横向锚点、人物可见发顶与裁切线在原图中的位置、最终缩放及底边对齐。已有透明留白不得算成人体高度。站位布局作为共用展示参数，人物图自身的边界作为每张素材的校准数据；逐句文字只引用人物/素材和站位，不逐句复制一套坐标。

最终字段名和值由文案案与配表同时落定。前景姿态朝右放屏幕左侧，朝左放右侧；中央交谈优先正面或近正面。按具体图片记录朝向，同一角色的不同姿态不固定在同一边；连续会话换表情保持合理站位，不默认镜像不对称衣着、伤痕和持物。手册人物页、头像与证物插图沿各自用途显示。

场景姿态与交谈立绘分别绑定。人物在场景里低头收衣、背向端盘、坐着整理物件，不决定进入对话后的立绘。开始交谈时调取该人物正面或近正面的常态对话立绘，再按台词段切换已交付的表情差分；退出后恢复当前场景状态。未配置表情变化的句子沿当前交谈状态，不继承前一个场景的背影或忙碌姿态。新的交谈从明确的默认对话立绘开始。

同一场交谈可有多次表情变化，依实际台词绑定；图片与人物、姿态、朝向一致。本轮不制作连贯人物动画，真实缺失姿态按授权补齐并接入，不使用占位路径冒充已交。猫回应动画沿撸猫系统的本轮要求。

脚本明确为画外声音或仅使用旧年场景的段落，按原演出保持无立绘；五岁洛恩的回忆不能自动补成年洛恩常态图。普通交谈缺少合用图时补齐对应资源和绑定，不借无立绘规则掩盖。

嵌入背景的可交谈人物使用原位置透明热区，并交付同机位有人/去除交谈对象的配对背景。有对话时，同一演出步骤切去除该对象的背景并调出中央正面近景；结束清除近景，按实际剧情在场状态恢复。多名背景人物只去除当前进入前景者，其他在场者保留。无话题不切图、不出立绘，只给就地反馈；尼娜沿“还是别打扰她了。”。主视图和可点击的局部视图分别绑定各自背景与热区。

热点所在视图与人物实际位置分别记录。例如大厅从厨房门口看见尼娜，热点显示在SC02，人物仍可位于SC03；会话展示不修改真实位置。只有入口明确允许从当前地点交谈时才调用，厨房物件调查沿对应视图。独立前景人物、纯剧情CG、回忆与遗体按各自用途处理，不自动套背景活人交谈流程。

临时会话背景状态与真实在场状态分别维护。暂停或打开手册时保留当前会话背景，人物因剧情离开后不强行恢复旧人影。取得遗体记录不移除现场遗体，只有明确物理取走/移动事件才改变实体。
