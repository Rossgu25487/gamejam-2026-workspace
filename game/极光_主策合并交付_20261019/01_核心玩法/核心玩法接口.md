# 核心玩法接口

2026年10月18日。维护方：副策划2。配套玩法策划案.xlsx是核心规则与正式关卡配置的编辑依据，沿原规则与关卡结构增加“核心界面资源”“核心界面布局”和“核心动作音效”页。正文、公共条件与事件沿文案唯一数据源，材料身份和内容版沿办案手册；核心只维护调用、问题、关系及结果引用，不复制字库、事件动作或材料库存。本文定义字段语义与消费者，游戏接入和实测分别验收。

## 1 固定规则

证据、证言和推论共用当前案件的一份持有集合，同一material_id只对应一个实体，实际取得的content_id分别保留。核心浅扇手牌、双槽、手册证物页与结果阅读都引用这一状态，不另建手牌库存。材料不消耗；取得记录和内容更新不隐藏世界实体，实物移动、收物和NPC离场由对应剧情事件独立处理。

两个出示槽各有固定编号，最多放入两份不同身份的材料。一份已经充分即可成立，无关第二份不加入实际来源；左右顺序不影响集合匹配。同一材料的两个版本不能同时入槽，查看、选中、翻页、切版与取消均不提交判定。

稳定核查下方为浅扇手牌，5张及以下松扇展开，6—10张压缩重叠，默认同屏上限10，4:3上限7；超出后分页浏览全部已获材料，库存无此上限，不抽牌或筛答案。每张保留可点击区域，方向键可达全部条目。点击牌默认找首个空槽，玩家也可先点槽位指定，放入后下一张自动找另一空槽。两槽已满时提示先撤下或明确指定替换位置，不自动替换；复核后只改该槽，200ms入槽不判定，无须拖拽或额外确认。空槽点击不打开手册。

顶部为准确目标原话，中央两张2:3出示卡为主焦点，下方浅扇手牌；有人物上下文时保持当前核对对象，姓名在左下。目标原话不进入牌库。卡片详情与已持有旧版就地阅读，关闭回原手牌位置；核心打开手册始终为全量只读，不发起select_material情境调用，不显示手册选入按钮。其他系统的手册情境合同保持。

statement使用已经完整听过的准确原话，首次由玩家选择目标；reasoning使用合法入口提供的问题，进入时已经选定。不同问题初始化空槽，同一问题恢复原草稿、TargetRef与精确内容引用；材料主列表正在查看哪一版不改变草稿。

结果成立范围与effect_kind、effect_level分别配置，表现强度不参与匹配或提交时点。最多两个槽、单份充分、结果单次、首次高潮去重与每题3次容错保持，不增加点数、概率、限时按键或自由合成。正式问题沿当前六稿18项核查，不因UI入口变化另造问题。

普通材料按合法事件立即取得；推论先保存待收及实际来源，玩家主动收下时只提交该成果的知识事件，包括拥有、确认、更正与知识条件解锁。不借此移动现场实体、变更人物地点或重复执行现场收物动作。界面关闭不丢弃已经提交的知识，阅读、暂停和动效不补交结果。

## 2 配置对象与目标引用

正式工作簿以三张运行页连接入口、精确目标、材料关系和结果。完整字段类型、空值与消费者见第10节；程序按第2行机器键读取，不用标题或工作簿行号猜选对象。

| 配置对象 | 正式引用 | 使用要求 |
| --- | --- | --- |
| 核心轮次与问题 | 关卡轮次.id、question_ref、interaction_kind | 轮次采用Lxx_Rxx；普通对白question_ref为空，同题多入口共用question_ref |
| 原调用与入口 | call_ref、entry_ref、condition_ref、return_ref | 上游调用只作映射；入口与条件须真实存在，caller沿原上下文返回 |
| 精确目标 | target_text_ref、target_read_version | 直接引用文案text_id及其read_version，不补用最高版 |
| 证明材料 | a_material_ref、a_content_ref、b_material_ref、b_content_ref | 身份与内容版成对，最多两份；单份充分只冻结该份实际依据 |
| 出示关系 | match_scope、condition_ref、response_entry_ref、result_ref、priority | 先按充分档位，再取较小priority的唯一关系，不能混入其他解法来源 |
| 结果接续 | event_ref、event_owner、timing、inference_content_ref、return_ref | 引用公共事件，提交方只执行一次；有新推论时等待主动收下 |
| 来源与前次确认 | MaterialRef、used_sources、basis_relation | 使用实际取得记录与形成时冻结快照，不另存材料正文 |

MaterialRef继续为{material_id,content_id}。TargetRef继续区分statement与reasoning，其精确目标由target_text_ref与target_read_version提供，question_ref映射为既有question_id。旧StatementRef、claim、statement及question_text_id只作适配语义；接入时从同一精确文本解析，不要求作者新造说法ID或复制正文。已经保存的目标引用保持可解析，不能因换表改指另一句。

statement目标必须属于当前问题且其准确阅读版本已经完整听到。reasoning目标必须来自玩家进入的已开放推理问题。目标文字本身不作为证明材料；推理目标没有人物断言，statement_quote及旧目标说法更正字段留空，不对问题文字使用断言碎裂。

数字version只供内部版序及引用解析，玩家卡面用【已更新】等状态标记，不显示“内容2”或内部版本号。previous不授予尚未取得的版本。直接取得新版时只持有该版；后来真实取得旧版可增加记录，当前内容仍指向已取得的最高版本。选择旧版只读取对应正文和观察，不能借用新版信息。更换版本前先撤下原槽，再通过正文及取得记录核对实际持有内容并选入。

目标的说法版本、类型或问题文本引用发生变化后，更新目标显示并使旧的局部补充失效。出示槽中的材料继续保留选用时的版本；已经确认的结果保留确认时的TargetRef及实际依据，不随新目标改写。

回看旧话读取该记录当时的精确说法版本，不替换当前问题的合法目标，也不把更正前的原句设回当前说法。恢复草稿时使用原精确引用；当前问题目标已经变化时按原目标更新规则处理，不能从手册正在阅读的条目猜选目标。

## 3 运行记录与实际来源

| 记录 | 接入字段建议 | 更新要求 |
| --- | --- | --- |
| 材料实体 | material_id、type、acquire_index、current_content_id、acquired_content_ids、viewed_content_ids、important | 首次取得、内容更新和实际阅读更新；核心展开层复用important切换身份重点，同一身份各版本共用 |
| 内容来源 | sources_by_content[content_id]：entry_id、object_id、relation_id、source_ids、MaterialRef[]、StatementRef[]、confirmed_result_refs[] | 普通材料每次真实取得时冻结该路径条目，另一真实路径追加、同一路径重复不追加；推论来源在形成时冻结，收下时整体提交 |
| 手册只读调用 | 原返回引用及手册临时浏览位置 | 手册管理页签、页码、选中项与正文；核心不传选入目标槽，不接收选入回交 |
| 当前问题草稿 | question_id、TargetRef、target_selected、slots[MaterialRef或null,MaterialRef或null] | 玩家选用、撤下、选择目标或离开当前界面时更新 |
| 场内窗口 | card_ui_page、last_selection_view、card_caller_ref | selection含双槽、浅扇手牌及本地展开视图，保留分类、搜索词、排序、重点开关、页码和焦点；pending/collected为结果，不复制库存 |
| 临时检视返回 | inspection_return_ref、opened | 保存原页面、mode、current_node_id、result_id、正文位置、来源层级和焦点；关闭检视后释放该返回引用 |
| 正文阅读锚点（接入建议） | body_anchor：text_id string、character_index int；body_offset为同布局辅助偏移 | 每个正文阅读上下文和来源层级分别保存实际文本引用与字符位置，不改变保存资格；旧档缺少锚点时继续使用已有恢复路径 |
| 当前结果 | mode、run_id、call_id、result_id、relation_id、current_node_id、target_ref、used_sources、option_refs、inference_content_id、collected | 出示或普通话题的显式核对成立时冻结实际来源；节点和操作状态继续更新，后来取得路径不补入本次used_sources |
| 已确认结果 | result_id、relation_id、target_ref、confirmed_scope、used_sources、confirmed、completion_index | 对应结果组完整提交后才设置confirmed=true；保留形成时的used_sources，completion_index在当前run中单调增加 |
| 表现快照 | TargetRef、statement_quote、effect_kind、effect_level、climax_key、selected_presentation、target_after_ref、first_resolution及实际来源 | 判定完成后冻结，不因检视、暂停或来源返回重新选择强度 |
| 业务执行记录 | resolved_result_keys、applied_group_ids、last_result_id | 继续使用既有结果去重；结果组按run_id、call_id、timing和group_id记录，不重复执行 |
| 关键表现记录 | handled_climax_keys | 进入关键表现时写入当前进度内存，随下一次合法调查档保存，不增加保存资格 |

body_anchor为{text_id,character_index}，属于我方运行上下文的接入建议，不是新的文案记录或正式存档schema。text_id引用当前正在阅读的完整正文文本；character_index从0开始，0表示正文开头，按该文本实际解析字符串的Unicode字符（码点）顺序计数，包括标点和换行，不按UTF-8字节或UTF-16代码单元计数。只能用这个位置恢复同一个精确文本引用，不能拿它定位另一篇正文。

重新排版时，程序先用body_anchor找到对应文字，再按当前字体和换行计算显示位置。body_offset只记录同一布局内的辅助像素偏移，不能直接转换成字符索引。来源回查的每一级正文分别保留body_anchor；source_offset仍按既有规则记录来源列表位置，不用正文字符位置替代。旧档没有body_anchor时，保留既有文本引用及body_offset、source_offset恢复路径，不填造精确字符位置，也不宣称跨布局精确迁移已经完成。字段接入与存档消费者统一验证，仍只在原来允许的保存边界写入。

浅扇手牌与本地展开层分别保留页码和焦点，展开层另保留分类、搜索词、排序及仅重点开关；关闭、详情返回或临时手册查阅后均恢复原状态和双槽。手册保留自身浏览上下文。草稿仍用question_id、TargetRef及slots，不从预览项重建；分类和重点不改变材料身份或证明资格。

所有实际取得版本都未读时，卡牌显示新标记。已经阅读过任一版本而当前版本未读时，显示更新标记。当前版本已经阅读后不显示这两个标记。打开已取得版本的材料全文或来源全文才记为已读；焦点预览、选用、重点标记、调查正文及尚未入库的推论预览都不替代这次阅读。阅读旧版不清除新版的更新标记。

手册仍不提供核心的分类、搜索、排序或重点操作；这些能力由核心本地展开层复用已有类型、acquire_index和important实现，不恢复旧手册导航。已读、内容版与来源保持，推论主动收下后才进入同一持有集合。

### 普通材料来源与成果快照

普通材料的同一content_id经另一条真实取得路径获得时，在sources_by_content的来源集合末尾追加该次实际来源条目，原条目及其精确引用保持不变。取得路径需要按来源身份及实际入口识别，本案以来源行身份、entry_id与relation_id说明其含义，具体字段由程序映射。同一路径重复取得不追加，新的call_id不使旧路径变成新路径。各次取得按约定顺序保存，不重排早先条目，也不混入没有经历的路径。追加来源不增加卡牌、内容版本或获得序号，不改写正文、当前最高内容版本、已读标记和两个出示槽中的引用。阅读、暂停及来源返回不构成取得；观察或正文信息发生变化时，仍按内容版本规则处理。

推论及已确认成果的used_sources固定为形成当时的快照，包括实际采用的来源条目、材料版本、说法版本和前次已确认结果。实际依据的每一级下属来源都随形成时快照固定；不能只保留MaterialRef，再在下一层读取后来扩大的普通材料来源集合。推论收下时提交已经冻结的快照；后来取得的材料路径不能补入旧推论或旧成果的证明。直接回查普通材料时使用该content_id已经实际取得的来源集合；推论或确认成果的每层沿自身used_sources展开。新版手册主导航不提供来源层，核心以专用阅读调用这些冻结记录。

record_content只表示说法所属的原文，不自动构成来源追溯边。材料来源、说法来源和已确认结果的引用不能形成循环。来源回查由核心已有专用阅读上下文承接，逐层保存精确引用、正文锚点及来源位置。来源成立、真实取得与成果快照由玩法和文案提供，阅读器不自行追加经历，也不重新加入手册页签。

跨次证明使用来源kind=已确认关联依据。basis_relation填写完整出示关联记录ID，与同一来源行的basis_content、basis_statement、basis_slot互斥。relation筛选本次来源分支，basis_relation定位前一次已经确认的结果。核心按当前run_id、指定关联及精确TargetRef筛选confirmed=true的记录，并选择completion_index最大的一条。

本次结果及来源快照中的confirmed_result_refs记录所选前次结果的result_id、relation_id、target_ref、completion_index、confirmed_scope和used_sources。后续回查沿这一冻结记录展开，不重新选择最新结果，不替换当时使用的材料版本。没有找到符合要求的已确认记录时，这项来源不成立。

已知条件决定问题入口或关系是否可用。作为证明依据时，还必须声明并取得实际来源，不能只用“已经知道”条件替代证明。前一次结论不占第三个出示槽，也不会自动变成可以选用的卡牌；需要选作材料时，必须正式配置推论并由玩家主动收下。不生成卡牌的确认范围，通过已核问题、材料来源及既有核心结果视图回看。

程序消费正式三页中的精确目标、关系和结果引用，并保留前次确认、真实来源、逐层冻结、表现选择及调用上下文。TargetRef和basis_relation继续沿本节语义适配；正式配置可直接维护，文件检查与游戏运行验收分别记录。

对白记录按实际顺序提供已经显示的原话、署名和精确引用；当前未播完的句子只记录已经显示的字符。未来句、未播放分支与选项不进入记录，不设置归纳区。追加新句时恢复未读，旧话保留当时版本。记录由文案提供，点击右下【对白记录】或按L打开，不占新版手册页签；查阅、暂停和重绘不补播或执行结果。关闭回原会话节点、结果与实际阅读位置。

出示时先检查目标合法、当前目标及确认范围尚未完成、该question_id剩余容错大于0，再按TargetRef筛选关系，依次检查双份充分、单份充分、局部成立／有效反证、明确错误和默认不足。同一问题已有其他成果不代表本范围完成。条件分支内部全部满足，不同分支任一即可；版本和观察只读取实际取得／选用内容。同档可同时命中的关系按priority取唯一最小值，只冻结该条实际采用的依据；并列最小仍有多条时报告歧义，不按行序任选。错误关系仍须消除互斥原因。错误关系的最低语义见第11节。

reasoning不要求目标有已经听到的人物原话，但必须具有明确问题说明、充分条件与确认范围。I进入的只读检视不会暗中启动推理，阅读正文、查看来源或点击手册图标也不会触发判定。关键原句必须是实际所用正文中的连续原文，配对关系不依赖卡面被省略的文字。

无卡结果按event_owner与timing，由唯一提交方在准确时点提交；不把所有更正统一放到进入回应或点击继续。新推论进入待收时只保存预览与冻结来源，主动收下才提交对应知识事件。event_ref为空不推定授卡或解锁；显示和回调不重复执行事件。

核心回应链切换节点时回传current_node_id，恢复显示该结果节点的完整文字。普通对白的分页、已显示字符和演出位置由文案系统恢复。结果组已经执行过就不再触发。推论节点的next在玩家收下前不推进，自动播放不能绕过收下。表现结束只改变显示，不自动确认尚未提交的结果。

连续核查由文案显式配置下一问选项。玩家点击【继续】或配置的下一问选项后，核心先调用continue_result，完成当前结果在该时点应执行的确认与结束步骤，清除该问题的目标选择、两个出示槽中的卡牌引用及临时补充状态，再依据更新后的真实条件处理后续入口。支持事实如果在点击继续时才确认，必须先执行这次确认，不能为了预先开放下一问题而提前写入事实。

普通继续仍返回原调用界面，不自动选择另一个问题；玩家选择配置中的合法下一问选项时，再调用open_card_session打开对应问题。statement类型仍由玩家选择具体说法，reasoning类型的当前推理问题已经被选为核对目标。两个出示槽里都还没有放入卡牌。后续入口没有满足真实条件时，不能进入该问题，也不能自动改选其他入口。

产生新推论的结果必须先由玩家收下卡牌，收卡动画结束前不能进入下一问题。已经收下的成果也必须按正常结束步骤收束，不能通过下一问选项跳过当前结果。下一个问题在当前地点内通过合法入口打开；需要跨地点时，仍使用原调查转场规则，不通过连续核查暗中移动场景。

### 场景与人物显示

以下场景与人物读取约定用于核心材料核查及其结果视图。current_scene_id由调查模块维护。人物说法核查根据问题对象的parent取得talk_character_id，目标说法的speaker必须属于同一交谈对象。核心结果节点的speaker只决定台词署名，text决定正文；有人物上下文时，其他角色插话仍保持当前固定核对对象，不凭署名切换左侧立绘。普通问话按新版文案系统的本句人物位置、头像和演出显示，不套用这项限制。

背景按current_scene_id读取当前地点资源。回看旧话只显示其原记录地点信息，不按旧话发生地点换背景；L06在公共休息室引用站长室旧判断时仍在休息室，实际复查转场后才更新地点。交谈开始时，根据talk_character_id读取合适的常态图：实际朝右素材放左、朝左素材放右，正面或近正面可居中，核心左侧核对人物用朝右或近正面图，洛恩近正面常态保持左侧。站位按可见朝向选择，文件名left/right不作为朝向，不水平翻转伤痕、服饰或持物；连续表情保持站位，朝向不合时改用合适资源。场景中的低头、背影或忙碌姿态不作为对话默认图。台词明确指定表情时切换对应资源，未指定时保持本次交谈已有表情。新的交谈重新读取默认对话图，退出后恢复当前场景状态；同次会话打开核查、检视及返回均保留当前对话状态。本轮人物使用静态图及已有表情差分，不配置连贯人物动画。默认1600×900下发顶约250、膝上切线贴底900；其他高度同比适配，切线贴有效区域底边，横向站位按可用宽度定位。不以透明留白计算身高，不缩成地面小人。缺图沿正式缺图处理，不填虚假路径。

reasoning可以不具有交谈对象。没有交谈对象时不建立talk_character_id，不加载人物立绘或身份行，显示问题说明和配置明确引用的相关已确认事项。存在合法会话上下文时可以保留该交谈对象，不能因为材料署名或台词发言者变更而切换。相关已知事项只提示范围，真正作为证明时仍须声明basis_relation。

### 结算去重与保存资格

每次文案调用记录run_id和call_id。收下、查看来源和暂停恢复沿同一次调用处理，不创建新的call_id。结果组的去重键为(run_id,call_id,timing,group_id)。合法的新调用可以复用结果组；同一逻辑成果和推论拥有仍由resolved_result_keys与材料身份判断，不能只按调用次数发放。

本文中的保存或提交首先表示更新当前运行内存，不等同写入存档文件。手动保存只允许可操作调查主画面、问题列表及未打开手册/阅读层的稳定核心核查页。对白、普通回应、资料、目标详情、对白记录、来源、等待收下、已经收下但尚未继续的结果、判定、演出和收卡阶段，都不能写入新的手动调查档。菜单、设置和读取子页不提高资格。

进入等待收下的页面、点击收下、收卡开始或刚结束、打开关闭资料或来源，都不写入新的普通自动档。结果组完整提交、表现完成，并且玩家按正常流程返回允许调查的页面后，当前有效流程才按既有条件触发一次完整自动保存。核心不代替玩家收下或继续，不保留跨会话的补写队列，旧流程被替换后不再发出保存请求。

不可中断事务期间不接菜单请求。纯表现暂停时停止画面和声音的播放时钟，保持当前帧与原处理锁，不完成显示，也不代替业务操作。玩家选择跳过时才显示既定终态；暂停和跳过都不扩大保存资格，保存模块按实际业务状态判断。正式指认前保护、阶段前后保护和结局内部续播继续由《存读档》规定。处于禁止保存的页面时，离开确认提供直接离开和取消，保存选项不可用；读取其他档案也不增加先保存资格。直接离开会丢弃最近一次成功保存之后的变化。

旧资料、来源、等待收下或已经收下的快照，按其保存引用和执行标记恢复到稳定页面，不重发卡牌，不重新执行结果，也不因为恢复了旧页面而允许写入新档。目标选择、两个出示槽和当前界面显示状态分别恢复，不能从其中一项推断其他状态。

## 5 主动补充与结果返回

局部补充只使用玩家实际点击的已拥有内容版本，不自动代用已有材料。两个出示槽都已放入卡牌时，先回选材界面撤下无关卡牌。基准材料撤下、目标改变或目标版本改变后，旧局部补充失效，必须重新判定。

回应入口是实际文案调用，按配置可在收下前或收下后阅读，不统一要求先回应再发卡。三个表现等级都保持相同业务结果。未收下的新推论不能进入持有集合、不能参与下一次出示，也不能提前执行它所绑定的更正、确认和解锁。

| 等待收下时点击【回看来源】 | 独立调用来源阅读器并读取本次used_sources；逐层保存返回位置，不建立推论实体，也不套用办案手册的整次检视调用 |
| 来源上一级或Backspace | 返回上一层；关闭回最初调用，Esc只暂停 |
| 关闭来源阅读 | 结束本次来源阅读，回到最初详情或同一个等待收下的推论页面，恢复位置、焦点和出示槽引用 |
| 待收、已收或失败时打开菜单 | 暂停继续或取消离开回原页面；返回标题／退出沿共用确认，禁保存，直接离开可用，不提交未完成结果或推进next |
| 点击收下 | 验证当前待收引用，执行该推论唯一知识事件，提交拥有、永久来源、确认、更正和知识条件解锁，不移除世界实体 |
| 收卡动作结束 | 回已收结果并恢复检视；有指定收下后回应时先完成，再允许核心继续；新卡不自动入槽 |
| 点击继续或合法下一问选项 | 按正常结束步骤清除当前问题的草稿，再返回调用界面或初始化已经开放的下一问题 |

等待收下时允许菜单、只读全库检视、实际来源和收下操作。改变目标、修改出示槽、离开场景及进入下一问题仍不可用。通过【办案手册】或I进入的整次检视，关闭后回原待收页面；通过【回看来源】独立进入的阅读，关闭后回同一待收全文。独立来源页中按I，沿原检视许可打开完整手册，结束该次手册检视后返回原来源页及层级；I不替代【关闭来源】，也不穿过上层菜单。两种调用均保留当前结果、正文位置、焦点和两个出示槽的精确引用，不能隐式收下。核心手册固定只读，普通阅读沿其第2—4节；本段来源是核心独立调用，数据和返回不移交手册导航。普通问话的显示及原核查上下文恢复见第4节“普通对白调用与核心结果视图”。

普通材料按取得节点直接入库，没有等待收下步骤，不锁定正常操作。同一材料实际获得新内容版时，再播放普通新卡生成反馈；实体数量、获得序号和已有出示版本保持。同版重复、回看及读档恢复不重播。新操作切换页面时结束显示，已取得材料和未读状态保持。核查生成的新推论仍须主动收下。

并行发现按实际已知事件选择内容版。第二项发现应授予同时包含两项已知信息的合并版，其版序高于任一单项版；两种发现顺序得到同一合并内容。版本由文案的合法结果提交，动画只表现取得，不选择版本或覆盖已知信息。

## 6 跨次核查与关卡配置

关卡由工作簿“关卡轮次”“出示关系”“结果接续”组织，读取公共正文、条件、事件以及同一份材料持有集合。正式轮次、关系和接续直接在表内维护；本接口只解释功能规则，不复制案件剧情。

| 配置项 | 内容要求 | 核心处理 |
| --- | --- | --- |
| 开始入口 | 问题引用、target_kind、实际目标文本引用、开放条件和调用上下文 | 尚未开放的问题不能进入；两种目标分别校验合法引用 |
| 证明目标 | 确认范围、可用内容版本、充分关系、局部及未命中回应 | 保持本次选用的版本，一张材料充分时无关第二张不进入来源 |
| 中间结果 | 回应节点、结果组、执行时点、是否生成推论和实际来源 | 不生成卡牌时保存已确认记录；生成推论时等待玩家主动收下 |
| 后续入口 | 必要的已确认事实或已拥有内容，以及显式下一问选项 | 只开放合法入口，不自动选择问题或改变地点 |
| 前次依据 | 需要引用的basis_relation及其实际确认范围 | 已知条件和证明来源分别校验，冻结实际结果，不占额外出示槽 |
| 等价解法 | 相同确认范围、业务成果、结果组、是否生成推论、强度和必要高潮标识 | 共用成果去重，每条路径仅保存本次命中的实际依据 |

串联把上一段已经确认的结果作为下一段的开放或成立条件。并联允许多个已开放的问题按不同顺序完成，各自保存实际结果。汇合在同一条件分支要求必要的前段全部完成，再开放共同的后续问题。可选补证使用独立条件分支或额外可选问题，不提高已经充分的最低要求。多解法通过不同合法关系指向同一成果，不能只因为共用动画就判为同一结论。

条件为真只说明入口或关系可以使用。后续核查真正采用前次结论作证明时，必须另外配置basis_relation，读取实际已确认记录。没有生成卡牌的结论通过已核问题、材料来源及既有核心结果视图回看，不能拖入出示槽。需要选作牌时，正式配置推论并完成主动收下。

每段必须有可以到达的开始条件、可以取得的充分依据和正常返回路径。循环依赖使任何前提都无法取得、同优先级关系指向不同成果、尚未收下的推论提前解锁后续内容、未声明的材料自动补入，都需要在内容接入前解决。扩展不增加推理点数、成功概率、任意合成或强制固定问话顺序。

### 普通追问、问题身份与成果复用

普通话题、编排轮次与question_id分别对应各自用途。普通追问可只取得证言，不创建核心问题；需要核查成果时，显式绑定合法目标、充分关系及已有结果组。同一待核问题内换目标、补材料或继续追问可沿同一question_id，次数仍按第11节维护。单个确认范围完成不封死该问题的后续合法目标；已完成范围回看原结果，新范围按配置开放。轮次id与question_ref分别维护，不按一次追问或一个入口重新分配本题容错。

普通话题与玩家出示核明同一成果时，共用result_id、confirmed_scope、timing、group_id及已有去重记录，只冻结各自实际采用的来源。文案已看、话题结束和成果confirmed互不代替。自动核对使用配置的精确目标与已听依据，不假填出示槽、不消耗卡牌、不伪造一次用于扣罚的主动出示；绑定待核问题时仍须满足其当前合法入口与失败状态。实际听到的内容可以登记为证言，登记本身不等于本题已完成。

### 正式配置的逐题核对

逐题条目沿主笔当前采用稿填写，允许解法按实际条数展开。材料正文由办案手册唯一维护，文案入口、公共条件与事件结果由文案系统唯一维护；核心只维护问题、合法材料关系和结果引用，不复制正文、条件判定或事件动作。

| 交接条目 | 本题需要填写 | 复用位置或映射 |
| --- | --- | --- |
| 原题与原话 | 采用稿文件、校验值、场次及稳定原句定位；注明本题要核明的范围。正文引用统一源稿，不在这里另存一份可修改台词 | 原稿定位与程序运行编号的对应，由主笔统一交付 |
| 当前目标 | 问题编号、目标类型及实际显示文字引用。人物说法列target_text_ref、target_read_version及实际已听条件；推理问题列已开放问题的精确文字引用 | 第2节TargetRef；Excel“##程序映射”的TargetRef行 |
| 前置取得 | 逐份列材料身份、精确内容版、合法取得入口和取得时点；需要前题成果时列已确认范围。核对这些依据能在本题成立前取得，回叙中看见的信息不自动成为可出示材料 | 第2、3、6节；MaterialRef、basis_relation及调用入口 |
| 允许解法 | 每条分别列一份或两份实际依据、已知条件、匹配范围、确认范围和实际采用原句。一份已充分时可带无关第二份，该份不进入证明来源；左右槽位不影响结果，同一材料的两个版本不能同时出示 | 第4、6节出示关联；材料身份与内容引用成对，不补用最新版 |
| 未充分与明确错误 | 分别列需要保留的局部确认、欠缺说明或有效反证。只有作者明确声明的错置对象、时段或证明范围才列为扣罚关系，附合法目标、精确材料、条件、原因和回应 | 第11节；Excel“错误出示”沿既有字段填写，普通无关材料不逐条穷举 |
| 成果与生效时点 | 列确认、更正、推论、开放内容各自所属结果组及生效步骤。无新推论沿原回应／继续时点；有新推论时，拥有、更正和解锁按收下结果组一起提交 | result_id、timing、group_id；保持原程序映射槽 |
| 表现与原句 | 普通或递进等级、表现形状、需要高亮的实际原句；关键击破／涌现补climax_key和首次重大成果说明。击破对象为人物断言，推理问题的重大新确认可用涌现 | 第7节；effect_kind、effect_level、statement_quote、a_quote、b_quote、climax_key |
| 证明与多解法 | 列本次实际来源。等价解法共用同一成果、结果组、产出和关键转折，每条只冻结自身命中的依据；引用前次成果时填写实际已确认关联 | 第3、6节；used_sources、basis_relation，不占第三个出示槽 |
| 接续与返回 | 列成功后可进入的下一问及原返回处；注明提前取得、提前解题、重复进入、错误后重选和归零重试的接续。待收、检视和暂停不补交成果 | 第4、5、11节；next、return_to、button及既有去重记录 |
| 本题核验 | 列至少一条从合法取得到正常返回的完整走法；按本题实际使用的机制补替代解法、错版本、明确错误、提前完成和重复执行的预期结果 | 第8节；分别记录文件检查、成功导入与游戏实测，附实际文件／包版本 |

公共文案数据读取《文案接入数据.json》：入口使用entries[].id、first_text_id和condition_id；准确原话使用text[].id与read_version；条件引用conditions[].id，事件结果引用events[].id，提交沿jumps[].event_id与timing。条件内部的any及事件内部的effects由文案系统维护，核心不再登记一套同义进度。材料使用手册material_id与精确content_id。

轮次id标识本表的一条入口记录，同一问题的不同入口分别编号；question_ref沿稳定的Lxx_Rxx问题身份，同题多入口共用。call_ref填写实际文案question调用目标，dialogue行的question_ref与call_ref为空，不创建核心问题或容错。已填写的文本、条件、回应、事件和返回引用必须真实存在；可空字段按下文约定处理，缺少必填引用时保留数据并禁用，在#备注列明缺项。

内容检查先核充分依据、准确版本、结果时点和返回，再检查单份充分、双份换序、旧版不足、提前完成及重复进入。导入后补实际操作与跨模块存读验证。工作簿第1行写中文名和约束，第2行机器键，第3行类型，第4行业务列填c、维护列留空，第5行数据。跨系统按稳定ID读取对应数据，不用核心行号读取文案。

## 7 三级表现与业务结果

| 字段 | 填写要求 | 核心使用 |
| --- | --- | --- |
| effect_kind | 正式结果页只用既有“击破”“涌现”中文枚举，其余沿反馈规则留空 | 关键主题与普通反馈语义分别消费，不改变结果和时点 |
| effect_level | normal、progress或key，缺省normal | 选择普通反馈、递进推理或关键突破，不参与匹配 |
| statement_quote | 人物说法的限定或排除表现需要填写，必须是目标全文中的唯一连续片段 | 只定位指定原句；推理问题留空，不碎裂问题文字 |
| climax_key | key必填，normal和progress留空 | 同一个关键认识转折的合法解法共享，在当前进度中记录已经处理 |
| a_quote和b_quote | 本次实际使用内容版本中的连续原句 | 只高亮实际依据，不绑定左右出示槽 |

normal承载日常确认、限定、普通排除、局部、不足及重复成果回读。progress用于充分关系首次确认新的范围或事实，或者形成新的推论，默认表现约3200毫秒。它可以只保存确认结果，也可以生成普通推论，或通过结果组开放后续问题，不要求与人物原话发生矛盾。key用于主要调查方向改变、重要解释排除或阶段证明链闭合，提供最高规格的击破或涌现。

等级、形状与是否生成卡牌分别配置。已经成立的普通排除仍完整更正说法，普通关联仍可以生成推论；递进确认可以不生成卡牌；关键涌现也可以只揭示重大新确认。表现强度不能补造充分条件，也不能替代作者明确声明的确认范围。

关系判定完成后，在本次结果组执行前确定first_resolution，冻结selected_presentation、TargetRef和实际来源。首次依据精确目标、确认范围及既有完成结果判断，不依据调用次数或动画名称。同一成果的等价解法共用稳定业务引用，程序不通过台词相似程度猜测两个结论是否相同。

### 普通追问后直接形成矛盾

沿原节点、结果组和表现快照配置以下顺序，不增加另一种核查库存或完成记录：

1. 绑定仍需核查的精确旧断言及其原句，确认玩家已经实际听到该版本。保留旧原话，不先用补充回答覆盖它。
2. 补充回答完整呈现并到达既定结果触发点后，登记实际已听证言及精确来源。补充回答呈现与核心结果调用沿既有后继分步安排，不能在承认入句时先执行此次更正或完成。未来文字、回叙中角色未知的信息、尚未呈现的承认不参与核对。
3. 沿显式关系核对同一对象、事件与所否认行为。只有明确否认与明确承认直接互斥才可击破；省略、怀疑或仅有可疑细节使用普通补充。没有这条合法关系时不由台词关键字猜测成立。
4. 在确认、更正或完成标记写入前，取得同一成果的既有状态，冻结first_resolution、TargetRef、used_sources、selected_presentation与climax_key。已完成成果沿原记录回读；当前进度已处理该高潮时不再选择它。
5. 按结果接续的event_owner与timing交接：narrative沿回应内原event提交，核心不重复调用；core/after_response在完整成功回应结束后由核心提交公共事件；core/on_accept由玩家主动收下调用公共事件，统一提交推论、确认、更正和解锁。到所选主表现入口才登记handled_climax_keys。表现可以穿插在本次回应链的明确节点，不能替代业务提交。
6. 按原继续或收下流程结束本次结果，接续完整人物回应或合法下一入口。同一成果在前一段追问已充分成立时直接合并后续重复操作，不再出示刚听到的自认，也不执行第二遍结果组。

普通话题不得先写成果完成，再另发一条关键演出请求重新计算首次资格；这会把原本的首次成果当成重复。首次选择后的表现沿同一结果快照使用，不因结果组已经提交、暂停或查阅而重算。

progress只用于首次充分成立的新结果。重复成果使用普通回应回读，复用result_id、resolved_result_keys和confirmed记录，不新增progress_seen队列或累计数值。局部反馈仍是当前问题尚未充分完成的结果，不因为画了进展效果就写入永久完成状态。普通话题如果明确核明同一合法成果，共用该成果记录；纯台词切换和重读不自动确认。

### 关键表现准入与终态

key需要充分关系、首次重大认识转折、明确climax_key以及当前进度尚未处理该标识。人物说法的击破还需要精确断言片段和与它互斥的实际依据。推理问题没有人物原话，不能使用断言碎裂；重大新确认可以采用关键涌现。

关键涌现有两个结果分支。需要生成新推论时，还必须确认这个推论身份尚未拥有，结束后显示完整等待收下的推论，玩家主动收下才能提交拥有、更正和解锁。不生成新推论时，必须是首次新增的重大确认结果，灵感演出揭示结论图文后返回完整普通回应，仅提供继续、回看依据和办案手册入口，不显示收下按钮，持有数量不变。

不生成新卡牌的关键涌现使用key_insight_fact表现分支，退出时mode=response、card_ui_page=closed。需要玩家收下的新推论退出时mode=pending、card_ui_page=pending。核心依据配置的inference_content_id和业务结果选择终态，不从动画形状或粒子是否出现推断。

已经拥有的推论如果只被再次说明，使用普通回读；如果这次有新的合法确认或更正，作者另外配置结果与执行时点，按该新成果判断等级。不能重新发放旧推论、覆盖首次来源或自动执行旧的收下结果组。同一成果的多条合法路径，结果组、是否生成推论和climax_key必须一致。

同一次成果同时更正说法并生成新推论时，只选择一个主表现，先说明合法更正范围，收下后才整体提交。没有新推论的关键成果继续使用其原节点执行时点，不增加专用结算接口。动画结束后读取明确配置的终态，不通过定时器推测是否应发卡或打开下一问题。

### 提前充分、合并与延后演出

提前充分时沿同一成果身份确认，复用已核事实和实际来源；后续重复问题直接承接。需要先听完人物回应再播放时，在首次成立的同一结果上下文中保留表现快照，由current_node_id及原有演出顺序确定播放位置。已到timing的结果组照常生效，未到时点的继续或收下操作仍需玩家执行；延后表现不改写这些时点。不得清除当前结果后再用新call_id或新result_id把同一旧成果伪装成首次。

延后期间可穿插文案回应、已确认内容回读、检视及暂停，均保留当前结果。进入另一项独立核对或返回自由调查前，先完成当前主表现和原结束步骤；不建立跨问题的待播队列。若后续普通追问还要分别确认新事实，先完成这些独立结果，再在真实汇合节点建立综合结果，避免让多个未结束核心结果互相覆盖。

文案分页的继续只推进当前文字，不调用continue_result。该操作会按原规则执行继续时点结果、结束调用并清草稿，因此约定的主演出必须放在它之前。推论仍先到原收下节点，收下后再正常继续；不能先结束结果，再声称延后快照仍在使用。

局部断言的击破只确认该断言范围。人物各自回答分别按原结果组确认；双方所需回答、前题事实、局部主表现及其人物回应齐备后，才在配置的综合确认节点核对完整关系，冻结综合成果的首次资格和一个主演出。此处复用已确认记录，无需再次装填同一材料。综合结果与局部结果的确认范围不同，不能把涌现排为局部击破那次提交中的第二段主演出。

综合成果若确已在更早的结果中提交并结束，后续只普通回读；如需在后段演出，必须在首次确认时安排并保留同一结果上下文。不能回滚成果、换名建副本或借重试恢复首次资格。需要情感段后领取推论时，情感段放在进入推论待收节点之前，仍属同一未结束结果链；可读取本次充分判定及已确认前提，不能用尚未提交的综合confirmed作为开放条件。综合确认、更正、解锁和发卡均等原收下结果组，进入pending后next继续等待收下，不以情感段推进绕过，也不追加第二个主演出。

### 重复、暂停与读取进度

进入选定关键表现时，把climax_key写入当前进度内存。正常播放、跳过和减弱动态都视为这个高潮已经处理。暂停、只读检视、来源返回及同成果的另一解法都不重复播放；业务去重仍沿resolved_result_keys和结果组执行记录，两类标记互不代替。

关键标记随下一次合法调查档保存。已经完成的档案恢复完整结果，旧的待收或已收档案恢复稳定阅读页面，不续播动画。读取突破之前的旧档，再重新完成核查，可以在该档进度中播放一次。文案全局已看仅控制对白快读；到核心确认或主表现交接处停止快读，不能永久屏蔽该档尚未处理的高潮。核心不增加禁止保存页面的写入资格，也不保留后台补写队列。

普通、递进和关键表现结束后，完整回应或推论全文都没有阅读倒计时。暂停保持当前画面与声音时钟，不推进播放；跳过才完成当前显示，不代替继续、收下或下一问选择。静音仍能读到确认范围，减弱动态使用静态对照代替强位移。连续段的检视限制保持，收卡期间的检视锁随演出调整为900毫秒。

同一转折在当前进度只处理一次，每次出示只选一个主高潮。关卡可参考2—3次递进后安排一次关键转折，此参考不参与运行判定；不配置时间冷却、随机概率或累计成功门槛。关键资格不足时使用普通反馈，失败／重试不清高潮标识。

### 接入责任

缺省normal用于已有配置。progress没有充分新结果、key缺少climax_key、推理问题使用断言碎裂、同一高潮标识指向不同认识转折、等价解法产生不同业务结果，都属于需要在接入前修正的配置错误。表现字段不能吞掉合法结果，也不能凭显示效果产生事实。

策划维护核心工作簿中的轮次、关系、结果接续及其引用。文案提供公共正文、条件和事件，手册提供材料身份与内容版；程序消费精确目标与实际来源，冻结首次资格和表现，按唯一提交方执行结果。存档在原合法边界读取联合快照。正式数据维护、文件校验、游戏导入和实测分别验收。

## 9 通用分段配置

串联、并联、可选补证、多解法和汇合使用第6节的现有入口、关系、条件和结果组实现。配置每一段时，必须明确开始条件、实际目标引用、可以取得的充分材料、确认范围、结果执行时点、实际来源和正常返回。每条后续入口说明采用哪些已经确认的事实或已经拥有的内容，不以动画播放完毕作为解锁条件。

需要连续核查时，文案显式提供下一问选项，玩家自行选择。需要自主探索时，正常结束后返回原调用界面，已经开放的问题保持可用。两种方式共用同一完成记录和来源快照，不设置强制固定顺序，不把阅读、等待或查看资料当成内容推进。

正式轮次、证明关系和结果接续由核心工作簿承载；文本、条件、事件及材料仍引用各自唯一源。原型采用六稿真实18项核查及实际材料，不新增谜题，也不反向生成或改写正文。

## 10 扩展边界与推荐配置格式

### 共用手册展示与玩法职责

办案手册沿其第1—4节提供证物与人物浏览、详察，第5节规定同一状态与旧阅读上下文。核心只使用全量只读调用；其他系统的情境出示沿其原合同。材料正文维护一次，核心浅扇手牌、双槽及手册读取同一取得集合、准确内容和已读记录，不另存库存。

核心不再发起手册select_material情境请求，旧核心选入按钮、绑定与示例退役；点击空槽只确定手牌放入位置。点击手牌复核并更新原草稿，就地详情只阅读实际持有内容。手册的翻页不改变双槽，不用图标槽序替代slot_index或material_id，关闭、暂停和键鼠边界沿第4节。

新版手册取消排序、重点、来源、历史履历、新推论列表和对白记录页。核心已选旧版、成果冻结依据和文案实际原话仍须可回查，分别使用核心版本/来源阅读及文案记录调用，保留原目标、结果、准确引用与返回位置；不恢复已撤销的手册导航或建立第二份正文。

world entity与知识记录独立。尸体、窗户、饭具记录取得后不默认隐藏现场对象，推论收下不处理现场收物。实际物件移除与NPC在场变化必须由对应合法剧情事件独立提交；素材换图也不能替代该事件。

### 功能与表现分别维护

新增问题、材料内容版本、合法关系、条件分支和等价解法，沿现有目标、结果组和来源引用配置。它们可以扩充核查内容，但不能仅靠配置文字扩大出示上限、增加新的目标种类或改变结算时点。涉及这些规则时，需要同时明确数据结构、校验与消费者的变更。

颜色、纹理、字体、立绘、缩略图和布局可以重新设计，材料身份、目标引用、确认记录和永久来源保持不变。两个出示槽各自绑定固定编号，撤下一槽不移动另一槽。本版浅扇手牌直接写入原草稿，手册全量只读，详情就地打开；导航、焦点及返回均按当前布局同步。

正式界面必须按稳定动作键、语义区域和当前业务状态绑定输入。区域位置、大小、字体和素材适配从最终布局读取；重新排版后，命中范围随当前布局重新计算，不能沿用旧图坐标。按钮改变中文名称、颜色或形状后仍调用同一业务接口，颜色变灰或图像隐藏不代替程序拒绝输入。

| 接入对象 | 稳定绑定 | 布局改变时的要求 |
| --- | --- | --- |
| 操作控件 | 对应接口的稳定动作键与参数，例如指定槽编号 | 更新当前命中范围，重新校验业务状态，不按按钮文字或图注编号派发 |
| 两个出示槽 | 固定slot_index及各自MaterialRef | 显示位置可以改变，材料引用和槽编号不变，不按屏幕顺序重新分配 |
| 焦点与列表 | focus_ref记录对象引用和控件语义，列表使用anchor_id | 按新布局找到同一对象，重新计算可见位置，不把旧屏幕坐标当焦点 |
| 正文阅读 | 精确文本引用与稳定文字位置，像素偏移仅作布局内辅助 | 字号或换行改变后回到同一文字位置，不能仅复制旧body_offset；具体文字锚点与存档消费统一接入 |

布局刷新只更新显示排布、文字排版、素材适配与命中范围。它不重新打开一个问题，不执行关系判定或结果组，不改变TargetRef、所选材料版本、来源快照、业务mode及call_id，也不清除当前问题的草稿或重新播放已经处理的关键演出。保存资格继续根据实际业务页面和处理锁判断，不因为换皮或重建控件树而改变。

材料文字和观察图片如果承载证明信息，就必须跟对应内容版本一致。没有改变信息的素材替换可以作为美术调整；证明信息改变时，使用新的内容记录，不能用换图覆盖旧版本。annotation_specs、局部裁切、分帧和图注从同一语义区域维护，布局变更后更新受影响派生图。内边距、滚动条、字号和行高变化后，重新计算显示容量，完整正文数据继续保留。

旧绘图工具的固定坐标、六列网格和白模范围不作为当前UI规格。浅扇手牌默认上限10、4:3上限7，超出分页；新图、图注与命中区按实际组件和有效显示区同步，不从旧坐标重建。静态图通过不代表游戏已接入。

现有接口分别定义材料身份、版本、来源与确认成果记录，通用显示读取这些记录。出示接口接收MaterialRef集合，证明关系的a/b字段与两个出示槽是双卡核对的局部约束。手册按自身取得顺序读取同一材料引用；新的观察操作可以沿材料更新和结果提交入口接入，手册与导航只读已生效记录。该操作的输入、临时交互与信息变化仍需具体设计并由程序实现，不能在手册只读层暗中发卡；这些接口约定不代表游戏架构已落地。

### 配套表头与程序映射

工作簿在原七张规则页、三张说明页及三张正式内容页之外，增加“核心界面资源”页。运行页所有字段独立一列，第1行中文名与约束，第2行机器键，第3行真实类型，第4行业务列填c、维护列留空，第5行数据。##说明页不导入；A列以#开头的行、全空行及#字段列均排除。已有data_scope时仅取runtime，已有enabled时仅取TRUE；没有enabled列的固定规则页按启用处理。

程序按机器键和类型读取。新页只使用string、int、bool；枚举是string字段的允许值，不另写enum类型。data_scope区分runtime与test，enabled控制是否启用；#name、#source_lines及#备注均不导出。说明文字不能代替条件、事件或结果字段。

轮次的trigger_text_ref只在需要由实际原句完整播放后开放核查时填写；已有question调用时可空，不自动选材或提交。回应优先采用本轮次非空的response_entry_ref，否则读取命中关系的默认回应。同一回应只调用一次，领取前后顺序沿该文案外调的回调时点；配置在on_accept后的回应，必须等核心完成主动收下后才开始，不能提前用尚未取得的推论通过入口条件。

内层文案回应返回时恢复当前核心结果；最终核心【继续】才结束本轮并触发外调after_response。领取前回应完成后进入待收；领取后回应完成后回已收结果。return_ref指本次回应与结果都结束后的接续。结果表timing=after_response用于其所属公共事件的回应完成时点，外调after_response用于核心调用结束，程序按各自调用上下文区分，不能把两层返回合为一次。

启用的轮次与关系必须具备本类记录要求的入口、目标及回应。condition_ref为空表示本行无额外条件，已填写的条件引用必须存在。缺少必填引用时保留已核实数据并禁用，在#备注列明缺键。条件与事件读取公共源，材料读取手册身份和内容版，原文读取text_id和read_version；摘录列只定位该版本的连续原句。

普通dialogue轮次不创建question_id或容错；同题多入口共用question_ref。出示时先按双份充分、单份充分、局部或有效反证的既有档位检查，再在当前有效档中选择priority唯一最小的一条。只冻结该条实际用到的材料版本与各层来源，不合并其他等价解法。basis_material_ref与basis_content_ref可空但成对，声明玩家已经实际取得的前次材料；验证持有后冻结该准确版本，不放入出示槽，不以condition_ref代替来源。并列最小仍有多条时报告具体歧义，禁止按工作簿行序任选。未命中后才进入既有明确错误与默认不足。

narrative表示文案在其已有event点提交，核心接收结果及回调，不再调用同一event。core/after_response在完整成功回应结束后由核心提交公共事件；core/on_accept由主动收下调用公共事件一次，整体提交推论拥有、更正、确认与解锁。本次表timing只填写after_text、after_response或on_accept，分别对齐对应文本完成、完整回应结束及主动收下；narrative仍遵循原event点，既有进入回应等运行语义不作全局替换，动画结束不代替这些业务时点。return_ref为caller时沿原调用上下文恢复，其余值必须解析为真实入口。原结果组、执行去重与严格保存规则保持，不建立第二套事件动作或材料库存。

制作参数的单位与范围独立说明，不混入正式文案数据表。x和y定位所属视图中的区域；width和height必须大于0。font_size与line_height按真实字体排布检查，不能仅按字符数量推算。像素必须标明所属参考画布；1600×900为默认稿，运行按设置的有效显示区重排，1920组件进入默认稿只换算5/6一次；实际播放时长和制作姿态时钟分别标明单位。带pose_ms的值只用于姿态取样，按照rhythm映射到实际播放时间；粒子姿态寿命不能成为发卡、解锁、保存或检视恢复的条件，程序读取真正的表现结束事件。

字段字典中的中文说明供维护者阅读，程序校验按同一schema中的机器键与明确约束实现，不执行自然语言说明。类型为枚举时，存储值与中文显示名称分别解释；默认值采用明确类型，不能把示例编号用作默认引用。

程序确认格式后，更改机器键、字段类型、引用目标或枚举值时同步实际数据、字典、导入与消费者。中文显示名修改不改变业务语义。接入验证需覆盖缺失引用、互斥目标、重复路径、逐层冻结，以及目标类型与生成卡牌的两种终态；推荐表头不证明程序已经支持。

## 11 核查完成、容错与重试

### 结果类别与判定顺序

沿第4节原有关系，补充明确错误类别incorrect。按双份充分、单份充分、局部成立／有效反证、明确错误关系、默认不足的顺序求得唯一结果。充分和有效局部结果优先；单份充分时，无关的另一张卡牌不计入来源，也不扣容错。无匹配继续按insufficient说明欠缺，不从卡牌类型、动画等级或出现反证自动推导incorrect。

incorrect表示作者已经明确声明：本次出示在当前已知条件下错置对象、时段或证明范围。所选材料仍可用于其他问题，真实材料和正确内容保持。错误关系必须同时满足合法目标、实际所选精确材料及已知条件，不能只配置一个error标记。未取得的新版本或尚未知晓的条件不参与这次判定；同优先级错误关系若给出不同原因和结果，在接入前修正。

| 最低配置语义 | 填写要求 |
| --- | --- |
| 错误关系身份 | 稳定且唯一的incorrect_relation_id；具体表名和ID格式由程序映射 |
| 合法目标 | target_kind、question_ref及target_text_ref＋target_read_version；旧错误页字段由适配映射。说法须完整听到，问题须已开放 |
| 所选材料 | 一份或两份MaterialRef，各自明确material_id与content_id；不写版序代替内容身份 |
| 匹配范围 | exact_set要求所选身份集合正好一致，contains要求包含配置引用；两者均按精确版本核对，左右槽无关 |
| 已知条件 | known_condition_ref必填，引用实际已经满足的条件组；始终有效时显式引用作者配置的无附加条件组 |
| 原因与回应 | reason_text_ref及response_ref，说明错置范围并展示本次扣1、剩余次数；全文可读，不使用无依据的通用失败话术 |

配套表“错误出示”有可填模板与匿名test例：TEST_Q_STATEMENT绑定已听到的目标对象，TEST_CARD_OTHER_OBJECT_V1是实际取得的另一对象记录，TEST_COND_OBJECT_MISMATCH_KNOWN表示玩家已知两者不同。没有前面的充分或局部关系命中时，只选择该材料时以exact_set命中错误关系，回应指出对象对应错误。切回未绑定错误关系的其他材料，默认不足且不扣。主笔用试跑的真实引用替换这些占位；示例不给正式剧情补造材料或正文。

错误结果只改变当前问题的容错，显示原因与实际出示依据；不生成推论、不更正目标、不确认成果、不解锁内容。人物回应正常加入实际已听记录，记录展示仍由手册消费。归零判断发生在这次扣除提交后；表现结束开放相应稳定页面，不由粒子或定时器扣次。

### 次数、退出与重试

每个question_id在案件进度中分别记录初始上限3和剩余次数。普通追问和编排轮次不逐项创建新问题；同一待核问题换目标或补材料仍可用同一ID，不按每轮补3，也不按整组质询共用3次。首次合法进入未完成问题时创建记录；同问重入、收起、检视、换版、更新目标及暂停均保持。只有命中incorrect的新主动出示扣1，最低0；充分、支持、限定、排除、关联、局部、有效反证、不足和重复均不扣。

每次出示有程序可识别的提交身份。同次连点、回调和恢复重复消费只能扣一次；玩家读完回应再主动提交属于另一次出示，可以再次扣。容错扣除使用独立提交记录，不能借climax_key或结果组执行标记代替。字段格式由程序确定，最低需能识别当前案件、问题、尝试和该次提交。

剩余大于0时显示完整错误原因，可重新选材或稍后核对，保留草稿。该question_id剩余为0且当前目标／确认范围未完成时进入failure，card_ui_page=closed，出示、收下与成功继续不可用；该问题的其他已确认范围不抵消0次，也不封存所有后续范围。已完成成果可回看。检视、依据、暂停和返回原处可用；共用菜单可直接离开或取消，保存灰显，离开不补自动档。失败由0次及当前未完成范围推导，不新增完成记录。

返回原调查或会话后仍保留0次，重新打开同问仍显示失败页。点击【重试】才恢复当前问题3次，开启新的尝试身份，清该问题草稿与局部临时结果，按当前合法入口初始化：statement目标未选，reasoning问题自动选定，两个出示槽均无材料。按钮文字复用UI_COMMON_RETRY，动作保持retry_question；恢复未放材料的核心双槽页，手册临时浏览按当前调用规则处理。

重试不回滚持有材料、已取得版本、同版来源、材料已读／重点、其他问题容错、已确认成果、冻结证明、已经执行的结果组和handled_climax_keys。已经完成的成果回看原记录，不通过重试重新发卡。上述核心业务及高潮记录读取该档进度；文案已看独立维护，不成为恢复容错或屏蔽核心高潮的条件。

### 完成与保存

本次核查成功以充分成果实际提交为准。无新推论时，按原进入回应或继续时点确认；需要新推论时，收下才整体提交。动画停止、关键未触发、局部成立、待收、明确错误和失败均不完成核查。继续或下一问结束本次结果，随后按原规则返回；阶段开放、案件胜利与正式指认失败由对应案件／指认功能判断，核心只提供确认成果与实际依据。

容错只存运行内存，随原合法调查档联合保存。稳定选材、允许的调查页或问题列表按《存读档》开放手动保存，保存不执行出示；档案导出／恢复各问题剩余次数、尝试和扣次去重记录，无新档位或时点。0次返回允许调查页后可手动保存，重入恢复失败。

失败及其原因、依据和手册阅读按禁存调查来源打开暂停。失败主屏继续回原失败页，阅读层按手册恢复原对象、层级与位置，关闭后回失败页；读取只有直接读取／取消，取消保留原状态，成功读取才替换会话。保存与先保存后读取禁用，禁存提示绑定UI_SAVE_DISABLED_CORE_FAILURE，正文读取初始化唯一文字源。玩家返回可操作且允许保存的调查画面后，即使本题剩余0次，也可按原条件保存。上层菜单不提高资格，返回标题／退出沿共用直接离开和取消规则。

错误、失败返回及重试本身不触发普通自动档，不新增问题开始保护档，不补写旧快照。重试850ms显示结束到稳定选材后，才按原资格开放手动保存。完成成果仍在完整提交、表现结束并正常返回原允许页面后按既有条件更新自动档。旧档缺少本节记录时，未完成问题采用3次初值，已完成成果／结果／高潮标识保持；兼容由程序与存读模块确认接入。

### 频率与共用消费

effect_level缺省normal；progress须首次充分的新确认，key还须完整关键准入和未处理climax_key。同一转折当前进度一次，同一出示一个主高潮，无随机触发、时间冷却或连续累计门槛；2—3次递进后安排一个高潮是关卡节奏参考，不作为程序判定。关键资格不足降为同语义普通反馈，合法结果继续执行。失败和重试不清高潮记录。

功能文字读取初始化唯一源basic.TbFunctionText，位置与引用见[核心玩法配置说明](核心玩法配置说明.md#共用功能文字引用)。无匹配关系时读取核心总控的insufficient_text_ref，当前已引用实有键UI_CORE_INSUFFICIENT；已匹配的专用不足回应仍读取对应文案入口。【复核机会】显示当前问题的三枚记号和剩余数字，位于玩家出示按钮上方，人物姓名纸签不放次数；不足提示放在原话框标题行右侧，不挤复核区。错误只划去一枚，归零主动重试。retry_text_ref继续绑定UI_COMMON_RETRY，核心不另存固定词库。

声音使用《声音播放》的事件／通道、暂停和减弱规则，只补动作切点及声音特征；目标导航读取真实完成状态，不根据动画和容错变化判为完成。手册读取同一材料与证明，失败不会新建库存或隐藏已取得材料。

配置数据页的#备注供策划阅读，不参与导出；data_scope继续决定runtime／test。测试行备注注明匿名用途。本轮TEST_*例与主笔TEST_BLUEBOX的内容和活动关系分别使用；蓝盒试跑读取核心已定runtime规则与主笔有效内容，不能把两套测试关系一起加载。
