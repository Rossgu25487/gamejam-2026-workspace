# 核心玩法接入

主场景 `game/main/main.tscn` 的 `CoreGameplayPage` 替代计数接口演练。计数夹具独立保留在 `game/features/counter_demo/counter_demo.tscn`。Main 只创建服务、连接页面动作及切换标题／暂停／子页；各玩法页面自己的节点绑定自己的脚本。

## 运行首段

在 Godot 4.7.2 中运行工程，选择新游戏。先检查占位资料，再与占位人物交谈，打开核对占位说法并点击目标。选用证据甲 v1 和证据乙后出示，回看依据，主动收下推论，再点击继续。后续问题以推论和证据乙共同核对；支持结果在继续时确认。

复核占位资料可取得甲 v2，该版单份充分。另一对象记录在已知错置条件下单份出示会扣一次容错；未匹配的普通材料只得到不足，不扣次。三次明确错误后可返回调查或主动重试。I 打开／关闭整次手册检视，Esc 先处理阅读层、网格和对局，结果页 Esc 打开共用暂停。

人物说法核对需先点击上方原话选定目标，单独放入材料不会自动选中原话。服务 `present_disabled_reason()` 同时提供出示资格和禁用原因，选材页在按钮旁展示未选目标／未选材料等提示，并提供相同悬停说明。两个出示槽允许只填一个：单独选用另一对象记录、选定原话后，可以点击出示并将容错从3扣至2。

自主推理的目标在打开问题时自动选定，页面展示“推理目标（已选定）”。问题句用于说明核查对象；选用材料放入出示槽后，点击“出示”才执行判定。筛选下拉菜单的焦点交接不触发暂停，手册筛选在菜单回调结束后刷新；暂停期间不重建玩法控件，恢复游戏时重新计算出示与结果按钮资格。

## 内容数据与策划表映射

`game/data/core/placeholder_case.json` 是用户授权的占位首段。正式文字不在 Main 或页面脚本里。所有内容、版本、问题、关系、结果组、条件与入口使用稳定 ID；正文通过 `texts` 引用解析。替换内容必须同时调整 `content_revision`，再核对关系和旧档兼容策略。

`tools/import_core_config.py` 只读策划 XLSX，读取第2行机器键、第3行类型、第5行起数据；默认只导入 runtime，并排除禁用模板与备注。输出 `rules.json` 和初始化唯一文字源对应的 `function_text.json`。游戏与导出包读取 JSON，不依赖 Excel、绝对路径或 Office。

| 策划对象 | 当前映射 |
| --- | --- |
| 材料身份与内容版 | `materials[id].type`、`contents[content_id]`；`material_id/version/previous/title/summary/body` |
| 说法 | `statements[statement_id]`；`claim_id/speaker/text/record_content/version` |
| 问题 | `questions[question_id]`；`target_kind/statement_id` 或 `question_text_id`、开放 `condition` |
| 出示关联 | `relations[id]`；精确目标、`materials: MaterialRef[]`、`feedback/match_scope/condition/node` |
| 充分成果 | `result_key/confirmed_scope/inference`；等价解法共享业务键、结果组和高潮标识 |
| 条件分支 | `conditions[id]: Array[Array[term]]`；分支内全满足、分支间任一满足，支持 fact/heard/owned/completed |
| 结果时点 | `nodes[id].timing` 为 enter/continue/collect/none；`group` 指向有序动作，collect 强制主动收下 |
| 更正／确认／解锁 | `groups[id]` 的 correct/confirm/fact；入口条件读取已提交事实或已完成问题 |
| 前次证明 | `basis_results[]` 的精确 `relation_id + target_ref`，选取当前 run 最近已确认记录并递归冻结 |
| 明确错误 | feedback=incorrect、精确目标／材料、known condition、reason text、response node；无结果组与推论 |
| 实际取得路径 | 入口、来源身份和关系构成去重键；内容未改变时追加路径不增加实体或版序 |

结果和推论的 `used_sources` 包含形成时完整下级快照。材料当前来源可以增长，旧证明不能重新从当前库存展开。`record_content` 只定位说法所属正文。阅读页用真实文字布局计算 Unicode 码点锚点，像素偏移不能跨正文复用。

## 保存边界与旧档

新游戏初始点建立普通自动档。成功结果完整提交、表现完成且按正常继续返回合法页面时再自动保存。暂停、阅读、待收、收卡、失败、重试和直接离开都不补档。手动保存只允许可操作调查或稳定选材，包括网格；待收、已收未继续和失败页禁用。

联合档案包含 `card_snapshot`、`navigation_snapshot` 和相同 `state_revision`。存读服务先验证完整性与内容版本，再通知 Main 替换。写入通过临时文件和成功重命名提交序号；测试注入独立目录。旧计数器演练档缺少卡牌快照，会被判为不兼容，原文件保留，不伪造正式玩法进度。新游戏会覆盖唯一普通自动栏，手动旧档仍在原处。

## 验证与范围

统一入口：`tools/project.ps1 -Action test -Godot <Godot路径>`。核心回归覆盖版本、匹配优先级、实际路径去重、递归冻结、主动收下、进入／继续时点、容错、失败、重试、旧结果恢复和完整快照；输入回归注入真实 Control 鼠标／键盘事件，在1280×800与1920×1080检查布局。输入回归同时覆盖底栏／网格／手册的推论→全部筛选、手册排序、卡牌详情选用、暂停与刷新交错后的出示、后续推理演出自然结束及已完成结果回看。渲染测试已实际运行并核对本地截图，不代表人工键鼠或跨机器验收。

首段是功能白模。正式案件、地点转场／棋盘、完整目标导航、手册人物话题整理、场景背景与立绘、声音资源、碎裂和飞页成品特效，仍属后续模块或资源接入。当前不会把这些未交付内容标为完成。已绑定接口不预建无依据的分支／结局机制。
