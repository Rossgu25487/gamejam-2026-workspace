# 配置表统一填写规范

## 唯一维护位置

本次以10.14蓝盒测试包为接入样例，保留策划原表的列名、中文、ID和资源字节。程序启动直接读Excel，由配置服务转换成各系统需要的结构。Main只传入包入口、连接模块；页面只处理自己的显示和输入。

后续日常填写 **`game/data/system_test/package/配置表/`内13份Excel**，以及 **`game/data/system_test/程序接入配置表.xlsx`**。这些是此Demo的运行内容源。原`game/代码开发需求/测试用资源/`作为本轮接收基线保留，不要同时改两处。`outputs/system-test/`只是交付副本，游戏不会读取它。

`game/data/system_test/profile.json`只选包根目录、工作簿路径与`test/runtime`用途。普通换正文、资源、条件、目标时无需改JSON、脚本或生成第二份配置。原占位案件及雨夜案例的Excel仍由各自场景使用，改测试包不会改变F5的内容。

收到整套更新包后才运行以下同步命令；**它会用所选包覆盖13份运行表和同名资源**，先用Git保存当前填写成果。新增程序接入表不被覆盖。该脚本需要Python及Pillow，游戏启动无需它：

```powershell
python tools/prepare_system_test.py --source '新测试包目录'
```

`source_manifest.json`记录本轮接收的56份文件哈希及3份SVG兼容PNG的来源。日常编辑Excel后，哈希表示接收基线，不再表示当前编辑结果；以Git提交区分后续版本。严禁把作者本机绝对路径填到运行资源列。

## 表头、类型与行规则

沿用当前模板，**不要重命名工作表或程序字段**：

| 格式 | 数据从哪一行开始 |
| --- | --- |
| 关卡、系统参数、接入补表 | 第1行中文说明；第2行`##var`程序字段；第3行`##type`；第4行`##group`；第5行数据 |
| 调查表 | 同样四行，A2为`##`，第3行带“类型/单位/必填”说明，第5行数据 |
| 文案和演出资源表 | 保留原中文首行表头，第2行数据，不改造成四行表 |
| 目标导航表 | 保留原模板前三行说明、第4行中文列名，第5行数据 |

- ID全部使用文本格式，区分大小写，禁止以Excel显示格式代替真实值。`5000201`也是文本ID；不要变成科学计数法或`.0`。ID跨表引用必须完全一致。
- 数值填写数值，不附“px”“ms”“%”。音量`70`表示70%，透明度等0—1字段填写`0.85`。整数不得带小数；禁止NaN、无穷。
- bool填`0/1`或`true/false`，不填“是/否”。必填空值会被拒绝；可选空格应清空单元格，不填`null`、`无`或横杠。空字符串、0、false含义不同。
- 多ID字段用英文分号`;`；正文换行用Alt+Enter。别把正文逗号当成ID分隔符。
- 读取只消费指定数据页。`_填写说明`、资源需求、操作用例、`#备注`列不执行。完全空行忽略，禁用行不应再被其他有效记录引用。
- 四行模板A列`#`开头作为注释；旧测试包显式`data_scope=test`的带标记行，在测试入口允许载入。新增有效测试行统一A列留空、scope填`test`，不要依赖历史例外。`test`入口包含`runtime`公共行，普通入口排除`test`行。
- 不写Excel公式、宏、脚本或依赖外部链接。通用/关卡读取会拒绝公式和错误单元格；其余适配器仍需作者检查，不能用缓存公式值作为配置数据。
- 类型行的`!`/“必填”会检查空值；枚举、引用、范围由对应系统校验。Excel的下拉、注释或`range/set`说明不是全部都能被通用读取器自动执行。

## 接入补表字段

每页第1行是说明，第2行是程序字段；ID为该页唯一，以下一对多页按组合区分。

| 页签 | 需要填写的内容与约束 |
| --- | --- |
| 资源绑定 | `resource_id → path`；用于原表留给程序的载体和动作资源。原表已有非空路径时保留原引用；不要另造同义资源ID |
| 流程入口 | 必须各一条`id=opening/closing`，`text_id`引用实际文案文本 |
| 事件接续 | `event_id`存在于文案事件；`target_text_id`与`return_action`二选一。返回动作仅`investigation/commit_entry/ending` |
| 阅读选择 | `source_text_id + order`唯一；`label_text_id`取文案按钮文字；`target_text_id/target_event_id`二选一。不会默认替玩家选择 |
| 立绘离场 | `text_id + character_id`，该句显示时移除该人物；同人物换位不能留下第二个副本。时长取演出表准确文本定位 |
| 观察效果 | `observation_ref`引用调查观察；`transfer=true`在成功确认提交后取走物件，取消检查不能隐藏 |
| 目标运行 | 目标`id`取目标表，`visible_condition/closed_condition`取核心条件；关闭条件空表示不自动关闭 |
| 事项运行 | 事项`id`、`goal_id`、`done_condition`；`go_kind=question/entry`，`go_id`引用真实问题或调查入口；`basis_refs`用分号 |
| 依据运行 | `id`；`kind=material`时仅填准确`content_id`，`kind=statement`时仅填准确`statement_id` |
| 补充条件 | `id + or_group + kind + ref`；同组AND，组间OR，组号从1连续填写。支持的原子类型沿核心条件，事实必须有真实生产入口 |
| 场景附加对象 | `id/scene_id/kind/target_ref/image_path/x/y/w/h`；`kind=character/cat`；人物目标取关卡人物ID，猫目标取猫互动ID；几何沿调查画布 |
| 回应头像 | `node_id → image_path`，只替换指定核心回应的临时头像，正常退出恢复 |
| 核心动作声音 | `id/effect/at_ms/event_id`；effect仅`support/partial/break/insight/collect/error/failure/retry`，时点为非负毫秒，同一动作可配多条 |

数字文案人物`1000002`和关卡人物`TEST_1014_CLERK`属于两个目录：文案立绘用前者，调查人物绑定用后者，不把显示名称“洛恩”当作主键。

## 图片与坐标

资源路径以包根为基准，例如`assets/objects/paper.png`实际解析到`game/data/system_test/package/assets/objects/paper.png`。程序场景载体使用已存在的`res://examples/hosts/test_front.tscn`。PNG大小和路径大小写都应与磁盘一致；独立可取物件不要烘进背景。

| 显示用途 | 坐标约定 |
| --- | --- |
| 本包调查图片/热点/附加人物猫 | `1600×900`逻辑画布，左上原点，x向右、y向下。图片和热点分别填写，共用完整窗口等比缩放居中的画布；问题列表和目标面板覆盖在上层，不压缩画布 |
| 物件图片 | 调查“对象图片”的`image_x/y/w/h`，contain保持比例，`draw_layer`控制图层 |
| 点击区 | “热点映射”的`x/y/w/h`、`hit_priority/focus_order`；有图不等于自动有热点 |
| 通用旧“图片布局” | `1280×800`逻辑画布；保留标题、暂停、材料卡等用途。本包已启用调查画布，调查背景/物件以调查表为准，旧布局不重复绘制 |
| 地图 | 图内逻辑`map_width/map_height`，棋盘原点和`cell_size`同单位；`grid_col/grid_row`从0起，点击宽高为图内尺寸 |
| 猫近景 | 猫展示表的0—1归一化屏幕框与头部框；不套用调查1600坐标 |
| 文案舞台 | 左/中/右三槽，由舞台节点负责缩放；正文表指定位置和人物，当前槽矩形由程序维护 |

本包3份SVG实际嵌了PNG，Godot导入会丢掉嵌入图片。准备脚本按原裁剪和画布生成`generated/assets/system_test/map/*.png`，运行自动使用兼容图，原SVG保留。后续新素材优先直接交透明PNG；更换此类SVG后重新生成并导入。

调查画布与开场采用相同的等比缩放规则：1280×800窗口中1600×900画布显示为1280×720，上下各留40；1920×1080窗口显示为1920×1080。策划始终填写1600×900逻辑坐标，不要为不同窗口分别改坐标，也不需要通过改图片尺寸补偿页面缩小。背景、人物、物件和热点同组缩放。

对白显示完整后，点击背景、人物或正文区域继续，Enter/Space也可继续；对白右侧不再放“继续”按钮。选择、记录、菜单等控件执行各自操作，不同时推进对白。该行为由文案页面处理，策划仍只填写正文及跳转/选择关系。

## 玩法、来源和状态

- 一个材料身份可有多个`content_id`版本。新版本填`previous`，出示、保存与依据都指准确版本；不能只写“最新版”。两槽不能放同一身份的两版。
- `contains`表示包含指定材料即可，`exact_set`要求所选集合完全相等。不匹配进入不足；只对配置了明确错误关系、且已知前提满足的主动出示扣容错。
- 充分关系填写稳定`result_key`、确认范围、动作组和提交时点。等价解共享成果身份。`enter/continue/collect`分别由进入回应/主动继续/主动收下提交，动画结束不代替确认。
- 调查“观察引用”绑定入口、准确内容版与真实来源；检查正文确认才提交。普通交谈接文案时，完整读完再`commit_entry`发材料，未读句子不能预先进入已听记录。
- 目标表“已完成/未完成”、猫首见、材料已拥有、蓝盒已取、文案已读等是运行状态，不从测试快照灌入新游戏。每个条件都需能追溯到真正生产它的入口/结果动作。
- 地图连接为单向，返程另配一行，可并行公开多个满足条件的地点。普通移动、手册回看、猫退出不额外生成普通自动档。
- 存档序号由成功落盘统一分配，策划不填。修改不兼容ID、版本、证明关系或流程时更新案件`content_revision`，用新游戏测试；旧档拒绝混读并保留文件。
- 设置首次/恢复默认来自Excel，已有设置文件优先；调查读档不覆盖音量。手动栏可配1—10；自动、指认保护、结局续播数量及容器schema本版固定为1。

| 导航`menu_open_ms/menu_close_ms` | 目前页面即时开关，参数保留，未接菜单过渡动画 |

| 调查画布/热点/图片、观察与话题 | 已接；部分“每行字符数/可视条数”仍采用现有自适应布局，不按表逐项定版 |

| 文案状态赋值 | 当前阅读选择按明确分支接续；不把制作说明中的`10000111=1/2`解释成通用状态写入程序 |

## 策划实际填写流程（从零制作一段可玩内容）

策划只需要维护运行包中的Excel和包内资源，不需要改GDScript。每次制作建议按下面的顺序填写，先把内容身份和引用关系建立起来，再补表现，避免出现“文字有了但程序不知道何时执行”的孤立行。

1. **建立案件骨架**：在`关卡内容_程序读取表`填写案件ID、内容版本、起始地点、地点名称、人物名称和稳定ID。ID一旦被其他表引用就不要改名；内容改版时递增`content_revision`。
2. **建立材料和说法**：先填材料身份，再填材料内容版本、标题、摘要、正文、来源观察和历史版本`previous`。人物说法要绑定人物、说法版本、原话正文归属材料；正文必须确实包含说法原句。
3. **建立调查入口**：为每个可调查对象或人物话题填入口标题、正文、地点、条件、来源、取得的材料、听到的说法和产生的事实。材料不能在调查入口中直接产生推论，推论必须由后续核心问题主动收下。
4. **建立问题和出示关系**：先填问题类型（人物说法或推理问题）、目标、地点和开放条件，再填每条出示关系。每条关系明确材料版本、`contains/exact_set`、反馈类别、结果节点、证明引用、确认范围和提交时点。推理问题只填`question_text_id`，不要填人物说法或更正字段。
5. **建立结果和后续条件**：在结果节点中填写玩家看到的回应正文、动作组和`enter/continue/collect`时点；在条件表中引用真实生产者（已取得材料、已听说法、已完成问题、调查观察或结果事实）。每一个事实都必须能回溯到调查入口或结果动作。
6. **配置地图与调查画面**：填写地图地点、连接、棋盘坐标和场景载体；再填调查热点、对象图片、人物/猫附加对象。图片路径写包内相对路径（如`assets/objects/paper.png`）或有效`res://`PNG路径，调查坐标按`1600×900`填写，热点矩形与图片矩形分别填写；有图不代表自动可点击，必须另有热点行。
7. **配置文案与跨系统接续**：在文案表填写人物、场景、正文、跳转和选择；在演出资源表绑定头像、准确文本和时长；在程序接入表填写开场/收束、事件接续、观察效果、目标事项、回应头像和声音。制作说明只能作为备注，不能代替动作、目标、资源、时长和等待方式。
8. **配置通用系统文字和表现**：初始化、存读档、设置、声音、手册、猫和目标导航表只填写各自系统的参数与文字引用。核心玩法的两槽、底栏5张、网格6×2、3次容错等属于本版本固定协议，不能通过改表把布局改成另一套玩法。
9. **先做最小验证，再做完整回归**：Excel保存后先只改一条正文或一张图片，在Godot打开`game/examples/system_test_demo.tscn`按F6，启动新游戏确认画面确实读到新值；再沿“新游戏→文案→调查→出示→结果→收下→地图→存档/读档”完整走一遍。重点测试取消、返回、重复确认、错误出示、未满足条件和读档后的最新进度。统一回归命令为`./tools/project.ps1 -Action test -Godot '引擎路径.exe'`，从标题错误正文或`.local/`日志定位工作表/行/ID；剧情含义、听感和显示容量仍需人工核对。
10. **交付版本**：提交运行包内Excel、包内图片/声音、程序接入表和必要导入文件；不要提交玩家存档、`.godot`缓存、WPS临时锁文件或个人电脑绝对路径。

### 一行配置的检查方法

填写每一行时都问自己四件事：**它是谁（稳定ID）？它在什么时候出现（地点/条件/提交时点）？它产生什么（材料、说法、事实、结果或显示）？它引用的对象是否在其他表真实存在？** 四个问题有任何一个答不上来，就先不要把该行交给程序测试。
