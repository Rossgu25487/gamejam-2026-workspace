# 核心玩法实现清单

依据：`game/代码开发需求/代码生成规范.md`、核心玩法系统策划案／说明／配置表、功能系统架构与开发顺序，以及共用手册与保存边界。2026-10-10 用户确认正式地点和人物尚未输出，首段允许使用占位符。

## 本轮接入

- [x] page → service → main：调查、选材、阅读、反馈各有节点和脚本；Main 只连接模块。
- [x] 四行表头导入 runtime 规则和唯一功能文字；test 与禁用模板不进入游戏。
- [x] 明确标记的占位首段：材料取得、普通问话、人物说法与自主推理入口、后续条件。
- [x] 材料身份、实际已获版本、同版路径去重、已读与重点；不自动补旧版。
- [x] 两个独立槽、单份提交、五卡底栏、六列网格、分类排序和独立浏览状态。
- [x] 精确目标与问题草稿；关系优先级、局部补充、明确错误和不足。
- [x] 结果组整体提交与去重、主动收卡、完整来源冻结、前次确认依据。
- [x] 每题三次容错、尝试去重、失败返回和主动重试。
- [x] 只读检视、精确版本与多层来源返回；页面自己的输入与焦点处理。
- [x] 反馈等级与业务时点分离，暂停／跳过／减弱动态不替代业务动作（当前纸面白模）。
- [x] 完整联合快照、内容版本校验、合法保存边界、结果正常返回才请求自动保存。
- [x] 隔离用户存档的业务与页面回归；保留独立计数器夹具。

## 内容与资产边界

本轮占位包仅用于接通首段，不作为正式案件。正式场景、人物、材料原文、证明范围、条件、结果组和资源统一在内容配置中替换；未交付的立绘、背景、纸纹、碎裂／翻页特效与声音不能宣称完成。反馈节点先实现可暂停、可跳过的文字／纸面白模与稳定终态。

## 接口约定

- `CoreGameplayService` 是材料、草稿、容错、结果与来源的唯一更新者。
- 页面通过稳定方法和精确引用提交动作，不直接修改服务状态。
- `GameSessionService` 组合／校验卡牌和导航快照。保存服务使用验证器，在成功校验后才交给 Main 替换会话。
- 结果去重键由案件、调用、时点、结果组组成；容错独立记录尝试；高潮独立记录已处理标识。
- 普通自动存档只由新游戏初始点与玩法成功正常返回请求。暂停、直接离开、阅读和收卡均不补档。

本轮验证：核心规则与页面状态133项、Control鼠标键盘与布局59项通过；计数夹具与工作台合同、导航居中与焦点、重复确认及真实退出均通过。已实际渲染并核对1280×800与1920×1080白模画面。人工键鼠、独立导出包和跨机器验收未执行。
