# 协作空间使用指南

本说明供全队直接使用。协作空间的界面在 Godot 编辑器里打开；GitHub 存放团队文件、接收修改和管理成员，Codex 在各人的本地工作目录里辅助完成任务。

## 1. 从哪里进入

| 要做的事 | 入口 |
|---|---|
| 查看项目、最新文件和说明 | [GitHub 仓库首页](https://github.com/Rossgu25487/gamejam-2026-workspace) |
| 下载对应岗位的工作流 | [岗位工作流目录](https://github.com/Rossgu25487/gamejam-2026-workspace/tree/main/岗位工作流)；[完整分发包](https://github.com/Rossgu25487/gamejam-2026-workspace/raw/refs/heads/main/分发包/八人岗位工作流_v2.zip) |
| 接受已发给自己的邀请 | [邀请入口](https://github.com/Rossgu25487/gamejam-2026-workspace/invitations)，使用被邀请的账号登录 |
| 队长邀请成员、确认是否加入 | [协作者管理](https://github.com/Rossgu25487/gamejam-2026-workspace/settings/access) |
| 打开实际协作界面 | 用 Godot 导入本地仓库里的 `game/project.godot`，点击顶部“协作空间” |
| 让 Codex 协助工作 | 在本人的仓库或独立岗位目录打开 Codex，提供自己的岗位工作流 |

仓库已公开，所有人可以直接查看和克隆。接受协作者邀请后，成员才能以自己的账号向团队仓库推送修改。岗位选择与 GitHub 权限分开管理，具体写入范围遵循岗位分工。

## 2. 第一次使用

1. 取得本人的岗位 MD，发给自己的 Codex，使用文档开头的启动提示。Codex 会检查已有工具和文件，再补必要准备。
2. 每个人在自己的电脑上克隆一份仓库；已有副本直接继续，避免重复覆盖。建议让 Codex 协助完成下面的操作：

   ```powershell
   git clone https://github.com/Rossgu25487/gamejam-2026-workspace.git
   Set-Location -LiteralPath gamejam-2026-workspace
   ```

3. 在该仓库根目录打开 Codex，让它核对岗位、分支和现有修改，并建立或复用本人的工作分支。仓库根目录包含 `README.md`、`岗位工作流/`、`game/` 等内容。
4. 使用团队当前固定的 **Godot 4.7.2 Standard**。在 Godot 项目管理器点击“导入”，选择自己副本里的 `game/project.godot`，打开工程，等待首次资源导入。
5. 在编辑器顶部点击 **“协作空间”**，再从左侧选择自己的岗位。这里即可查看工作流、写交接、查看策划案。
6. 需要验证工程时按 **F5**；当前会运行“加 1／重置”的接口演练。停止运行后回到编辑器继续使用协作空间。正式游戏内容待命题和方案确定。

队长当前电脑的主工程位于 `E:\gamejam\game\project.godot`。队员使用各自电脑实际克隆位置，不照抄这个盘符。

可以直接交给 Codex：

> 我的岗位是副程序 A（gameplay，请按本人岗位替换）。请按我提供的岗位工作流接入 https://github.com/Rossgu25487/gamejam-2026-workspace。先保留并检查已有文件，核对本人分支，再帮助我打开本地 game/project.godot 和“协作空间”。请说明哪些已实际验证，哪些需要我操作。仓库已公开，尚未接受邀请也可先克隆和准备。

## 3. 三个工作页怎么用

| 工作页 | 主要操作 | 保存位置或结果 |
|---|---|---|
| 岗位工作流 | 阅读本人任务、负责路径、接入与完成要求；文字可以选择和复制 | 读取 `岗位工作流/` 中对应 MD，界面内为只读 |
| 岗位交接 | 记录本轮工作，点击“保存交接” | 写入本机 `workspace/handoffs/<role>.md` |
| 策划依据 | 查看入库文件；策划导入文档并指定当前采用版本 | 原件存入 `planning/inbox/`；当前指针为 `planning/current.json` |

顶部会显示当前依据、本机分支、提交号和修改状态。“仓库目录”“工作流目录”可打开对应文件夹；“加入说明”打开仓库 README。

**“刷新本机文件”只重新读取本地文件。**它不会从 GitHub 下载队友的修改；需要先完成 Git 同步，再刷新界面。切换左侧岗位也不会切换 Git 分支或本地目录。

存在未保存的交接草稿时，刷新会保留草稿。需要查看磁盘新内容时，先点击“复制草稿”保留文字，再“重载磁盘版本”并合并需要保留的内容。

## 4. 队长怎样上传策划案

1. 选择左侧 **“策划 / 队长”**，进入 **“策划依据”**。
2. 点击 **“导入原件…”**，选择 MD、TXT、DOCX 或 PDF。原文件保留，同名文件在收件箱中另加编号。
3. 在列表选中文档。UTF-8 编码的 MD/TXT 可以直接预览；DOCX/PDF 点击 **“打开所选文件”**，用系统软件查看。其他编码的文本也可用系统软件打开；需要内置预览时，保留原件，另存 UTF-8 副本后再导入。
4. 确认团队采用这一份后，点击 **“设为当前依据”**。导入和采用是两个步骤，当前选择会记录文件路径、内容校验值与版本信息。
5. 让 Codex 将该原件、`planning/current.json` 和本轮有关的需求说明一起检查、提交到本人分支，推送并交主程序合入 `main`。
6. 告知成员采用的版本。成员同步到相应提交后，点击 **“刷新本机文件”**，核对顶部依据与“策划依据”页。

GitHub 仓库现为公开，推送到仓库的策划原件也会公开可见。只提交可公开给团队使用的资料，账号凭据和不宜公开的材料保留在仓库外。

## 5. 每次工作按这个顺序

1. **开始前：**让 Codex 检查本人分支、未提交工作、当前依据和交接；保留已有内容，再同步本轮需要的共同版本。
2. **工作中：**按本人工作流处理负责内容。依赖队友的接口、资源或测试包时，写清需要什么以及由谁提供。
3. **结束前：**在“岗位交接”记录已做内容、文件位置、实测结果、未完成项、接收者和下一步，点击“保存交接”。
4. **交给团队：**让 Codex 检查本轮差异，只提交本人的任务文件与交接，推送本人分支并创建合并请求（PR）；主程序接入共同版本。
5. **接收队友更新：**取得已合入的版本，在自己的工作分支正常接入；再刷新协作空间，读取上游交接。发现冲突先保留工作并解决差异。

可以交给 Codex：

> 请检查我本轮的改动和岗位交接，完成与影响相称的验证。只提交本任务文件，推送本人分支并向 main 创建 PR，写清依据、改动、已测和未测。保留其他未完成工作；遇到真实冲突时说明具体文件并继续不受影响部分。

“保存交接”完成本机保存；推送本人分支后，队友可取得该分支；合入共同版本并同步后，队友才会在自己的工作区看到它。构建包、`.local/` 和其他已忽略文件不会随 Git 提交同步；大视频按团队约定另行交付，都应注明实际取得位置。

## 6. 八个岗位与换岗

| 岗位 | role ID |
|---|---|
| 策划 / 队长 | `planner` |
| 主程序 | `lead` |
| 副程序 A · 逻辑 | `gameplay` |
| 副程序 B · 界面接入 | `integration` |
| 美术 A · UI 组件 | `ui_art` |
| 美术 B · 二维图形 | `visual_art` |
| 测试 | `qa` |
| 运营 | `ops` |

成员可以换岗，通常无需重新发送 GitHub 邀请。队长明确新分工后，原成员保存并交接未完成内容和版本；新成员读取该岗位记录与工作流，在自己的独立目录和分支继续。

同机需要多个隔离岗位时，在主仓库目录运行，例如：

```powershell
./tools/start-role.ps1 -Role gameplay
```

把 `gameplay` 换为实际岗位。脚本返回 `Path` 后，在那个目录重新打开 Codex，再用 Godot 打开其中的 `game/project.godot`。它会复用已有岗位目录，保留修改；不会自动切换当前 Codex，也不会把旧岗位分支更新到最新 `main`。需要更新时，让 Codex 核对版本后正常同步。

每人一台电脑、各自一份克隆时，使用本人的任务分支即可。同一个目录同一时间由一个成员负责写入；GitHub 写入权限覆盖仓库，岗位目录由团队约定分工。

## 7. 常见情况

| 遇到的情况 | 处理方式 |
|---|---|
| Godot 顶部没有“协作空间” | 确认打开的是 `game/project.godot`；在 `Project → Project Settings → Plugins` 检查“协作空间”已启用，检查底部是否有加载错误 |
| 只下载了岗位分发 ZIP，找不到工程 | ZIP 仅含工作流说明；继续从仓库克隆完整工程 |
| “当前依据”显示待定 | 策划尚未指定方案。可以继续准备，正式任务等明确依据 |
| “设为当前依据”不可用 | 确认当前选择策划岗位，并已选择可读取的入库文档；其他成员按分工查看依据 |
| 保存交接提示磁盘内容已变化 | 先用“复制草稿”保留当前文字，再核对新内容。“重载磁盘版本”会放弃当前未保存草稿 |
| 看到旧策划案或队友的旧记录 | 先核对分支和提交号，完成 Git 同步，再点“刷新本机文件”；仍显示未保存交接草稿时，先复制保留，再重载磁盘版本 |
| 推送失败或无权限 | 确认邀请已接受，当前登录账号正确；已完成的本地工作保留，交给 Codex 定位具体原因 |

详细分支与同步规则见[加入与同步](加入与同步.md)，岗位归属见[协作协议](协作协议.md)。
