# 任务提醒

工作台可以生成提醒草稿，并打开对应 Issue。复制草稿、打开页面均不会发送消息；在 GitHub 发布评论后，提醒才会进入任务记录。

自动提醒通过 GitHub Actions 给任务负责人留下 `@用户名` 评论。成员开启 GitHub 邮件通知后，也可以通过邮箱接收。仓库无法代替成员打开邮件通知，工作台也无法确认邮件是否送达。

## 先准备任务

任务状态、负责人和截止日期都从 GitHub Issues 读取。原生 Assignees 优先；未指派时按 `role:` 标签查询 `workspace/manifest.json` 中已确认的成员。负责人不明的任务跳过，交队长补齐。

需要自动提醒的任务，在 Issue 正文中单独保留一行：

```text
截止时间: 2026-10-17T20:00:00+08:00
```

日期必须带时间和时区。正文有此字段时优先使用；重复、空白、日期不合法会跳过并报告。正文未填写时，才读取绑定里程碑的截止时间。两处都未填写则显示“未设截止”，项目总排期不会代填个人截止。

## 提醒规则

| 方式 | 发送范围 | 重复处理 |
| --- | --- | --- |
| 自动检查 | 剩余时间进入 72 小时或 24 小时窗口的未关闭任务 | 同一任务、截止时间、档位和负责人集合只提醒一次 |
| 手动指定 | 手动输入的任务编号，最多 20 个 | 同一 UTC 日期、任务和负责人集合只提醒一次 |

自动检查每小时第 17 分钟触发。GitHub 调度可能延迟；实际发送时重新计算剩余时间。晚到 24 小时窗口时只发该档，不连续补发两条。已经逾期的任务列为跳过，队长可查看后手动提醒；已经完成或取消的任务始终跳过。

待验收任务的评论提示“请确认验收进展与下一步”。当前负责人负责协调验收和接手人，系统不会把待验收描述成制作未完成。

手动提醒允许未设置截止的任务，但截止字段错误仍需先修正。UTC 日期在北京时间 08:00 切换；此规则用于防止重复点击。

## 本地预览

需要 Node.js 24。默认只读取公开任务、输出候选提醒，不创建评论：

```powershell
node tools/remind-tasks.mjs
node tools/remind-tasks.mjs --issues 4,7
node --test tools/test-remind-tasks.mjs
```

预览输出的 `action: preview` 表示候选内容。实际运行时还会核对最新状态、负责人和已有提醒。无有效截止的自动任务会显示 `no-deadline`；日期错误显示 `invalid-deadline`；逾期显示 `overdue`；无负责人显示 `unassigned`。

发送需要同时满足 `--send` 和环境变量 `TASK_REMINDERS_ENABLED=true`。令牌仅从 `GH_TOKEN` 或 `GITHUB_TOKEN` 环境变量读取，不写入命令参数、前端、仓库文件或日志。本地使用个人令牌时，脚本会通过 GitHub 查询实际发信身份；避免和 Actions 同时执行发送。

## 经授权后启用

当前代码完成和本地测试不代表已经启用提醒。上传本次改动、启用自动发送均按队长的本次明确授权执行。

1. 将已确认的提醒代码与工作流合入默认分支。
2. 在仓库 **Actions → 任务提醒 → Run workflow** 先运行预览。输入一个或多个任务编号；留空会按截止窗口检查。
3. 核对负责人、截止与提醒内容后，在仓库 **Settings → Secrets and variables → Actions → Variables** 设置 `TASK_REMINDERS_ENABLED` 为 `true`。此开关会启用每小时自动提醒；删除或改为其他值即停止自动发送。
4. 手动发送时填写任务编号，并勾选 `send`。只有开关与勾选同时生效才会发出评论。未启用开关时，勾选也只会预览。

GitHub 自带的 `GITHUB_TOKEN` 由工作流使用，无需收集团队成员邮箱或个人密码。预览工作只有读取权限；发送工作仅申请 `contents: read` 和 `issues: write`。工作流只接受定时和手动触发，不接受 PR 触发，手动和定时运行共享串行队列。

## 成员打开邮件通知

进入 [GitHub 通知设置](https://github.com/settings/notifications)，开启参与会话（Participating）的 Email，并确认通知邮箱已经验证。提醒评论保留在原任务内；成员可以从邮件或 GitHub 回到同一条记录。

## 失败和复查

在 **Actions → 任务提醒 → 对应运行 → 预览提醒对象 / 发送未完成任务提醒** 查看结果。`sent` 表示 GitHub 已返回创建成功的评论；`already-reminded` 表示同一发信身份已留下相同提醒。评论中的隐藏标记用于防重，普通成员复制的标记不会被当成机器人已发送。

遇到超时或评论响应不明，程序停止，且不自动重试 POST。先打开原 Issue 查看机器人是否已经留下评论，再决定重跑。重跑会重新检查标记；不要删除已发送评论中的标记。截止时间或负责人变更后，将按新的安排重新判断。

GitHub 在高负载时可能延后或丢弃定时运行；公共仓库连续 60 天无活动也会停用定时工作流。关键截止仍需队长查看任务进展。
