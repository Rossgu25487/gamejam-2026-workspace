# 雨夜借阅单试玩说明

这是按用户请求制作的虚构短篇示例，用来体验“填写配置表后程序直接读取”的流程。故事包含两个地点、一位管理员、两道问题，预计试玩5–10分钟，沿用现有白模界面。它不作为正式案件策划。

## 运行

在 Godot 4.7.2 打开本仓库的 `game/project.godot`，然后打开 `res://examples/rainy_library.tscn`，按 **F6（运行当前场景）**。点击“新游戏”开始。**F5仍启动原占位案例**。

也可以在仓库根目录运行：

```powershell
./tools/project.ps1 -Action example -Godot '本机Godot控制台可执行文件路径'
```

示例场景继承主场景，只指定自己的故事配置与存储目录；页面和规则仍使用同一套实现。Main只传入工作簿路径和标题，不判断故事ID或生成案件内容。

## 配置和保存

游戏直接读取 [雨夜借阅单.xlsx](../game/data/story/outputs/rainy-library-20261011/雨夜借阅单.xlsx)。15张表中已填入正文、人物原话、材料、条件、出示关系、结果动作和地点连接。“填写说明”末尾附有操作及解法。字段含义见[故事配置表填写指南](故事配置表填写指南.md)。

修改示例工作簿，保存后停止游戏，再按F6即可读取新内容。无需运行生成脚本或转换JSON。不兼容的内容修改应更新`content_revision`。

导出资源包前先保存并关闭Excel/WPS中的配置表，避免文件锁使Godot无法读取。导出预设只包含两份明确命名的工作簿，不包含Office临时锁文件。

示例独立使用`user://story-examples/rainy-library-v1/`中的存档和设置，原玩家档案保持原位。第一次点击新游戏生成初始自动档；充分结果正常返回调查、地点移动更新自动档。“菜单 / Esc”中可手动保存或读取，标题页“继续调查”读取示例最新有效档。

## 操作

每段调查正文读完后点击“返回调查”。进入人物说法核对时，先点击原话选择目标；点击材料卡查看正文，再点击“选用”放入出示槽，最后点击“出示”。自主推理的问题自动选定目标，但同样需要选用材料。

“全部撤下”清空材料槽，“全部材料”展开卡牌，I打开办案手册。表现可以等待结束或点击“跳过表现”；跳过只结束表现，推论仍须主动“收下推论”。随后点击“继续”返回调查。Esc或“菜单 / Esc”打开暂停菜单。

## 解法

1. 在借阅柜台依次检查借阅簿、书架标签和招领夹，询问管理员林岚。
2. 打开“核对晚间借阅说法”，点击原话“七点以后，没有人借走A-17。”。
3. 想试错误反馈，可只选用“A-71招领单”并出示：它对应另一份档案，容错从3降到2。点击重新选材，再全部撤下。
4. 只出示“晚间借阅簿”得到局部成立，不扣次。点击“补入 A-17书架标签”形成完整证明。也可以一开始就选用这两份材料再出示。
5. 收下“七点后的借阅”推论，点击继续，然后进入档案室。
6. 检查归还凭条，打开“确认A-17的去向”。选用“七点后的借阅”与“A-17归还凭条”并出示。
7. 点击继续确认结果，调查页显示完成提示：A-17于19:12借出，20:05归还后暂存B3柜。

两道问题均配置了A-71单张出示的明确错误关系。其他未匹配组合显示不足，不扣容错。最终证明同时要求第一问已经真实确认，持有一张同名卡不能替代前次确认记录。

## 开发检查

`game/tests/story_example_test.gd`用真实控件鼠标事件走完错误、局部补材、推论收下、地点切换、阶段完成、手动保存、两次读取与标题继续。测试每次注入独立目录，避免污染试玩档。统一`tools/project.ps1 -Action test`包含这项检查。

实际渲染并截取画面：

```powershell
godot --path game --script res://tests/story_example_test.gd --quit-after 3600 -- --capture
```

它是自动输入测试，独立人工试玩和跨机器验收仍由实际试玩者完成。示例展示现有调查推理范围，多段对白、立绘、背景切换、配音及结局演出未在这个短篇中接入。
