# 工作台维护

网页地址：https://rossgu25487.github.io/gamejam-2026-workspace/

## 共同数据维护一处

- **工程版本**读取 GitHub `main` 当前提交；可试玩包读取 GitHub 最新正式 Release，未发布时为空。网页不会由成员手填另一套版本号。
- **任务**读取仓库 Issues，排除 PR。普通 open 是待完成；`status:doing` 是进行中；`status:review` 是待验收；以 completed 关闭是已完成；以 not_planned 关闭是已取消。
- **岗位**使用 `role:<id>` 标签，岗位清单与已确认成员来自 `workspace/manifest.json` 的 member。具体任务优先显示 GitHub Assignees；为空时注明“岗位负责人”并显示已确认成员，不伪造原生指派或已接受邀请。完全未知时才显示待分配。
- **阶段**使用 `phase:preparation` 或 `phase:production`。命题前主要推进准备任务；已有职责占位不表示正式制作已开始。
- **排期与阶段说明**由队长维护 `workspace/roadmap.json`。日期含北京时区；`kind:suggested` 是建议，`is_deadline:true` 是截止。时间到达不等于工作完成。

任务完成前应有交付位置、版本和实际验收结果。需要接收者验收时先标待验收。取消的任务不得计入完成数量。准备任务的完成数量也不能当成正式游戏完成度。

## 发布方式

`site/` 是无后端的静态网页，发布到独立 `gh-pages` 分支，由 GitHub Pages 托管。发布内容只包括页面、样式、脚本与数据快照，不包括本机文件和凭据。

构建过程读取版本、任务与发布记录，写入 `site/data/snapshot.json`，并复制浏览器可复用的数据模块。生成文件已被 main 忽略。构建失败保留上次成功的页面，命令明确报错，不生成假空任务列表。

打开网页时先呈现发布快照，再自动读取 GitHub 当前数据；手动刷新执行同一过程。工程、任务、发布记录及同一提交的岗位和排期全部取得后一起更新，失败时保留已有数据和时间并说明未能刷新。浏览器不保存 GitHub 密钥，不伪装直接更改共享任务；任务修改在 GitHub 登录界面或成员已授权的 Codex 中完成。任务和 main 内容变化无需重新发布网页；前端功能或样式修改需要重新发布。

## 本地构建与检查

使用 Node.js 24，静态前端与数据构建均无 npm 依赖：

```powershell
node --test tools/test-dashboard.mjs
node --test tools/test-dashboard-progress.mjs tools/test-remind-tasks.mjs
node tools/build-dashboard.mjs
```

直接运行构建默认访问公开 API。已登录 GitHub CLI 时，可以传 `--gh '本机gh可执行文件路径'`，通过其正常 API 调用构建。发布脚本会优先使用 PATH 或本仓库 `.local/github-cli/bin/gh.exe` 中已登录的 CLI，避免匿名接口限额影响交付；不提取凭据，也不向网页分发令牌。

构建后运行 `node tools/preview-dashboard.mjs`，打开输出的本地地址；需要更换端口时在命令后加端口号。服务只监听 127.0.0.1，只提供 site/ 文件，不发布内容。直接双击 HTML 的 file 协议无法可靠读取 JSON。实际修改前端后，检查桌面与窄屏、筛选和搜索、没有试玩包、刷新失败等受影响路径。节点日期、任务状态和版本分别核对源记录。

浏览器冒烟脚本为 `tools/smoke-dashboard.mjs`，需要本机已安装 Playwright 和 Chromium；检查工具不属于网页运行依赖。先构建并启动预览，再运行：

```powershell
node tools/smoke-dashboard.mjs --url http://127.0.0.1:4179/ --playwright '本机 Playwright 模块目录' --browser '本机 Chrome 或 Chromium 可执行文件'
```

使用 Playwright 自带浏览器时可省略 `--browser`；项目环境能解析 Playwright 时可省略 `--playwright`。脚本将 GitHub 数据和外链全部替换成测试响应，禁止远端写入；它检查真实页面操作，不发送评论或触发工作流。结果和必要截图写入忽略的 `.local/dashboard-review/`，单独的真实只读检查用于核对当前仓库数据。冒烟结果见[工作台验证记录](../qa/工作台冒烟测试.md)。

取得用户对本次具体修改的上传与发布授权后，才推送已确认版本并同步到 main；随后用有团队仓库写入权限的本人身份发布：

```powershell
./tools/publish-dashboard.ps1 -AuthorName '本人Git显示名' -AuthorEmail '本人Git提交邮箱'
```

已配置 Git 提交身份时可省略这两个参数。发布工具使用独立临时索引，只推送静态站点分支，保留当前分支、暂存区及游戏中的未提交修改。GitHub 仓库 Settings → Pages 的来源设为 `gh-pages` 分支根目录。

## Godot 与历史资料

Godot 插件只加载 `workspace_home.gd` 的快捷页；旧面板与原件处理代码仍保留供历史资料和已有检查使用，日常不再加载长文或三个编辑页。插件继续从导出游戏中排除。

岗位 MD 已单独分发，保留原文件作为 Codex 的职责与操作参考，网页首页不重复展示。旧版界面路径以当前[使用指南](协作空间使用指南.md)为准。

`workspace/handoffs/` 保留本人的任务链接、分支与未提交工作等恢复线索；状态与验收记录维护在任务里。此前 Godot 三页的测试记录仅说明当时实现的行为，不代表新网页已经通过全部检查。

## 本次界面约定

任务概览与列表先共同筛选岗位、阶段和搜索内容，再按状态切换。URL 保留当前视图，localStorage 仅保存选择的岗位；这些偏好不影响共享任务。团队工作流和资料链接绑定显示的 main 提交，避免混入未发布草稿。

全队进度按阶段独立计算，成员待办按同一阶段统计，忽略个人列表的搜索条件。负责人沿用原生 Assignees 优先、岗位成员备用的规则，多人共同任务在全队总数中只计一项。

提醒按钮仅生成可审阅的评论草稿；定时发送由独立 [GitHub Actions 工作流](../.github/workflows/task-reminders.yml) 完成。前端不保存令牌。具体截止解析、开关、人工触发和运行失败处理见[任务提醒](任务提醒.md)。
