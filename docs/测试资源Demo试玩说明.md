# 蓝盒交接测试 Demo

## 启动

使用 Godot **4.7.2 Standard** 打开 `game/project.godot`，在文件系统中打开 `game/examples/system_test_demo.tscn`，按 **F6（运行当前场景）**。F5仍运行原主场景。

也可在仓库根目录的 PowerShell 执行，替换引擎路径：

```powershell
./tools/project.ps1 -Action system-test -Godot '你的Godot控制台程序路径.exe'
```

运行不需要 Excel、WPS 或 Python。配置在启动时读取，修改 Excel 后先保存、停止游戏，再运行。测试包已经放入工程，其他电脑无需准备原策划目录。

本入口存档、设置和已读记录独立保存在 `user://system-test-bluebox-v1`，不改原占位案件和雨夜示例的进度。用新游戏从开头开始；“继续”读取本入口最新有效保存记录。首次新游戏自动档包含开场位置。

## 成功路线

1. 标题打开设置，拖音量、试听、开关静音/减弱动态，恢复默认后返回。默认音量为100/70/60/80，步长5。
2. 选择新游戏、确认开始。正常阅读开头三场及功能演示；等正文完整显示后点击背景、人物或正文继续，也可按Enter/Space，对白右侧没有“继续”按钮。选择“再读刚才两段”可以测试实际已读后的加速/跳过。最后选择“开始交接演练”。
3. 前厅点击洛恩，在话题中选择“询问蓝盒”，完整读完取得交接单初版和原话初版。点击柜台交接单，确认检查；再次点击可补查背面取得第二版。墙上门禁记录、柜台红盒单分别检查确认。
4. 进入“蓝盒已经送到柜台了吗？”，选用交接单初版，点击“出示”，等反馈后点“继续”，完成第一问。第二版也属于充分解。
5. 可点击猫，摸头、暂停/继续、返回，再次进入对比回应。猫不发材料，本次未配呼噜声。此时地图中的后室已公开但尚不可前往。
6. 进入“核对储物间开门的说法”，先点击人物原话选定核对目标。单独出示原话材料只会不足；重新选材后出示门禁记录。可以附带交接单，但实际证明依据只有门禁记录。等击破和完整回应后点“继续”。可选补谈“追问借出的钥匙”，保留原话和更正版。
7. 地图选后室，点“前往”，观察棋子移动后进入后室。可以来回测试，进度不清空。检查流转记录，并检查确认取走蓝盒；重访时蓝盒图片、热点、提示一同消失。
8. 进入“蓝盒经过什么路线到了后室？”，选交接单初版＋流转记录。打开菜单在手动栏保存为 **S0**，记下实际栏位；换第二版后读取S0，应恢复初版槽位和原有进度。
9. 撤下交接单，只出示流转记录，得到局部成立。补证选交接单第二版，进入推论待收。可以查看准确版本和来源；此时不能保存。主动点“收下”，再等反馈并点“继续”，推论才完成返回，更新普通自动档。
10. 打开手册、目标回顾，检查6个材料身份、旧版/新版与证明来源。读取最新自动档确认不重发推论或关键表现。
11. 后室左侧问题面板点击“确认结束交接演练”，读完测试收束及原尾声。列表较长时滚动该面板；调查背景、人物和热点保持在完整窗口画布上。

## 错误支线

读取S0，撤下两个槽，只选红盒单出示。前提是已检查红盒并知道箱号不同。每次主动重新出示扣一次，容错3→2→1→0。普通“不足”或“局部成立”不扣容错。返回调查后重进仍为0，只有主动“重试”才恢复3次；再用交接单第二版＋流转记录完成。
