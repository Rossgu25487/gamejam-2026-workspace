## 2. 在仓库中接手

1. 按[加入与同步](../docs/加入与同步.md)从本人独立 clone 或 worktree 根打开 Codex，先读根 `AGENTS.md`、`README.md` 和当前阶段、角色路由；角色 ID 为 `ui_art`。不依赖其他电脑路径、全局 Skill 或历史对话。
2. 只读检查当前分支、未提交改动和本轮资料，核对主程序公布的共同 main 提交号。使用 `codex/ui_art/<task>` 分支；同机隔离可从主副本运行 `./tools/start-role.ps1 -Role ui_art`，进入返回的 `.local/roles/ui_art` 与 `codex/ui_art/workspace`。已有 worktree 只验证后返回，不覆盖或自动更新；多人不共写同一目录。
3. 读取 `planning/current.json`，active 时核对策划路径与 sha256；任务同时引用工作分支/提交号和需求 ID，revision 只作该分支的局部修订。原件哈希变化交 planner 核对后重新指定。当前准备夹具引用 [PREP-001 / prep-v1](../docs/接口与交接.md)，pending 不推定正式游戏规则。
4. 首次最多集中询问 3 个实质缺项，已有信息直接复用；提问期间继续不依赖答案的本地准备。未确认外部来源就地待核，避免停下全部工作。
5. 主要写入范围：`game/art/ui/` 和 `game/ui/theme.tres`；不改 `counter_view.tscn`、交互脚本或共享设置。公共文件或接口变化先说明 owner、生产者、消费者、兼容性及接入顺序；已有授权内直接推进，不增加逐次审批。
6. 唯一状态与交接记录是 `workspace/handoffs/ui_art.md`。可在 Godot“协作空间”编辑本人记录；保存只更新当前工作副本。提交本人分支和 PR，由主程序统一接口与分支合并，下一位拉取新 main；常规已授权小改动不增加逐次审批。

## 3. 先核对规格和可用工具

- 先读当前主题与已有 UI、已给风格和实际窗口规格。保留原有成果，复用同一计数界面。
- 使用本人熟悉且能交付可编辑文件的工具，不要求同时安装多种软件。缺图形操作能力时说明可完成部分和最少人工步骤。
- 本轮只需一个中性面板布局和一个按钮组件，用于数值、增加和重置；状态按实际接入需要准备。
- 明确源尺寸、显示尺寸、透明背景、必要状态、导出格式和接收位置，写入本人交接。
- 与 visual_art 对齐颜色、轮廓和图形放置区域；正式美术风格待命题后确定。
- 字体来源、许可与所需中文字形先核对；未核清的字体不自动打包分发，相关项待核，其他布局继续。
- UI 场景布局由 integration 实现，你提供可编辑参考；主题颜色、字号和样式只在约定的 `theme.tres` 修改，先核对实际资源结构。

## 4. 制作、导出与接入

1. 在 `game/art/ui/` 维护源文件，保留图层、对象和独立文字；源文件的真实可编辑范围如实说明。确需区分源稿和导出时再按需求分子目录。
2. 为面板和按钮保持一致的边缘、对齐与状态位置，数值和按钮文字采用原生控件或独立文字对象。
3. 按规格将必要导出放入 `game/art/ui/` 的约定位置；可直接接入的原生 SVG 无需额外复制为导出稿，不逐轮复制整个资源包。
4. 将布局参考、尺寸、状态对应和更新方法写给 integration。主题资源变更注明哪些控件受影响。
5. 在源文件与真实运行界面分别检查字形、间距、对齐、裁切、透明边缘、缩放和操作状态。
6. 资源问题只改自己的源文件、导出或主题；节点布局和引用配置问题交 integration。
7. AI 资产记录工具、输入来源、用途和人工修改；单层图片不声称具有完整分层结构，需要编辑的 UI 文字保持原生。
8. 来源不明的外部元素就地待核，可用自有占位继续。正式使用资格与来源声明留给明确的本届规则判断。

## 5. 验证与交付

交付可编辑源文件、必要导出、实际主题变更和一份岗位记录，说明规格、许可/AI 状态、接入路径与检查结果。
至少查看约定大小下的布局与按钮必要状态；和 qa 或 integration 确认实际运行结果。
只有导出成功或静态图正常时，记录“资源已检查，运行接入未执行”，不称界面已验收。
一轮合并相关修正后复查受影响内容；满足当前规格即可交付，不追加整套审美改版。
无法打开编辑器时交付能够检查的文件与人工步骤，保留真实限制。

## 6. 交付、恢复与正式切换

- 更新 `workspace/handoffs/ui_art.md`：需求 ID/依据版本、实际文件、相关提交或包版本、通过/失败/未执行、卡点、接收者、下一步。必要证据放指定产物目录，不逐轮另造报告。
- PR 或本地交接在已有授权内自主完成；未经明确授权不向他人发送消息，不代替队长正式上传。界面显示的角色不授予修改他人文件的权限。
- 恢复时先读本人记录，比较当前依据与主程序集成 main 的相关变化；保留未完成工作后正常同步需要的更新，不 reset 脏目录。只复核受影响部分，未变化的通过结果可复用；同因失败且无新信息时停止原样重试，保留成果和继续条件。
- 只有收到命题、当前方案、本人任务与剩余工时后才切换正式制作；先核对练习成果的复用资格，再替换对应内容，不由日期自动启动。
- 独立投放：若只收到本 MD、尚无团队仓库，先盘点环境、已有成果和接收要求，复用独立练习位置与一份记录；取得仓库后转入上述路径，不另造重复工程。原件、版本、验证和权限边界继续适用。
