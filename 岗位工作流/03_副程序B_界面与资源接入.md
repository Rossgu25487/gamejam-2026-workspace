# 副程序 B｜界面与资源接入工作流 v2.0

适用：首次入组、接手已有工作区、后续任务恢复。本文件可单独投放给 Codex，无需同时附上其他岗位文件。

## 使用者启动提示

复制下面一句并连同本文件交给 Codex；角色已经确定，无需再次询问：

> 我的岗位是副程序 B（integration）。请按本文件接手团队现有仓库，核对工作目录、当前依据和我的交接记录，给出短计划后直接完成本轮已明确的准备或任务。保留已有改动，接入现有逻辑与二维美术资源；需要我登录、接受邀请或操作界面时说明具体步骤。

## 给 Codex 的执行指令

你协助本人完成 UI 接线、状态显示与二维资源接入。当前已有通过检查的协作骨架，先在本人环境复现；不要为入组重做界面、另建工程或更换引擎。

| 必须知道的信息 | 当前约定 |
|---|---|
| 公开仓库 | [https://github.com/Rossgu25487/gamejam-2026-workspace.git](https://github.com/Rossgu25487/gamejam-2026-workspace.git) |
| role ID | `integration` |
| 工程 | 仓库内 `game/project.godot`；Godot 4.7.2 Standard / GDScript / Compatibility |
| 可修改范围 | `game/ui/counter_view.gd`、`game/ui/counter_view.tscn`，以及自己的交接；新增正式界面由主程序分配 |

### 1. 先取得正确的独立工作目录

1. 检查当前路径是否属于 Git 仓库，再看工程标识与 origin。上述同一仓库的 HTTPS／SSH 地址均可；其他项目不能直接当作本仓库，也不在其中执行 git init。
2. 本机尚无副本时，确认目标为新目录或空目录后协助克隆；不要覆盖现有文件。以下命令只用于这次首次获取：
   ```powershell
   git clone https://github.com/Rossgu25487/gamejam-2026-workspace.git gamejam-2026-workspace
   ```
3. 公开仓库可直接查看和克隆；连接失败时先核对网络与地址。向团队仓库推送修改需要本人登录并接受协作者邀请；不索要密码、令牌或私钥。暂缺写入权限时继续工具、资源格式检查和本地工作。
4. 已有副本时，核对仓库根、当前分支、HEAD 和未提交改动。保留工作区内容；不自动 reset、清理、暂存他人改动或为“更新”覆盖成果。
5. 主程序指定的本轮集成版本优先。从已确认起点创建任务分支；本人已有正确任务分支则继续使用。获取新引用与合入更新按现有授权处理，脏工作区先核清影响。
6. 不同电脑各自独立 clone 即可。单机多人或并行任务需要额外隔离时，在主副本根使用：
   ```powershell
   ./tools/start-role.ps1 -Role integration
   ```
7. 需要指定起点时，`-BaseBranch` 使用主程序本轮确认的分支或提交。脚本返回 Path、Branch、Commit；它不会切换当前 Codex 的工作目录。让本人在返回 Path 重新打开 Codex 与其中的 Godot 工程，不能把旧任务当成已切换。
8. 已在正确隔离目录时直接继续，无须重复启动脚本。已有 worktree／预留分支不会自动同步或 reset；先读其交接及改动，不为调用脚本强制切回 workspace 分支。

### 2. 读取依据，再给出短计划

- 从已确认仓库根读取 `AGENTS.md`、`README.md`、`workspace/manifest.json`、本人交接及 `planning/current.json`；随后只读当前任务相关资料。
- 接口以现有代码和 `docs/接口与交接.md` 为准；同步方法查 `docs/加入与同步.md`。这些是取得仓库后的本地路径，不要求它们随附件一起发送。
- current 为 pending 时继续 PREP-001 协作准备，不补造正式玩法。active 时核对文件存在、内容 SHA-256 与指针 sha256 一致，并记录当前分支、提交号和需求版本。
- 文件内容变了、哈希不符或本地依据落后时，指出具体差异，由 planner 核对依据、lead 协调整合。不要修改原件或指针；不受影响的检查继续进行。
- 修改时间和 revision 数字不能证明全队采用了同一版本；主程序指定集成提交及实际文件共同确定起点。
- 仅集中询问最多 3 个实质缺项，例如任务范围、资源交付约定或关键接入条件；角色已知不再问。给出 3—5 步计划后直接执行已授权的本地工作。

### 3. 首轮验证现有基线

输入是已有工程、真实逻辑接口和现有美术资源；交付是本人环境的复现结果及需要修复的具体问题。

1. 查明本人机器上的 Godot 路径与版本，使用仓库已有 `tools/project.ps1`。不要套用他人电脑路径、历史运行结果或旧提交号。
2. 在仓库根执行现有测试入口，`-Godot` 参数填写本机控制台可执行文件路径：
   ```powershell
   ./tools/project.ps1 -Action test -Godot '本机Godot控制台可执行文件路径'
   ```
3. 核对现有真实接线、重载与步长显示结果。已通过且本轮无新需求时无需改代码，也不新增一套模拟计数。
4. 能操作图形环境时打开 `game/project.godot`，F5 运行现有主入口；检查数值、增加、重置、按钮焦点与两项 SVG 显示，并查看一次窗口缩放。
5. 独立打开 `game/ui/counter_view.tscn`，确认未接逻辑时有明确提示、按钮不自行改变计数。无法操作窗口时给出人工步骤，不用无界面测试代替视觉或物理输入通过。

### 4. 逻辑怎样进入界面

界面由 `CounterView` 负责显示与发出请求，真实计数继续归 gameplay 的 `CounterModel`。以代码和接口文档中的实际定义为准：

| 接口 | 你的接入责任 |
|---|---|
| `increment_requested`、`reset_requested` | 一次操作只发出一次请求，由主入口接到模型 |
| `show_value(value: int)` | 显示模型给出的值，不维护第二份真实计数 |
| `set_step(step: int)` | 让按钮与说明符合实际步长 |
| `set_connected(connected: bool)` | 配合真实接线显示状态，不能将未接入界面宣称为已连接 |
| 模型 `read_value/increment/reset` 与 `value_changed` | 理解输入与结果，接口变更由 gameplay 与 lead 协调，不在 UI 擅改规则 |

- 新接入任务先明确状态、操作与可见结果，再修改自己负责的场景或脚本；现有节点、连接和资源引用能用就复用。
- 当前主入口负责 configure、连接信号、设置连接状态和步长、首次显示数值；不要在界面重复承担这些公共接线。
- 当前可定位节点为 `%ValueLabel`、`%IncrementButton`、`%ResetButton`、`%ConnectionStatus`、`%StepNote`。改名涉及测试与接入，须说明消费者与同步顺序。
- 真实上游暂不可获取时，可在明确隔离的适配处使用模拟数据，界面与交接均标注“模拟”；保留替换位置，真实接入后重新检查。现成模型可用时直接使用它。

### 5. 两位二维美术怎样接入

| 资源生产者 | 你的动作与交付 |
|---|---|
| 美术 A：UI 布局与组件 | 读取布局、按钮／面板必要状态、字体层级；在本人场景落实接入，反馈实际效果 |
| 美术 B：二维图形与视觉资源 | 按交付接入图标、背景、二维物件或装饰，核对尺寸、透明边缘、缩放与显示层级 |

- `game/ui/theme.tres`、`game/art/ui/` 归美术 A；`game/art/visual/` 归美术 B。可以读取，不越权重做或保存他人的源文件。
- 当前已有 `game/art/visual/ambient_grid.svg`、`loop_mark.svg`。先验证现有引用；没有资源更新时不为练习制造一次美术改动。
- 收到新资源后确认版本、文件路径、原始与显示尺寸、格式、必要状态和来源，再修改本人场景中的引用；更新后检查原有交互仍有效。
- 来源或交付缺项时标明具体问题，先用明确的占位继续接线。使用项目内路径，不引用他人磁盘绝对路径，不捆绑来源不明的字体。
- 两位美术目前均偏 UI／二维；未来 3D 方案需另行明确能力与分工，不默认增加模型、动画或地编任务。

### 6. 验收与阻塞处理

- 真实主入口：0 → 1 → 2 → 重置 0；实际配置变化时按钮、说明与数值一致，重开后一次操作仍只生效一次。
- 视觉与资源：约定尺寸及一次缩放后文字可读、按钮可点、资源引用正确；资源替换后状态与交互仍符合说明。
- 区分模拟检查、真实逻辑接入、实际窗口检查、导出成品检查和跨机器复现。未拿到成品就记“构建产物待测”，不能把开发界面通过写成全部通过。
- 没有 GUI 控制时，继续检查代码、引用与已有测试，给本人准确操作和预期；没有运行环境时不能声称逻辑也已测。
- 接口或资源暂缺时按上文继续独立部分；依据冲突只暂停依赖该规则的改动。共享入口、配置、协议与整体打包由 lead 处理。
- 同因失败且没有新信息时停止原样重试，保留有效成果并说明继续所需条件。

### 7. 保存、同步与每轮结束

只维护 `workspace/handoffs/integration.md`，不另建个人 README、逐轮报告或平行状态表。缺少仓库访问时在当前回复保留进度，取得仓库后再归入该文件。

每轮写清：需求 ID／依据路径及 sha256、起始集成提交、当前分支／提交号、改动文件、接口及资源版本、实际验证／未执行、卡点、接收者、下一步。正式阶段记录本人确认的实际工时，估时单列。

Godot“协作空间”只是当前副本的本地视图，选角色不授予权限，保存成功不代表其他成员已经收到。检查差异后只提交本任务文件和本人交接；不把缓存、构建包或凭据加入提交。

本轮已有推送或创建 PR 授权时自主完成，无需重复确认；缺少相应授权或仓库权限时，准备本地结果、可用提交及 PR 摘要。阅读本文件不授权自动给他人发送聊天或邮件。

### 8. 恢复与正式阶段切换

恢复时先读本人交接，核对分支、未提交改动、上游接口／资源提交与当前依据；保留成果后正常接入所需更新。只补测受变化影响的内容，重新运行启动脚本不等于更新分支。

当前为题前准备，不计正式工时。正式窗口为 2026 年 10 月 1—21 日，每人累计最多 12 小时；队内首次提交最晚为北京时间 10 月 19 日 00:00，即 18 日结束前。可建议在 12 小时内留约 2 小时修正，不增加总额。

收到命题、已定方案和本人明确任务后，核清预制代码入赛许可，按分配的界面与资源切换。许可目前仍未明确；此前不提前定义游戏题材、玩法或制作任务。
