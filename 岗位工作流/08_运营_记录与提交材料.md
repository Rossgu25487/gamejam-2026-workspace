## 3. 目录隔离与当前依据

- 不同电脑各自 clone；同机多任务使用独立 clone 或 worktree，任何两人都不共写同一个目录。
- 常规任务分支为 `codex/ops/<task>`；`codex/ops/workspace` 预留给角色启动脚本。
- 需要本机隔离时，从主工作副本根运行 `./tools/start-role.ps1 -Role ops`，核对输出的 Path、Branch、Commit 和本地修改状态。
- 在返回的 Path 重新打开 Codex，再打开其中的 `game/project.godot`。脚本不会切换当前 Codex 的目录，也不提供远端权限。
- 已有 worktree 或角色分支不会自动更新到最新 main；比较主程序指定的共同起点，保留修改后正常同步需要的更新。
- current 为 `pending` 时只做准备，不推定正式规则；当前夹具引用 `PREP-001 / prep-v1`。
- current 为 `active` 时核对路径、文件 sha256 和工作分支/提交号；revision 仅为该分支的局部修订，不能凭版本数字或口头“最新”选材料。
- 哈希不一致或提示 stale 时，将相关说明标待确认，暂缓相关材料定稿，请 planner 核对后重新指定；不要自行改原件、指针或已定规则，独立准备继续。
- “协作空间”保存本人 handoff 到当前工作副本；遇到磁盘冲突先保留草稿、重新读取并比较，不能覆盖新内容。

## 5. 没有包或工具缺失时继续什么

1. 核对本机运行、截图、录屏与回放条件，列出可用工具和需要人工完成的步骤。
2. 向本人集中说明所需信息：包与版本在哪里、目标平台怎样启动、材料用途与已确认要求；已有信息直接沿用。
3. 在本人 handoff 写最小材料清单、接收格式与缺项，先整理已有真实资料和许可位置。
4. 缺 GUI、音频回放或设备时，给最少菜单步骤、输入值、预期与应回传文件；未亲自检查的结果标未执行。
5. 没有实际画面时不造录屏或“已完成”截图；交付已能完成的结构、说明草稿和待核项。
6. 等待明确的新产物信息后继续，不无限轮询，不建立平行日报或逐轮过程表。

## 6. 录屏与截图的最短流程

- 优先沿用已有可用工具；OBS 只需掌握窗口/游戏捕获、声音选择、开始/停止和回放。[OBS 官方入门](https://obsproject.com/kb/quick-start-guide)
- 题前可用已收到的夹具练习 30—60 秒操作录屏；标明练习身份与版本，不当作正式参赛内容。
- 收到正式材料任务后，先取得 qa 已验收的准确版本；未验收版本的素材只能明确标作草稿或过程素材。
- 记录包名、提交号或包校验值、目标平台和画面对应规则；确认数值、操作和截图来自这个版本。
- 回放核对画面清楚、实际操作可理解、声音来源正确；未能听取音频时保留音频待检查。
- 截图允许为说明需要做清楚标注或必要裁切；不得添加游戏中不存在的功能、效果或反馈来伪装实机。
- 操作失败、报错或未完成内容如实保留为问题或已知限制，不把选择性展示写成全面验收通过。
- 只有确有短音效处理任务时才补 Audacity 的裁切、音量和导出，不额外学习整套音视频流程。

## 8. 交付、同步与恢复

只维护 `workspace/handoffs/ops.md`：本轮目标、分支/提交号、策划路径/sha256、材料对应包版本、文件位置、实际检查结果（通过/失败/未执行）、缺项、接收者和下一步。
正式制作时记录本人确认的实际工时；搭建者曾做过的录屏或验证与本人成员入组结果分开，不称 8 人已经真实演练。
当前任务已有推送/PR 授权时，完成相称检查后自主提交本人材料和 handoff、推送角色分支并发起 PR，由 lead 统一合并。
缺少对应授权时先交本地产物与可转交摘要；本 MD 不构成外发消息、公开发布、联系队员、邀请账号或正式投稿的授权。
本地被 Git 忽略的大视频、包或证据需明确交接方式，不声称推送代码就已交付这些文件。
恢复时核对主程序集成 main、当前依据与包的变化，保留修改后正常同步，更新受影响材料；同因失败且无新信息时保留成果并停止原样重试。
命题、当前方案、个人任务与余下工时明确后，再切换正式材料制作；日期到达不自动扩展工作范围。
