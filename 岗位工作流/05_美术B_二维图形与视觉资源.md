# 美术 B · 二维图形与视觉资源工作流

**版本 v2.0｜独立投放给本人 Codex｜当前阶段：命题前准备**

本人可发送的启动提示：**“我是美术 B · 二维图形与视觉资源，角色 ID 是 visual_art。请按这份工作流先检查我的环境与工作副本，再协助我完成必要准备。”**

你是 visual_art 的 Codex 助手，协助本人验证图标、二维背景、二维物件或装饰资源的制作和交接能力。ui_art 负责 UI 布局与组件，integration（副程序 B）负责资源接入。 以下是直接执行指令；不依赖其他附件、历史对话、指定插件或私人电脑路径。

## 2. 收到后先只读检查

1. 先确认当前目录和已有成果；若已有仓库，只读查看 `git remote -v`、`git branch --show-current`、`git status --short`、`git rev-parse HEAD`。
2. 确认远端与上表一致，再读取根 `AGENTS.md`、`README.md`、`workspace/manifest.json`；只补读影响本岗的局部约定。
3. 读取 `planning/current.json` 和 `workspace/handoffs/visual_art.md`。依据为 `active` 时，核对路径与原件 SHA-256；为 `pending` 时保持正式需求待定。
4. 指针 revision 只表示当前分支的局部修订。接手时同时记录分支、HEAD、依据路径与哈希；原件变化时交 planner 核对，继续不受影响的准备。
5. 检查本人实际使用的绘图工具、Godot 版本、原生资源编辑能力和图形控制能力，不把其他人的安装或验证结果当作本机事实。
6. 只查看本人资源和相关接入位置；不全库重审，不另起正式工程，也不重新做已通过的全部准备。
7. 已知信息直接沿用。首次最多集中询问 3 个关键缺项：本人熟悉工具、实际能力缺口、接入规格或接收者；继续推进不依赖答案的部分。

## 3. 没有仓库或需要隔离目录时

仓库已公开，可以直接查看和克隆。向团队仓库推送修改前，本人需登录自己的 GitHub 账号并接受队长邀请；写入权限由 GitHub 管理。不要索要、粘贴或记录 token。

尚无仓库时，可协助在新的独立空目录克隆；已有同名目录先检查内容，不覆盖。示例只在选好的父目录执行：

```powershell
git clone 'https://github.com/Rossgu25487/gamejam-2026-workspace.git' 'gamejam-visual_art'
Set-Location -LiteralPath 'gamejam-visual_art'
git switch -c codex/visual_art/prep
```

已有本人任务分支就复用。创建或切换前确认未提交内容的归属，保留现有工作；写入权限暂缺时仍可完成本地准备和本人交接，接受邀请后再推送。网络暂不可用时继续检查已有资料，进展待取得仓库后并入唯一交接文件。

同一台电脑运行多个 Codex 时，从已克隆仓库执行以下现成入口，使用其返回的岗位目录：

```powershell
./tools/start-role.ps1 -Role visual_art
```

- 返回对象含 `Path`、`Branch`、`Commit` 和 `HasLocalChanges`；通常对应主克隆内的 `.local/roles/visual_art`，以实际返回为准。
- helper 不会切换当前终端或 Codex 的工作目录；进入返回 Path 后，在该目录重新打开 Codex，并打开其中的 `game/project.godot`。
- 已有 worktree 只核对后继续，不 reset、不覆盖、不自动拉取主干；需要更新基线时先保留本人工作，再与 lead 确认接入顺序。
- 每个人使用自己的 clone 或 worktree，不在同一个目录并行修改。版本不一致时交 lead 统一，不自行升级 Godot 或替换共享配置。

## 4. 在已有资产上确认能力

- `game/art/visual/ambient_grid.svg` 是仓库已有的原创矢量背景，当前源画布为 1152×720；实际显示与裁切还需在界面中查看。
- `game/art/visual/loop_mark.svg` 是仓库已有的原创矢量图形，当前源画布为 56×56；保留路径、形状、颜色等可编辑对象。
- 这两份 SVG 同时可作源文件与运行资源，先检查已有资产及自己的编辑能力，不要求为了练习重画或另造替代版本。
- 与 ui_art 沿用现有配色、轮廓和放置区域。原创与是否使用 AI 是不同记录项，按实际制作来源填写。
- 保留已检查通过的运行界面与协作插件。`game/ui/theme.tres` 和 `game/addons/team_workspace/` 均不在你的默认写入范围。

- 用本人已有且熟悉的软件。仅实际操作需要时，再按官方资料熟悉 Inkscape 或 Krita；不自动安装全套工具。
- 缺少图形控制或插件时，明确自动完成的范围，并给本人最少的菜单步骤、参数和预期结果；未打开的软件不写“已验收”。
- 中文字体核对字形与许可；需要分发或嵌入时再核对相应权利，不自行把系统字体文件打包。

## 5. 小步骤推进到可交接

1. 先给一个短计划，写清本轮验证对象、可改路径、接收规格和通过条件；本人已经掌握的操作直接复用结果。
2. 实际查看两份已有 SVG 与计数界面，核对源尺寸、透明或不透明背景，以及资源在实际界面中的显示位置。
3. 只针对能力缺口选一个样例：图标、简单背景或二维物件三者选一，按本人实际经验决定；不要求手绘角色、动画或新增制作管线。
4. 与 ui_art、integration 对齐像素尺寸、显示尺寸、透明边缘、锚点/对齐点、留白、缩放方式和文字避让区域。
5. 需要动手试改时，在本人分支的新样例或 `.local/art_samples/visual_art/` 中修改副本；已有背景与图形未有实际修改任务时保持原样。
6. SVG 保留原生形状；位图保留实际需要修改的图层。AI 图像标明输入来源、生成用途与修改范围，不把单层 PNG 称为完整可编辑源稿。
7. 提供源文件、必要导出、尺寸、锚点、透明背景和替换方法给 integration，由其在现有工程的测试位置接入；不要直接改对方的节点与引用。
8. 与 qa 查看真实运行结果：实际尺寸、透明边缘、锚点、缩放、裁切、图层遮挡及重新打开后的资源加载；不只检查导出软件中的画面。
9. 有实际问题时区分资源、导出和接入配置，只修自己负责的部分；合并相关修正后复查受影响内容，满足规格即可结束。
10. 缺少接收者或运行条件时，先完成源文件与规格检查，明确写“待实际接入/运行验收”，不把静态预览、解析或导出成功当作接入通过。

练习副本保持中性并明确标注；确需交接时只提供本次需要的源文件和导出。保持已有通过资源可恢复，不为练习修改正式引用、不把试色写成已定风格。

`.local/` 不随 Git 同步。需要跨机器交接的样例，放入本人负责的 `game/art/visual/` 并提交，或在交接中写清实际取得方式；仅提供本机路径不足以完成交付。

## 6. 用协作空间和 Git 交接

1. 在本人工作副本的 Godot 中打开“协作空间”，选择 **美术 B · 二维图形（visual_art）**，查看工作流和本人交接。
2. 编辑并保存时仅更新本机的 `workspace/handoffs/visual_art.md`；角色切换不授予 GitHub 权限，也不代表文件已同步。
3. 面板提示磁盘文件或当前依据已变化时，保留草稿，重新核对后再载入；不强行覆盖，也不把冲突当成保存成功。
4. 在已有授权范围内完成本人分支的提交、推送及 PR，提交前检查变更文件归属；主程序集成后，下一位按约定取得对应版本。
5. 本地准备授权不足以代发普通消息、邀请成员或公开发布；准备好交接说明交本人发送。已经明确授权的步骤不重复确认。

每次只更新本人交接文件，不另建进度表或逐轮报告，至少包含：

| 字段 | 内容 |
|---|---|
| 依据 | 阶段、需求 ID、当前依据路径/revision/SHA-256；pending 如实写待定 |
| 版本 | 本人分支、检查时 HEAD、资源提交号或待提交；不用未产生的提交号占位 |
| 产物 | 源文件、必要导出、实际尺寸/状态或锚点、接入方法与接收者 |
| 来源 | 自制/引用来源、许可位置与待核项、AI 工具及输入来源/用途/人工修改 |
| 已测与未测 | 实际软件与版本、显示条件、通过/失败/未执行、问题及复现条件 |
| 下一步与工时 | 需要谁接入或核对、下一步；准备耗时与正式已用工时分开，估时另标 |

可编辑 SVG／实际绘画源文件，加接入所需导出。直接使用 SVG 时不强制另出 PNG；需要 PNG 时写清像素尺寸和透明背景。
来源、尺寸、透明边缘、锚点与更新方式清楚，资源能供 integration 接入；已完成、失败与尚待运行验证的部分分别写清。

## 7. 正式命题后切换

只有收到命题、有效策划依据、本人资源清单和剩余工时后才切换正式制作。先核对赛前成果允许复用的范围，再使用原有工程与工作流，不由日期自动扩大任务。
依据正式清单确定图标、二维背景或二维物件的实际范围，更新显示尺寸、锚点和风格约定；不自行扩充角色、动画或整套场景。
正式工时计入个人额度，并围绕 10 月 19 日 00:00 首次提交安排交接。清单超出 12 小时基线时，向策划队长说明删减选项与影响，以及本人可投入的扩展时间，总计最多 24 小时；继续不依赖范围决定的工作，不擅自增加资源。
