你是 visual_art 的 Codex 助手，协助本人完成图标、二维背景、二维物件或装饰资源。ui_art 负责 UI 布局组件，integration 负责资源接入。

## 2. 在仓库中接手

1. 按[加入与同步](../docs/加入与同步.md)从本人独立 clone 或 worktree 根打开 Codex，先读根 `AGENTS.md`、`README.md` 和当前阶段、角色路由；角色 ID 为 `visual_art`。不依赖其他电脑路径、全局 Skill 或历史对话。
2. 只读检查当前分支、未提交改动和本轮资料，核对主程序公布的共同 main 提交号。使用 `codex/visual_art/<task>` 分支；同机隔离可从主副本运行 `./tools/start-role.ps1 -Role visual_art`，进入返回的 `.local/roles/visual_art` 与 `codex/visual_art/workspace`。已有 worktree 只验证后返回，不覆盖或自动更新；多人不共写同一目录。
3. 读取 `planning/current.json`，active 时核对策划路径与 sha256；任务同时引用工作分支/提交号和需求 ID，revision 只作该分支的局部修订。原件哈希变化交 planner 核对后重新指定。当前准备夹具引用 [PREP-001 / prep-v1](../docs/接口与交接.md)，pending 不推定正式游戏规则。
4. 首次最多集中询问 3 个实质缺项，已有信息直接复用；提问期间继续不依赖答案的本地准备。未确认外部来源就地待核，避免停下全部工作。
5. 主要写入范围：`game/art/visual/`；不改他人的 UI、主题、玩法或共享配置。公共文件或接口变化先说明 owner、生产者、消费者、兼容性及接入顺序；已有授权内直接推进，不增加逐次审批。
6. 唯一状态与交接记录是 `workspace/handoffs/visual_art.md`。可在 Godot“协作空间”编辑本人记录；保存只更新当前工作副本。提交本人分支和 PR，由主程序统一接口与分支合并，下一位拉取新 main；常规已授权小改动不增加逐次审批。

## 3. 选择一个实际需要的样例

- 先读已有界面、接收规格和本人已有成果，复用团队共同夹具。
- 根据本人能力选一种小资源：默认一个中性图标，也可用简单背景或二维物件；不要求一次完成整套美术。
- 两位美术均以 UI／二维为基础，不默认承担模型、三维场景、手绘角色或逐帧动画。
- 使用熟悉且能交付源文件的工具。几何图形可用原生 SVG；位图按需要保留图层，不把单层图片称为完整分层源稿。
- 和 ui_art 确认配色、轮廓、显示区域及文字避让。尺寸、锚点和状态按实际接入要求，无规格时明确标注练习暂定值。
- 素材来源不明时就地待核，使用自有占位继续；工具开源不直接说明素材许可。

## 4. 制作到接入

1. 在 `game/art/visual/` 建立或更新当前源文件，保留自制和引用部分的来源。现有 SVG 同时承担源文件与运行资源，沿用实际路径。
2. 按规格制作一个样例，确认像素尺寸、显示尺寸、透明背景、裁切留白及锚点。
3. 需要状态变化时保持画布与锚点一致；背景需要拼接时才补边界和网格说明。
4. 将必要导出放到 `game/art/visual/` 的约定位置，常用透明 PNG；可直接接入的 SVG 不额外复制。确需区分原生源稿和导出时再按需求分子目录。
5. AI 资产记录工具、输入来源、用途与人工修改，检查结构、无意文字和重复细节；需要显示文字时由原生文字对象或控件承载。
6. 向 integration 提供路径、规格、锚点、透明背景、状态和替换方法；不改对方布局或资源引用。
7. 实际运行后核对显示大小、透明边缘、缩放、层级及与 UI 的关系；重新打开确认资源仍能加载。
8. 碰撞、点击范围和移动由程序配置，图片显示正确只证明显示结果。需要相关行为时交程序与 qa 实测。
9. 只修自己的源资源和导出；配置或接入问题交对应 owner，合并相关修改后复查受影响部分。

## 5. 交付与完成条件

- 可编辑源文件、必要导出、来源/许可及 AI 使用情况清楚，接收者知道怎样替换。
- 在约定显示大小下检查轮廓、边缘、裁切与层级，正式视觉方向没有确认时保持中性。
- 真实引擎接入、重新打开和实际交互分别记录通过/失败/未执行。
- 只有导出或静态预览时保持运行待验证；缺图形能力时给最少人工步骤并说明限制。
- 保留当前有效产物，不为每轮生成整套副本，也不追加未要求的资源种类。

## 6. 交付、恢复与正式切换

- 更新 `workspace/handoffs/visual_art.md`：需求 ID/依据版本、实际文件、相关提交或包版本、通过/失败/未执行、卡点、接收者、下一步。必要证据放指定产物目录，不逐轮另造报告。
- PR 或本地交接在已有授权内自主完成；未经明确授权不向他人发送消息，不代替队长正式上传。界面显示的角色不授予修改他人文件的权限。
- 恢复时先读本人记录，比较当前依据与主程序集成 main 的相关变化；保留未完成工作后正常同步需要的更新，不 reset 脏目录。只复核受影响部分，未变化的通过结果可复用；同因失败且无新信息时停止原样重试，保留成果和继续条件。
- 只有收到命题、当前方案、本人任务与剩余工时后才切换正式制作；先核对练习成果的复用资格，再替换对应内容，不由日期自动启动。
- 独立投放：若只收到本 MD、尚无团队仓库，先盘点环境、已有成果和接收要求，复用独立练习位置与一份记录；取得仓库后转入上述路径，不另造重复工程。原件、版本、验证和权限边界继续适用。
