## 2. 在仓库中接手

1. 按[加入与同步](../docs/加入与同步.md)从本人独立 clone 或 worktree 根打开 Codex，先读根 `AGENTS.md`、`README.md` 和当前阶段、角色路由；角色 ID 为 `gameplay`。不依赖其他电脑路径、全局 Skill 或历史对话。
2. 只读检查当前分支、未提交改动和本轮资料，核对主程序公布的共同 main 提交号。使用 `codex/gameplay/<task>` 分支；同机隔离可从主副本运行 `./tools/start-role.ps1 -Role gameplay`，进入返回的 `.local/roles/gameplay` 与 `codex/gameplay/workspace`。已有 worktree 只验证后返回，不覆盖或自动更新；多人不共写同一目录。
3. 读取 `planning/current.json`，active 时核对策划路径与 sha256；任务同时引用工作分支/提交号和需求 ID，revision 只作该分支的局部修订。原件哈希变化交 planner 核对后重新指定。当前准备夹具引用 [PREP-001 / prep-v1](../docs/接口与交接.md)，pending 不推定正式游戏规则。
4. 首次最多集中询问 3 个实质缺项，已有信息直接复用；提问期间继续不依赖答案的本地准备。未确认外部来源就地待核，避免停下全部工作。
5. 主要写入范围：`game/features/counter_demo/`；主要文件为 `counter_model.gd`。公共文件或接口变化先说明 owner、生产者、消费者、兼容性及接入顺序；已有授权内直接推进，不增加逐次审批。
6. 唯一状态与交接记录是 `workspace/handoffs/gameplay.md`。可在 Godot“协作空间”编辑本人记录；保存只更新当前工作副本。提交本人分支和 PR，由主程序统一接口与分支合并，下一位拉取新 main；常规已授权小改动不增加逐次审批。

## 3. 实现与交接合同

- `CounterModel` 继承 `RefCounted`，维护唯一真实计数；UI 不保存另一份计数。
- 提供 `configure(initial, step)`、`read_value()`、`increment()`、`reset()`，以及 `value_changed(value: int)`。
- 初始值和步长由主程序从 `DemoConfig` 传入；默认夹具为 0、1。重置回配置初值，增加使用配置步长。
- `read_value()` 返回当前整数且不改状态；状态改变通过信号通知。消费者不依赖增加与重置的返回值。
- 主程序负责主场景接线，副程序 B 的视图发出操作请求。需要自测入口时放自己的目录，避免在共享场景再注册一套生效输入。
- 首次检查现有实现和 [接口合同](../docs/接口与交接.md)，补真实缺项，禁止因拿到本文就重写另一个计数工程。
- 接口变化先说明 lead/integration 哪些调用受影响及接入顺序。规则与数值含义不明时交 planner，其他已明确逻辑继续。

## 4. 操作步骤与相称验证

1. 找到现有模型、配置和调用位置，检查当前改动归属，再完成本轮已授权逻辑。
2. 使用现有轻量检查方式验证：读取初值、依次增加、重置、重置后再增加。
3. 默认配置应得到 0→1→2→3→0→1；配置发生变化时按同一需求版本核对相应预期。
4. 调试需要时使用一条有效日志或断点定位调用与状态，完成后清理无用途输出。
5. 交出真实方法、信号、运行入口和检查结果。integration 暂未接入时写“逻辑已测，待 UI 接入”，不接管对方界面。
6. 实际输入是否只触发一次，由真实接线后的运行检查确认。只做了纯逻辑或无界面检查时保留输入与视觉未执行项。
7. 回归只覆盖修改处和直接影响；实际错误出现后再扩展检查，不为小夹具建通用事件总线、状态机或测试平台。

## 5. 卡点与完成条件

- 环境缺失：保留代码与接口检查结果，记录首个相关错误和最少恢复步骤，未运行项保持未执行。
- 上游配置或下游接口待确认：在本人目录验证已有合同，标清占位或模拟，真实接入后再更新状态。
- 公共文件需修改：说明具体文件、理由、消费者和顺序，主程序处理公共部分；继续自己的独立工作。
- 完成时，逻辑可按当前规则验证，接口可供 lead/integration 使用，qa 能据准确版本复现。
- 实际工时由本人确认；发现正式任务超出余量时给出简化影响，由 planner 决定产品范围。

## 6. 交付、恢复与正式切换

- 更新 `workspace/handoffs/gameplay.md`：需求 ID/依据版本、实际文件、相关提交或包版本、通过/失败/未执行、卡点、接收者、下一步。必要证据放指定产物目录，不逐轮另造报告。
- PR 或本地交接在已有授权内自主完成；未经明确授权不向他人发送消息，不代替队长正式上传。界面显示的角色不授予修改他人文件的权限。
- 恢复时先读本人记录，比较当前依据与主程序集成 main 的相关变化；保留未完成工作后正常同步需要的更新，不 reset 脏目录。只复核受影响部分，未变化的通过结果可复用；同因失败且无新信息时停止原样重试，保留成果和继续条件。
- 只有收到命题、当前方案、本人任务与剩余工时后才切换正式制作；先核对练习成果的复用资格，再替换对应内容，不由日期自动启动。
- 独立投放：若只收到本 MD、尚无团队仓库，先盘点环境、已有成果和接收要求，复用独立练习位置与一份记录；取得仓库后转入上述路径，不另造重复工程。原件、版本、验证和权限边界继续适用。
