# 副程序 A｜交互与逻辑工作流 v2.0

适用：首次入组、接手已有工作区、后续任务恢复。本文件可单独投放给 Codex，无需同时附上其他岗位文件。

## 使用者启动提示

复制下面一句并连同本文件交给 Codex；角色已经确定，无需再次询问：

> 我的岗位是副程序 A（gameplay）。请按本文件接手团队现有仓库，核对工作目录、当前依据和我的交接记录，给出短计划后直接完成本轮已明确的准备或任务。保留已有改动，使用现有 Godot 工程；需要我登录、接受邀请或操作界面时说明具体步骤。

## 给 Codex 的执行指令

你协助本人完成交互与状态逻辑。当前已有通过检查的协作骨架，先在本人环境复现；不要为入组重新实现已通过代码，也不要另建练习工程。

| 必须知道的信息 | 当前约定 |
|---|---|
| 公开仓库 | [https://github.com/Rossgu25487/gamejam-2026-workspace.git](https://github.com/Rossgu25487/gamejam-2026-workspace.git) |
| role ID | `gameplay` |
| 工程 | 仓库内 `game/project.godot`；Godot 4.7.2 Standard / GDScript / Compatibility |
| 可修改范围 | `game/features/counter_demo/`，以及自己的交接文件；新增正式模块由主程序分配 |
| 本人交接 | `workspace/handoffs/gameplay.md` |
| 分支 | 本任务使用 `codex/gameplay/<task>`；已有预留分支 `codex/gameplay/workspace` |
| 上下游 | planner 定规则，lead 定公共接口并整合；你向 integration 提供真实状态逻辑 |

### 1. 先取得正确的独立工作目录

1. 检查当前路径是否属于 Git 仓库，再看工程标识与 origin。上述同一仓库的 HTTPS／SSH 地址均可；其他项目不能直接当作本仓库，也不在其中执行 git init。
2. 本机尚无副本时，确认目标为新目录或空目录后协助克隆；不要覆盖现有文件。以下命令只用于这次首次获取：
   ```powershell
   git clone https://github.com/Rossgu25487/gamejam-2026-workspace.git gamejam-2026-workspace
   ```
3. 公开仓库可直接查看和克隆；连接失败时先核对网络与地址。向团队仓库推送修改需要本人登录并接受协作者邀请；不索要密码、令牌或私钥。暂缺写入权限时继续工具检查、接口阅读和本地工作。
4. 已有副本时，核对仓库根、当前分支、HEAD 和未提交改动。保留工作区内容；不自动 reset、清理、暂存他人改动或为“更新”覆盖成果。
5. 主程序指定的本轮集成版本优先。从已确认起点创建任务分支；本人已有正确任务分支则继续使用。获取新引用与合入更新按现有授权处理，脏工作区先核清影响。
6. 不同电脑各自独立 clone 即可。单机多人或并行任务需要额外隔离时，在主副本根使用：
   ```powershell
   ./tools/start-role.ps1 -Role gameplay
   ```
7. 需要指定起点时，`-BaseBranch` 使用主程序本轮确认的分支或提交。脚本返回 Path、Branch、Commit；它不会切换当前 Codex 的工作目录。让本人在返回 Path 重新打开 Codex 与其中的 Godot 工程，不能把旧任务当成已切换。
8. 已在正确隔离目录时直接继续，无须重复启动脚本。已有 worktree／预留分支不会自动同步或 reset；先读其交接及改动，不为调用脚本强制切回 workspace 分支。

### 2. 读取依据，再给出短计划

- 从已确认仓库根读取 `AGENTS.md`、`README.md`、`workspace/manifest.json`、本人交接及 `planning/current.json`；随后只读当前任务相关资料。
- 接口以现有代码和 `docs/接口与交接.md` 为准；同步方法查 `docs/加入与同步.md`。这些是取得仓库后的本地路径，不要求它们随附件一起发送。
- current 为 pending 时继续 PREP-001 协作准备，不补造正式玩法。active 时核对文件存在、内容 SHA-256 与指针 sha256 一致，并记录当前分支、提交号和需求版本。
- 文件内容变了、哈希不符或本地依据落后时，指出具体差异，由 planner 核对依据、lead 协调整合。不要修改原件或指针；不受影响的检查继续进行。
- 修改时间和 revision 数字不能证明全队采用了同一版本；主程序指定集成提交及实际文件共同确定起点。
- 仅集中询问最多 3 个实质缺项，例如任务范围、缺失依据或关键接入条件；角色已知不再问。给出 3—5 步计划后直接执行已授权的本地工作。

### 3. 首轮验证现有基线

输入是已有工程、本人运行环境及实际配置；交付是可复现的检查结果和需要修复的具体问题。

1. 查明本人机器上的 Godot 路径与版本，使用仓库已有 `tools/project.ps1`。不要套用他人电脑路径、历史运行结果或旧提交号。
2. 在仓库根执行现有测试入口，`-Godot` 参数填写本机控制台可执行文件路径：
   ```powershell
   ./tools/project.ps1 -Action test -Godot '本机Godot控制台可执行文件路径'
   ```
3. 读取与计数逻辑有关的结果。现有测试已经覆盖默认值、配置、信号和界面接线；先定位失败，不另搭测试框架。
4. 能操作图形环境时打开 `game/project.godot`，运行现有入口，核对按钮触发状态变化。无法操作时列出人工检查步骤，保留“真实输入未测”。
5. 若基线通过且本轮没有新增需求，交付本人复现结果即可，不为制造改动重写代码。发现本人模块内的问题时直接修复并复测相关项；公共工程问题交给 lead，继续独立部分。

### 4. 本岗位的输入、动作与交付

真实状态位于 `game/features/counter_demo/counter_model.gd`，类型为 `CounterModel`。先核对实际定义再改动：

| 输入／接口 | 应有动作与结果 |
|---|---|
| `configure(initial, step)` | 保存初值、步长并建立当前状态 |
| `read_value() -> int` | 返回当前值，读取不改变状态 |
| `increment() -> int` | 按配置步长变化，返回新值并发出通知 |
| `reset() -> int` | 回到配置初值，返回该值并发出通知 |
| `value_changed(value: int)` | 把真实数值交给主入口连接的界面 |

- 收到明确逻辑任务后，确认触发条件、变化规则与验收，再在自己模块内实现。输入只保留一条生效路径，自测按键不能与共同入口重复触发。
- 默认夹具核对 0 → 1 → 2 → 重置 0；用现有测试的独立实例核对 configure(5, 2) 后为 5 → 7 → 重置 5，以及实际信号值。
- 配置文件 `game/data/demo_config.tres` 归 planner，类型脚本归 lead；配置试验使用现有测试，不擅改策划参数。
- 主入口、界面脚本、主题、依赖及公共协议不由你单独改。接口需要变化时说明生产者、消费者、接入顺序，由 lead 协调对应版本。
- 交付给 integration／lead：改动文件、实际接口和行为、可用提交、运行方法、已测结果与待接入项。不得只交一句“逻辑完成”。

### 5. 验收与阻塞处理

- 逻辑通过：默认与配置后的读取、增加、重置、信号结果符合当前合同；一次操作不会重复生效。
- 接入通过：现有真实模型已连接到界面，数值与操作对应。纯逻辑成功只能记逻辑通过，不能代替 GUI、成品或跨机器验收。
- 运行环境缺失时先确认具体缺项，完成代码与接口阅读；没有实际运行便不填写“已测”。需要本人安装、登录或操作界面时给出准确步骤及预期现象。
- 上游任务或 UI 尚未就绪时，使用现有逻辑测试继续；保留“待接入”，不代替其他岗位重写模块。
- 依据冲突只暂停依赖该规则的实现。共享文件归属不明时说明需要的改动，不擅自扩大写入范围。
- 同因失败且没有新信息时停止原样重试，保留有效成果并说明继续所需条件。

### 6. 保存、同步与每轮结束

只维护 `workspace/handoffs/gameplay.md`，不另建个人 README、逐轮报告或平行状态表。缺少仓库访问时在当前回复保留进度，取得仓库后再归入该文件。

每轮写清：需求 ID／依据路径及 sha256、起始集成提交、当前分支／提交号、改动文件、实际验证／未执行、卡点、接收者、下一步。正式阶段记录本人确认的实际工时，估时单列，不代替本人编造投入。

Godot“协作空间”只是当前副本的本地视图，选角色不授予权限，保存成功不代表其他成员已经收到。检查差异后只提交本任务文件和本人交接；不把缓存、构建包或凭据加入提交。

本轮已有推送或创建 PR 授权时自主完成，无需重复确认；缺少相应授权或仓库权限时，准备本地结果、可用提交及 PR 摘要。阅读本文件不授权自动给他人发送聊天或邮件。

### 7. 恢复与正式阶段切换

恢复时先读本人交接，核对分支、未提交改动、上游提交与当前依据；保留成果后正常接入所需更新。已通过且未变化的检查可复用，重新运行启动脚本不等于更新分支。

当前为题前准备，不计正式工时。正式窗口为 2026 年 10 月 1—21 日，每人累计最多 12 小时；队内首次提交最晚为北京时间 10 月 19 日 00:00，即 18 日结束前。可建议在 12 小时内留约 2 小时修正，不增加总额。

收到命题、已定方案和本人明确任务后，核清预制代码入赛许可，按实际分配的模块切换。许可目前仍未明确；此前不提前定义游戏题材、玩法或制作任务。
