## 2. 在任何成员电脑启动

1. 私有仓库已创建：[Rossgu25487/gamejam-2026-workspace](https://github.com/Rossgu25487/gamejam-2026-workspace)。取得权限后，使用 `https://github.com/Rossgu25487/gamejam-2026-workspace.git` 独立 clone；首版推送状态见根 README 的实际记录。
2. 按[加入与同步](../docs/加入与同步.md)接受邀请并核对主程序公布的同一 main 提交号。在本人 clone 或 worktree 根打开 Codex，使根 `AGENTS.md` 生效。告知本人角色 ID，不把岗位内容写成全局 Skill。
3. 使用 `codex/<role>/<task>` 分支。需要同机隔离时运行 `tools/start-role.ps1 -Role <role>`，使用其返回的 `.local/roles/<role>` 与 `codex/<role>/workspace`；已有目录只验证后复用，不覆盖。脚本不提供远端权限或实时同步。
4. Godot 打开 `game/project.godot`，采用工程声明的 Godot 4.7.2 Standard / Compatibility。每人复用同一练习结构，无需各自重建计数项目。
5. 可在 Godot“协作空间”查看当前依据和编辑本人交接。插件读写本机文件，成员间通过 Git 同步。
6. 开始前读 `planning/current.json` 和本人交接。原件只导入 `planning/inbox/`；只有 planner 明确指定才切换当前依据。

当前只预留了 8 个岗位，成员 GitHub 名单待用户提供，尚未邀请其他 7 位成员。岗位文件存在不代表成员已经加入仓库或完成各自环境验证。

启动话术：

> 我的岗位是 <role ID>。请从仓库根读取 AGENTS.md、对应岗位文件、当前依据和本人交接记录。当前处于赛前准备。先检查已有成果和本次范围，再直接推进已明确、可逆的本地工作；缺项集中说明，验证状态如实记录。

只有岗位 MD、暂未接入仓库时，也可独立投放：在本人的已有工作区打开 Codex，提供该文件和已知交接信息，先盘点环境与已有成果。仓库到位后迁入指定路径并复用成果；不要为每次接手重做工程。

## 3. 共同工作边界

- 题前工具学习、准备和练习不计正式工时。2026 年 10 月 1—21 日每人正式累计最多 12 小时，包含本人实际承担的制作、沟通、联调、记录和修正。
- 内部首次提交最晚为北京时间 **10 月 19 日 00:00（18 日结束前）**；10 月 17 日首提为提前建议。
- 官方最终要求 **10 月 21 日 12:00 前审核通过并完成投稿**。主程序交包、测试验收、运营备料、队长上传，分别记录实际状态。
- 本届禁止游戏联网；赛前预制代码入赛范围尚未明确。当前代码保留准备夹具身份，正式复用时依据明确规则。
- 当前工程仅为 **0 → 操作 +1 → 重置 0 → 界面同步**。正式玩法和专用内容由策划队长在命题后明确。
- 每项改动引用需求 ID 和依据版本。准备夹具用 `PREP-001 / prep-v1`；正式依据由 planner 设置，其他岗位不改上传原件。
- 一人一份 `workspace/handoffs/<role>.md`，持续记录版本、产物、验证、卡点和下一步；不另造个人 README 或逐轮报告。
- 常规已授权修改、PR 与本地交接自主完成，主程序统一接口与分支合并，下一位按合入后的 main 提交号同步。共享文件变化按 owner 与消费者对齐；不增加固定审批或默认全量审计。

## 4. 谁把什么交给谁

| 提供者 | 接收者 | 交付内容 |
|---|---|---|
| planner | 全员 | 当前依据、需求 ID、规则数值、验收与未定事项 |
| gameplay | lead / integration | CounterModel 与实际验证结果 |
| integration | lead / qa | CounterView、操作信号、显示及资源引用 |
| ui_art / visual_art | integration | 源文件、必要导出、规格、许可与 AI 使用情况 |
| lead | qa | 准确版本、运行包、启动方法、配置与已知限制 |
| qa | 对应作者 / planner | 实际验收、可复现问题及回归结果 |
| ops | planner | 与验收版本一致的提交材料及缺项 |
| planner | 平台 | 正式上传、审核与活动投稿核验 |

没有上游成果时，推进本岗位环境、规格、占位或独立验证，明确“待真实接入”。只有实际完成的检查才写通过；无故障也可以通过，不要求人为制造问题。
