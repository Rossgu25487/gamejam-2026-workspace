# 02｜Demo 最小元素、玩家能力与体验组合

2026-09-24 · 候选设计稿 · 依据[01 玩家与方向](01_TapTap风向与玩家分析.md) · 制作与关卡详见[03 工作计划](03_工作计划与关卡推演.md)

## 1. Demo 要证明的体验

候选名称为“拆件修补铺”，具体题材与正式标题待命题决定。玩家用有限零件修复顾客的日用品，赚取维持店铺的费用；供给不足时，可以少接订单、付费购买零件，或拆取一台有人寄存的旧收音机。拆取能解眼前之急，也会留下无法正常归还的物件。

**目标体验：我学会了修理，也能算清生意；理解一个物件的来历以后，我愿意重新考虑怎样使用手上的资源。**

主操作是点选零件、放入固定槽位、检查并交付。每一单都应同时给出三种反馈：物品变得能用、资源发生准确变化、顾客对实际结果作出回应。复杂度来自订单竞争同一资源与后续后果，首版不安排操作速度挑战。

标准 Demo 为 3 个营业回合、6 张订单，预计约 10—15 分钟；12 小时精简版为 2 个回合、4 张订单，预计约 6—10 分钟。时长属于设计目标，试玩后修订，不通过增加重复订单强行补足。

## 2. 玩家能力怎样逐步建立

第一稿的主要玩家愿意进行少量规划，同时希望看懂物件与人物的联系。将“会玩”拆成可观察的能力，才能决定教学与挑战的先后。

| 能力 | 第一次出现时如何支持 | 学会后增加什么要求 | 什么现象说明需要调整 |
|---|---|---|---|
| 看懂对象与目标 | 订单显示物品、两个以内的所需零件图标和报酬，工作台突出当前物件 | 两张订单并列，比较需求 | 玩家反复问“我要做什么”时，先改目标呈现 |
| 点选与安装 | 首单提示点击零件再点槽位，错误类型不允许安装且说明原因 | 允许自行换件，确认前无损调整 | 误触或找不到槽位属于操作问题，不计入策略挑战 |
| 理解库存与结算 | 显示现有、已选数量及交付后变化；日结费用始终可查 | 两单竞争一枚线圈 | 玩家能配好单件却不懂为何另一单缺件，需补订单比较反馈 |
| 规划机会成本 | 展示缺件、采购价格、拆取所得、当日预计结余 | 比较服务人数、现金与寄存物保留情况 | 玩家只会机械选金额最大项，需核对其他结果是否可见且有意义 |
| 结合线索判断 | 寄存标签和物品刻痕可查看；不可逆后果在确认前明示 | 回访把先前决定与具体的人联系起来 | 玩家不知道物品属于谁或误以为可复原，应先改提示与叙事顺序 |

借用 GameFlow 中目标、反馈、控制感、技能与挑战的维度组织检查；它提供分析框架，不保证玩家必然进入心流。[Sweetser 与 Wyeth，2005](https://doi.org/10.1145/1077246.1077253)

本稿同时关注掌握规则的胜任感、可以选择取舍的自主感，以及人物回应带来的联系感。相关动机研究支持把这些因素作为观察线索，实际效果仍需试玩验证。[Przybylski、Rigby 与 Ryan，2010](https://selfdeterminationtheory.org/SDT/documents/2010_PrzybylskiRigbyRyan_ROGP.pdf)

## 3. 最少需要哪些元素

P0 表示两回合精简版也必须保留；P1 为标准版在能力和时间允许时增加的内容。各元素共用同一套物品、订单与经营状态。

| ID | 元素 | 为什么需要 | 最小实现及验收 |
|---|---|---|---|
| E01 / P0 | 一次安全教学与一次独立练习 | 先建立操作和资源理解，后续取舍才有基础 | 先 1 槽配方，再 2 槽配方；玩家能在较少提示下完成第二单 |
| E02 / P0 | 两种零件与固定槽位 | 让“修理”成为可见行为 | 线圈 C、齿轮 G；每件最多 2 槽，类型匹配即可，不要求旋转与顺序 |
| E03 / P0 | 两张可比较的订单 | 建立竞争关系 | 同时展示需求和报酬，已交付状态明确；允许拒单并继续流程 |
| E04 / P0 | 现金、供给与日结 | 让处理有跨订单的代价 | 收益与费用预览、准确结算、缺钱结果；库存可带入下一回合 |
| E05 / P0 | 一次有告知的不可逆拆取 | 把核心取舍与人文表达结合 | 拆取寄存收音机获得 C×1，机体受损且本局无法修复；可取消确认 |
| E06 / P0 | 可见物件变化与少量短文本 | 让行动得到反馈，信息能被用于判断 | 修好差分、寄存标签、短对白、回访；无需独立剧情播放器 |
| E07 / P0 | 明确收束与整局重开 | 形成完整短篇，允许比较结果 | 展示完成订单、现金、寄存物结果；无资源可用时仍可拒单或结算 |
| E08 / P1 | 第三回合与临时采购 | 增加资源规划的变化 | 按回合显示固定采购按钮，每回合合计最多一次，价格直接显示 |
| E09 / P1 | 回合重新尝试 | 降低试验成本 | 恢复该回合开始时的全部状态，不保留本次尝试获得的零件或收入 |

“查看”不消耗资源；“选中／安装”只形成待确认方案；**交付成功才一次性扣零件、收款和记录订单完成**。修好预览与交付状态分开，避免重复扣除或把预览当作经营结果。

## 4. 画面和实际操作

![第二回合的操作信息草图](figures/修补铺操作草图.svg)

图中是规则已熟悉后的第二回合，现金 12、今晚费用 8、库存 C×1 与 G×1。它用于说明布局和信息职责，属于低保真原型，尚无游戏交互实现。

| 区域 | 玩家看什么、做什么 |
|---|---|
| 顶部经营信息 | 当前回合、现金、今晚开支及按已提交操作计算的结余；选中方案时另外显示交付预览，注明“预计” |
| 左侧订单 | 切换两张订单，查看配方、报酬、已完成／未处理；切换会清空尚未交付的槽位选择，不扣资源 |
| 中间工作台 | 放大当前物件，点击零件再点击对应槽位；再次点击已装槽可取下；配齐后交付 |
| 右侧寄存物 | 查看收音机的寄存说明与痕迹；点击拆取后出现成本和结果确认，取消可回到工作台 |
| 下方零件与操作 | 库存图标、数量、采购入口、当前缺件提示、交付按钮；关闭营业会提示剩余未完成订单 |

**最初 90 秒的目标流程：**看到坏掉的灯和一枚线圈 → 点击线圈与槽位 → 预览修好效果 → 交付 → 灯亮、库存减少、收入增加 → 顾客用一句话说明用途。此处不同时引入采购、拆取与回合重试。90 秒为教学目标，保留自由阅读时间。

明暗与景深用于聚焦工作台。背景柔化可以直接画入二维素材，交互物品和 UI 保持清晰；前景遮挡不覆盖操作。当前 Compatibility 的内置景深能力有限，本稿沿用预处理背景与分层方案，不增加实时景深系统。[Godot 渲染器对照](https://docs.godotengine.org/en/4.7/tutorials/rendering/renderers.html)

## 5. 标准 Demo 的规则，逐项说明

### 对象与状态

- 两种零件 C（线圈）、G（齿轮），数量为非负整数。图标必须配名称，不能只靠颜色。
- 每回合提供两张订单，各最多两个零件槽；同类型槽位顺序不影响结果。两单可自由先后交付，每张只结算一次。
- 同一回合的未交付订单在打烊后结束，不滚入下一回合，也没有未告知的额外罚金。打烊前提示预计结余与未完成订单。
- 暂不处理可直接切换订单；主动拒单要明确确认，确认后本轮不再交付该单，不扣现金或零件。标准版回合重试可恢复这一尝试的处理。打烊时尚未处理的订单按未承接记录。
- 零件不足可调整方案、先做另一单、按规则采购、拆取或结束营业；不得卡在必须完成的订单上。
- 初始现金 10。第一回合基础供给 C×2、G×1；后两回合各供给 C×1、G×1，未使用零件保留。每回合开支 8，包含常规供给与店铺费用；供给与费用先显示再操作。
- 标准版第二回合可临时购买 C×1，费用 8。第三回合可选购买 C×1／费用 12，或 G×1／费用 6；每回合合计最多购买一次，现金不足时按钮显示原因。现金到账后可再购买；用固定按钮完成，不单独制作市场界面。第二回合开始、首次交付／采购／拆取之前，即可查看第三回合的供给、两张订单和采购价，后续困难不依赖隐藏信息。入口显示剩余采购次数，购买一种后关闭另一种并解释原因。
- 收音机从第二回合起可拆。它是同一台持续保留的寄存物，整局最多拆一次，得到 C×1。拆解会破坏灌封机芯，本局无法修好归还。确认文字完整说明这一后果；寄存身份不作为事后才揭示的陷阱。

### 日结、结果与恢复

日结现金 = 当前现金 − 8。结果小于 0 时进入停业结果；等于 0 可以继续。现金变化由交付、临时采购与日结三个入口产生，界面从逻辑读取状态。

最终分别展示完成订单、剩余现金和寄存物去向，不合成一个隐藏的道德评分。人物回应依据已交付订单与收音机状态产生，最多另加 2 个必要的叙事标记，避免分支树膨胀。

标准版“重新尝试本回合”恢复现金、零件、订单完成状态、采购次数、收音机与叙事标记到该回合开始时，清空待确认槽位。拆取在本次尝试内不可撤销，重新尝试会撤销本次尝试的全部行为。精简版只保留整局重开。

## 6. 一次具体的选择，而非空泛的“经营压力”

假设第一回合两单均已完成，第二回合开始时现金 12、C×1、G×1，寄存收音机完整。两单分别为：灯需要 C×1，报酬 6；钟需要 C×1、G×1，报酬 9。今晚费用 8。

| 路径 | 玩家实际做什么 | 本回合交付 | 日结现金 | 保留下来的差异 |
|---|---|---:|---:|---|
| 优先灯 | 将 C 装入灯并交付，钟拒单 | 1 单 | 12＋6－8＝10 | G×1 留到下轮，收音机完整 |
| 优先钟 | 将 C、G 装入钟并交付，灯拒单 | 1 单 | 12＋9－8＝13 | 收音机完整，但求灯的人未获帮助 |
| 花钱补件 | 购买 C×1，再交付两单 | 2 单 | 12－8＋6＋9－8＝11 | 两人需求都满足，收音机完整，少留现金 |
| 拆取补件 | 确认拆开收音机，用额外 C 完成两单 | 2 单 | 12＋6＋9－8＝19 | 现金较多，收音机只能以残骸状态留下 |

四条是便于比较的代表路径，实际允许先采购再拆取并把余料留到后面。继续营业是基础目标，拒单仍可得到完整结果。若试玩发现购买总被视为无代价最优解，要检查现金后续用途与玩家目标；若所有人只能靠拆取继续，就要调整供给与开支。第三稿提供后续回合，用于检查这些分歧能否持续发挥作用。

## 7. 元素怎样组合成完整体验

订单提出眼前需求，配方让玩家有具体操作；库存制造有限性，采购与拆取提供不同代价的解法；日结将本回合选择带入后面；物件痕迹与回访让资源变化对应具体的人。去掉任一核心关系都应说明损失，不能只按按钮数量判断内容完整。

心流预期主要来自“逐渐掌握后能独立作出判断”。前段的挑战是辨认操作，中段转为比较订单，后段使用已经学会的规则做取舍；对白与收束允许情绪停顿。情绪紧张、运算负担与沉浸是不同维度，不要求三者同时持续上升。

本轮只是设计与数值推演。还需要观察首单理解、两单比较、拆取后果解释、重复感和完成体验，详见第三稿验收。数值可行与程序正确都不能代替“玩家愿意继续玩”的验证。
