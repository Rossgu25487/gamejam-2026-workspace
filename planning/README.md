# 策划资料与当前依据

本目录由 `planner`（用户兼策划队长）维护。其他角色读取已确认规则，并在自己的岗位交接记录里提出问题。
当前阶段为赛前准备（manifest 为 `preparation`，简称 `prep`）；已有计数演练只依据 [PREP-001 / prep-v1](../docs/接口与交接.md)，正式游戏设计待命题。

## 1. 上传与保存

把收到的策划案原件放入 [inbox](inbox/README.md)。可以直接复制到目录，也可使用 Godot“协作空间”的导入入口。
导入保留原文件内容，不自动设为当前依据。文件重名时保留原件并使用可区分名称，避免覆盖。
收件区在 `.gitattributes` 中关闭文本换行转换，以保持原件字节和 SHA-256 在各成员工作副本中一致。
Codex 不擅改上传原件。用户要求修订时保留原件，在本目录建立清楚命名的工作稿；需要 DOCX/PDF 等格式编辑时采用实际可用工具，并验证对应产物。用户确认的新版本作为独立文件再次入库 inbox，再由 planner 明确设为当前，旧原件继续保留。

## 2. 怎样确立当前依据

[current.json](current.json) 只由 planner 在本人明确指定当前文件和版本后更新；其他人不能因为找到较新文件就切换它。
当前字段为 `status`、`path`、`title`、`revision`、`sha256`、`updated_at`。`pending` 表示尚未指定；`active` 的 path 从仓库根解析，插件只接受 planning/inbox 内已入库文件，并记录原件内容哈希。每次明确设为当前时递增 revision。它是当前分支的局部计次，不是全队统一的线性版本号；任务交接引用工作分支/提交号、策划路径与 sha256，并注明文档自身版本。
界面中的旧指针或已预览原件发生变化时，先刷新并核对，再由 planner 明确重指定。保留正在编写的任务成果，按正常 Git 流程同步新依据，不重置有未提交修改的工作目录。
未指定当前文件、路径失效或规则缺项时，只标明具体待确认点；各岗继续准备、接口检查或不依赖该规则的内容。

## 3. 怎样给出可制作需求

使用 [简版策划模板](简版策划模板.md)，保留本次需要的栏目。每项需求有稳定 ID，同一需求修改时保留 ID 并更新版本。
规则、数值、资源与验收必须能对应；设计建议、待试验值、已确认规则分别表达。无需建立复杂全库登记表。
每项实现和问题记录引用“需求 ID＋依据版本”。生产数值修改写到已分配的配置资源；本仓库演练为 `game/data/demo_config.tres`，其类型脚本由主程序维护。
